用户确认按以下顺序推进：缺陷收口 → 生命周期与稳定性 → 全面前端交互优化 → 发布收口。开发与独立审核均使用 Sol xhigh。本阶段不使用 superpowers 相关 skill。

## 第一批边界与验收

| 项目 | 修复边界 | 必要验收 |
| --- | --- | --- |
| LOGIN-001 | 登录入口必须有明确保存的目标；登录框显示名称和地址；关闭、切换或删除目标清临时凭据及错误；迟到认证与恢复结果不污染新窗口 | 零连接引导管理连接；关闭重开、A→B、删除目标；旧成功和失败回包；正常登录、注册、恢复 |
| EXECUTION-LOW-003 | 报告读取状态与正文保持同一版本，避免清理提交后仍返回 200 空正文 | 真实数据库受控交错；完整正文或明确 410；保留权限、摘要、长度、归档及去重语义 |
| EXECUTION-LOW-002 | 已登记的套件状态、历史证据与离线提示本地化 | 中英业务标签与提示正确；保留用户名称、业务原文和未知码 |
| F5 G-UI-01/02 | 嵌套调用结果模式标签及 AND 全成功的分支文案 | 标签符合真实报告与分支事实；不改执行内核或正确结果 |
| F3 保存状态 | 保存进行中产生新控制草稿时，不能误报全部已保存 | 真实异步保存交错；新草稿保留并继续提示待保存 |
| F3 撤销文案 | 撤销导入成功后显示已恢复，避免“未写入任何更改”误导 | 成功撤销与初次未写入分别说明，失败不冒称成功 |
| F3 固定文案 | 修正本次直接触达且可复用现有翻译机制的固定文案 | 两种语言正常，错误原因不隐藏 |
