# 本地与在线工作台修复及视觉统一实施计划

2026-11-19 · **用户已批准六批施工及逐批实机对照。** 代码核对基线为 `0fbaed4b`。本轮承接[发布验收发现](f8-project-workbench-parity-verification.md)、[运行八图](design/f8-frontend/project-workbench-parity/run-review-2026-11-19/README.md)、[测试六图](design/f8-frontend/project-workbench-parity/testing-review-2026-11-19/README.md)及[页面展示规范](ui-presentation-guidelines.md)。原三批的验证记录用于识别要保护的已有行为。

## 顺序与分工

| 批次 | 交付 | 依赖与切分理由 |
| --- | --- | --- |
| 1 | 接口目录、每个打开项目的工作位置 | 先统一选择和恢复的归属，后续页面可以直接接入。 |
| 2 | 测试对象选择安全、双端单接口用例 | 优先修可能操作旧对象的问题，同时用同一个用例校准双端外观。 |
| 3 | 数据集、测试套件、在线压测计划 | 沿用第 2 批的选择机制和页面布局。分别验收编辑对象与实际执行目标。 |
| 4 | 双端运行页布局、发起任务 | 沿用第 1 批的项目上下文。先用同一用例对齐两个宿主，再核对空态与本地模块预览。 |
| 5 | 双端任务记录、在线定时任务与通知 | 沿用第 4 批的页头、页签和底栏，集中核对历史身份与跳转。 |
| 6 | 客户端解释性旁注排查、最终实机对照 | 前五批随改随记文案位置；本批补齐其余页面，并在同一候选版本收口。 |

施工获准后，每批由开发子代理同时负责两端，另一名子代理独立审核，沿用 GPT-6.2 Astra xhigh。开发与独审都直接打开本批定稿、复现步骤和实拍。每批完成受影响验证并提交可复核的改动，记录提交号。主会话复核实拍与遗留；批内的首次双端对照用于及早纠偏。

## 第一批 · 目录与项目工作位置

**对照**　[接口工作区与底栏](design/f8-frontend/project-workbench-parity/api-status-bar.png)用于核对目录与编辑区的位置。跨项目恢复按[发布验收记录中的五步复现](f8-project-workbench-parity-verification.md#发布验收待修复切回项目或侧栏后恢复上次工作位置)验收；静态图只能证明其中一步。

**改动落点**　从 [App.vue](../apps/desktop/src/renderer/src/App.vue)、[项目记忆](../apps/desktop/src/renderer/src/stores/moduleMemory.ts)和[在线目录映射](../apps/desktop/src/renderer/src/onlineDirectory.ts)入手。本地沿用工作区目录与完整项目定位；在线沿用连接、成员、工作区、项目上下文。按打开的项目页签记录侧栏、子页和选中对象的稳定身份，草稿和响应仍交由已有编辑会话持有。新增恢复范围限于同次会话的已打开页签。先校验对象仍可访问，再恢复界面；迟到结果须核对归属，主动定位优先于普通切签恢复。

| 验收 | 操作与通过条件 |
| --- | --- |
| 1.1 目录 | 两端展开项目、空模块、空文件夹及嵌套目录，分别搜索。按业务节点身份筛选，`project.yaml`、`collection.yaml`、`folder.yaml` 等内部配置文件不进入目录、搜索、项目工具或模块菜单。用名称为 `project.yaml` 的真实接口作反例，应可打开编辑；旧选择命中配置路径时，回到可用的接口工作区。项目读写与同步仍使用原配置文件。 |
| 1.2 五步切签 | 首次打开均进「接口」。随后将本地 1 留在「环境 → 本地 1」、本地 2 留在「测试 → 某数据集」、在线项目留在「运行 → 某条任务记录」。依次切本地 1 → 本地 2 → 在线 → 本地 2 → 本地 1，再回在线。逐步核对项目、侧栏高亮、子页、对象，底栏保持该项目自己的值。 |
| 1.3 页内恢复 | 两端分别离开、返回五个侧栏项。接口恢复请求签、调试或设计子页、草稿及已有响应；工作流恢复列表或设计器、草稿、选中节点和画布位置；环境恢复全局变量、全局参数或具体环境及草稿，浏览环境不切换底栏。测试恢复分类、用例／套件／数据集和草稿；运行恢复原子页与所选记录，刷新可读状态，合成服务的业务请求和提交数保持原值。后续重做页面时复用这组用例。 |
| 1.4 回退与隔离 | 用同名项目、同名资源及快速往返验证不串选。离开期间在线对象被删或权限收回，返回可访问的上级列表并给出就地原因。验证晚到的读取结果不会覆盖当前项目，通知主动定位的目标不会被恢复逻辑改回旧对象。 |

**证据**　复用 `moduleMemory.test.ts`、`viewSwitch.test.ts`、`onlineDirectory.test.ts` 和 `App.test.ts` 中相关行为，按缺口补反例。保存同一组页签的往返实拍或短录屏，附业务请求与任务数前后对照。

| 验收 | 操作与通过条件 |

| 2.3 真实操作 | 在可编辑合成项目新建／保存用例，核对重开后的名称、范围、数据、请求、断言、提取与前后置操作；切项目再返回保留原草稿。通过原业务入口验证运行已保存用例、从用例进入压测时携带正确目标。在线用本机和可用代理抽验实际执行归属，并核对草稿和只读状态下的原有约束。 |

**证据**　`testingCenter.test.ts`、`TestSidebar.test.ts`、`CasePanel.test.ts`、`onlineWorkspace.test.ts` 的相关用例，附同名资源调用记录。首个可用版本即并排拍 T01/T02，确认页头、三栏、按钮和底栏后再继续。

## 证据、审核与完成条件

- **同场景比较。** 使用合成项目「订单服务」，保留两份本地项目与一个在线项目；双端共有页面固定业务对象、选择状态、窗口尺寸、系统缩放与主题。优先使用 1672 × 941 原图比例。其他尺寸以项目内容区的相对位置核对；运行页参照定稿中卡片与底栏的坐标。空态与已选态各对各自样板。
- **证据回填。** 施工时在本轮验收记录按「批次／验收项、定稿编号或复现步骤、候选提交、模式／角色、状态与窗口条件、定向结果、实拍或日志、独审结论」逐项填写。视觉样板逐张对应到最终候选的界面。每批已有的相同候选实拍可复用；画面随后有改动的场景重新拍摄。
- **通过口径。** 审查者打开定稿与实拍核对层级、边框、留白、列宽、选中态、动作位置和底栏，并核对实际目标和调用记录。标题缺失、卡片塌缩、按钮漂移、两端同义操作错位或旧对象可被操作，均记待修。缺图、缺行为证据的项记待验。第 6 批汇总遗留，由主会话逐项复核。
- **验证范围。** 每批运行所列文件中受影响的用例；共享 props 或类型变更时追加受影响包的类型检查。最终使用隔离客户端与合成服务做上述场景联验。本地全量或完整门禁需逐次获得用户明确确认。产品施工从本计划获准后开始。
