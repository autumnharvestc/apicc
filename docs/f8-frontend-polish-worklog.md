用户在 `getPetById` 的路径参数中填写再撤回 `id` 的值，输入框恢复为空，但请求签仍有草稿标记，编辑区仍显示「未保存」。源码核对发现，导入的参数可以没有 `value` 字段，清空输入框会写入空字符串。现有接口草稿与已保存快照按序列化结果比较，这两种存储形态会被判为差异。用现有参数类型和比较逻辑复现了「字段原本缺省 → 填值 → 清空」仍判为有修改。原本显式为空或有值时，精确改回原值可清除这一项差异。未读取截图中的实际项目数据。

以最后一次成功保存的内容为基线。原本缺省的参数值清空后恢复缺省，原本显式为空的值仍保留空字符串。用户确认基线非空时，清空仍是修改，必须改回基线值才算恢复该字段。逐项核对路径参数、查询参数、请求头和 Cookie 中同类输入，保留其他真实改动及仍待处理的草稿。整份请求没有待保存改动时，页签标记、「未保存」文案和关闭时的草稿确认应一致清除。验收覆盖输入后撤销、手动清空、非空值改回、改回一个字段但另一个仍有修改，以及关闭请求签和项目签的提示。
