## 1. 入口与布局

| 位置 | 交互与边界 |
| --- | --- |
| 项目签和目录树 | 顶栏用选中签标识当前项目。打开项目后，目录直接列模块和现有项目级导航项，保留项目身份作为隐藏的数据根。现有工作流、在线配置文件等可访问内容继续可达。搜索、展开状态和选择按完整项目身份保存。 |
| 目录标题「＋」 | 本地可写项目固定显示「新建模块」「新建接口」「导入接口」，在线接入前两项。新建动作始终属于当前项目。原有导入以当前项目为目标，允许显式合并到当时已选的模块，并清楚显示目标。空目录同样有创建入口。 |
| 目录标题「⋯」 | 承接原来项目行的项目级操作。本地项目的重命名、删除保留原确认、权限与页签更新。页签或目录收起时，按现有布局核对相关操作可达性。底部「项目工具」继续提供原有工具。 |
| 模块、文件夹行 | 右端同一列预留固定的「⋯」。可用菜单项按「新建接口」「新建文件夹」「管理」「重命名」「删除」顺序排列，删除单独置底并使用危险色。保留本地现有动作；在线本轮只接入新建模块、在已有模块或文件夹新建接口、默认模块改名。其余在线写操作留待后续设计，现有只读配置入口保留。 |
| 接口行和编辑标题 | 接口行沿用原快捷操作和窄窗回退。右上「新建 HTTP 请求」保留现有位置与自由请求入口。已保存接口的路径为「模块 / 文件夹」，模块根级只显示模块名。项目根级起草时可显示「尚未选择保存位置」。请求区和 AI 建议按现有设计。 |

模块与文件夹名称保持单行，长名称悬停可查看全名。默认标记和行末按钮占固定空间，悬停和键盘焦点都不会改变行高或名称宽度。菜单关联到实际触发行，键盘可开关，关闭后回焦。在线、本地均以活动项目和完整节点身份判断归属，重名或切签时不会借用别的项目的选中项。

## 2. 创建与保存规则

从项目根级点「新建接口」后，进入草稿。保存面板默认选「未分类接口（默认）」。该选项始终可选，也可选择当前项目已有模块或文件夹。从容器行创建时，保存面板默认选触发位置。两个入口均显示实际保存位置，已存在位置被删除或移走时保留草稿并要求重选。保留本地自由请求的发送、另存、显式新建自定义名称模块和关签草稿保护。

只有确认把第一条接口保存到默认位置时，才同时创建普通模块和接口。建项目、打开草稿、取消、失败或改存已有模块均不会生成空的默认模块。默认名「未分类接口」，显示低调的「默认」标记，悬停说明用途，在模块列表置底。业务模块保留相对顺序。改名后，保存位置显示新名称与「默认」。服务器端资产格式、普通模块路径和接口的 `collectionId` 继续沿用。

### 默认身份与旧版本兼容

`ContractProjectSchema`、`project.yaml` 和 `collection.yaml` 按严格模式读取。默认模块复用现有模块 ID 字段，以固定用途域和契约项目 UUID 派生识别部分，保留独立随机部分，按 UUID 值识别。新建时检查项目资产 ID 冲突。识别用于选中默认位置、标记及展示排序，权限仍按项目和目标资产判断。旧包读取、改名回写和新版重开已实际验证。

同名普通模块继续是普通模块。项目移动保留契约项目 UUID，模块身份随之保留。整项目克隆通过现有 ID 映射为新项目重新分配默认模块身份并保持内部引用；只导入普通模块时按目标项目的既有导入语义处理。默认身份不借用外部规范同步的命名空间。已保存数据出现多个默认候选时，拒绝自动归入并提示选已有位置，避免静默写错。同一项目从旧版本打开、改名和回写后，新版本能再次识别默认模块。现有本地删除仍使用原有保护，本轮只承诺按当前资产重新校验保存目标，在线删除及删除后的默认重建规则留待单独设计。

### 在线首次保存与并发

- 按服务器、登录身份、工作区、分组及项目捕获作用域，从服务端项目清单读取**项目有效角色**。`EDITOR` 及以上可写。`VIEWER`、缺少有效角色及失去认证时遵循已有读取与拒绝规则。前端只开本轮授权操作，由服务端继续完成最终校验。已有脚本变更仍需 `script.edit`。
- 已初始化且可解码的项目，以当前资产版本提交必要文件的增量。无资产、无格式且版本为 `0` 的在线项目可首次初始化，使用现有 `PUT /assets` 和 `expectedVersion: "0"`。显式「新建模块」可在首次初始化时写入模块。直接保存第一条接口时，把项目元数据、默认模块和接口放入同一次提交。含旧格式文件或无法读取的项目保留原有提示及显式迁移入口。
- 空白首写的前快照没有 `project.yaml`。由服务端检查资产元数据及版本，只有真空状态才通过内部协议授权 Core 将前快照视为空脚本集合。协作运行时完整解码首次候选、校验所声明的契约项目 UUID，并分类脚本。原 HTTP 接口和数据库结构继续沿用。Java-only 或运行时不可用时，已有 `script.edit` 权限的原发布入口沿用部署降级规则。
- 两名编辑者同时首次保存时，只接受一次符合期望版本的写入。冲突后保留草稿，重新读取项目并复用服务器已提交的默认模块。目标容器消失时提示重选，不自动切到别处。连接断开、提交结果不明确时，先用本次生成的接口身份核对服务端结果再允许重试。同一草稿的重复点击不能产生第二条接口。
- 保存成功后更新当前会话的资产版本和树，定位新模块或接口，使用服务端确认后的名称和身份。已有编辑缓冲不得被创建、刷新或迟到回执覆盖。切项目、切连接、退出或权限变更期间，以原作用域处理回执。区分「提交成功、目录刷新失败」和「提交失败」，让用户可刷新目录或重试草稿。

## 3. 实施批次

沿用上一轮分工和模型配置，开发由一个 Sol xhigh 子代理负责，另一个 Sol xhigh 子代理独立审核。相邻调用集中在同一批实现。每批交付可操作的完整路径、必要回归和实测证据，独审按需求集中反馈。最后对两种模式和既有入口做一次集成复查。

### 第一批　目录布局与本地完整链路

1. 在 `SideTree.vue` 和 `App.vue` 调整项目范围内的显示层、标题菜单和模块／文件夹菜单。保留完整项目上下文、现有项目操作、工作流和导入合并逻辑。核对搜索过滤后路径、展开状态、快速切签、同名项目和窄窗操作。同步修改接口标题路径及中英文文案。
2. 在现有请求草稿及保存面板中接入项目默认目标和容器行目标。在 Core 实现默认模块身份识别与必要的克隆接线。复用桌面 `apiCreateFromRequestDraft` 的凭据、草稿和来源保护，在同一次存储变更中完成默认模块分配及接口写入。继续复用现有显式模块创建动作和现有事务回滚。
3. 对 `App.test.ts`、`components.test.ts`、`ImportWizard.test.ts` 使用受影响用例，验标题「＋」固定、行菜单目标、转移后的项目操作、非当前作用域的导入拒绝和默认选项。以 `contract-assets.test.ts`、`contract-ipc.test.ts`、Core 的 `contractFiles.test.ts`、`clone.test.ts` 覆盖磁盘落盘、改名、回滚、版本竞争、重开和旧版本兼容。完成一次真实宽窗和窄窗预览。

**通过条件**　空项目从标题「＋」可保存第一条接口。保存到普通模块和默认模块都正确，默认模块可改名且不变身份，失败或取消无残留。接口标题路径、项目管理入口、导入合并和现有快捷操作可达。

### 第二批　在线新建与首存

1. 以在线资产读取结果和有效项目角色驱动目录动作。复用已有在线请求表单及资产构造逻辑，在真正空白的在线项目提供创建空态。同时区分「加载中」「只读／无权限」和「旧格式」。首期在线草稿支持编辑后保存，保存后按现有入口调试。在线未保存请求的本机／代理执行能力留待单独设计。
2. 将生成项目、模块和接口的操作接到现有在线 IPC 和项目资产增量链路。在线结构编辑保留服务端项目和契约项目两个身份，预期版本及草稿归属一并核对。修正精确空快照的脚本分类。保存后刷新本项目树及对应缓存，从已解码项目补齐名称、默认标记和嵌套路径，保留现有配置文件查看入口。核对 `onlineTreeToDto` 基于文件路径和缓存的读法，完整还原所选文件夹，无需从显示名或排序猜定位。
3. 使用 `execution.test.ts`、`onlineExecution.test.ts`、`online.test.ts`、`onlineTree.test.ts` 和组合根的受影响场景覆盖客户端上下文、权限和版本。以 Core `collaboration/mutation.test.ts`、协作运行时 `protocol.test.ts` 和服务端资产权限定向用例验证真实保存。集中覆盖两名编辑者从版本 `0` 或同基线并发、可写但禁脚本的普通首写、实际有脚本的拒绝、`VIEWER` 拒绝、旧格式拒绝和保存后再次加载。服务端落盘用真实 HTTP 走通其中的关键路径。

**通过条件**　有权限的用户能在空白在线项目显式建模块，也能直接从项目根级保存一条接口。团队看到同一默认模块，改名后可继续复用。并发、遗失回执或切项目时，目标身份、草稿及已提交结果均可核对。

### 第三批　集成复查与交付

1. 对照样板和本计划复查本地、在线的目录入口，测试已有和空项目、同名项目／模块、嵌套文件夹、树搜索、转移后的本地项目项及请求标题路径。逐项核对上一轮的项目工具、导入、独立自由请求及 AI 建议入口。
2. 同一冻结候选完成受影响用例、Core 与桌面构建、Windows 目录包冒烟，并用隔离合成项目作集中原生验收。覆盖中文常规窗及英文窄窗，记录行尾对齐、长名、默认标记、按键回焦和可读错误。在线路径用同一隔离服务覆盖编辑者和只读成员。对协作运行时分类变更核查打包引用和相应部署冒烟路径，保留加载到的版本证据。
3. 归档逐项验收、失败与复验、独审回执及 Windows 验证包。图和索引放 `docs/design/f8-frontend/project-directory/`。原始日志、候选和哈希放 `local/f8-frontend-project-directory/`。日常使用定向验证和 GitHub CI。本地全量或完整门禁逐次另行确认，提交、合并与推送按当次授权执行。
