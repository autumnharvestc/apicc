## 共同操作

| 操作 | 本地与在线共同约定 | 模式差异 |
| --- | --- | --- |
| 打开项目、选接口 | 窄侧栏按「接口、运行、工作流、测试、环境」排列。「接口」主窗格直接呈现目录对应的编辑区；首次未选中时提示选择接口，有创建权限时提供新建入口。返回已打开的接口时恢复编辑位置和草稿。 | 在线根据项目格式、连接和权限决定哪些动作可用，受限动作就地说明。有效在线项目可从侧栏进入已有功能。 |
| 管理环境 | 两种模式都从左侧「环境」进入管理页。 | 各自沿用项目环境数据、凭据和写入权限。 |
| 快速切换环境 | 在当前项目窗口最底部的同一位置显示「环境」及当前名称。菜单向上弹出，选中项带勾，选后留在当前页。切换接口、工作流或测试时仍能看到当前项目的手动执行选择。 | 本地「无环境」、在线「基础环境」等既有选项按实际执行语义标示。环境只取自活动项目。 |
| 选择执行位置 | 与环境相邻，当前名称常显。执行位置属于当前用户在当前项目的选择，切回项目恢复该项目上下文。 | 在线可选本机或获授权的代理；本地仅支持本机时省去此选择器。代理离线、配置未应用或能力不足时，显示原因，保留原选择，切换由用户决定。 |
| 调试与查看响应 | 发起、取消、查看响应都能在当前接口完成；响应栏独立展开、收起。后台任务可从状态行跳到对应记录。 | 代理任务可有排队和取消收束过程，按真实状态展示。本机和代理各自保留原执行生命周期。 |

底栏横跨项目窗口，建议高 28–32 个逻辑像素；两个选择器靠左，剩余空间留白。长名称单行省略，悬停和键盘聚焦均可查全名。切换项目时关闭旧弹层，避免将选择写入另一个项目。主页没有当前项目时收起项目快捷项。沿用[页面展示规范](ui-presentation-guidelines.md)。

**选择的作用范围。** 底栏影响后续手动执行；普通接口切换、保存或切换模块均无需再次选择。底栏选择属于运行上下文，不写入接口定义或同事的偏好。已启动的任务使用启动时快照，历史详情读取该次实际记录，定时任务使用自身保存的环境和代理。套件、压测计划等带显式环境的资产继续保有其配置；运行前展示本次实际目标，发生不一致时说明并沿用相应校验。切换底栏不可隐式改写已保存的计划、套件或凭据。

**与既有设计衔接。** [r7 工作台设计第 5 节](f8-frontend-polish-workbench-r7-design.md)记录了本地请求签级的环境选择、请求行与侧栏双入口，以及在线主导航的门控。本次更新这三处交互。实施前需核对旧请求签和未发送草稿中已选的环境，明确迁移后第一次发送所用环境，避免重开旧草稿时悄悄改发其他目标。原有草稿保护、远端版本冲突处理与真实执行权限继续适用。

## 原执行面板的去向

| 入口 | 内容 |
| --- | --- |
| 项目底栏 → 执行位置 → 执行详情 | 查看控制连接、配置是否已应用、脚本时限、运行时、受信脚本与批准、本机插件及关闭客户端的影响。授权管理沿用原有管理员入口。阻断执行的原因同步显示在发送或运行处。 |
| 接口 → 调试 | 「发送」旁的更多菜单提供新建调试会话。响应区呈现排队、本次响应或错误，在途操作可取消。 |
| 运行 → 发起任务／任务记录 | 两端用相同名称和顺序。记录页可手动刷新，代理列表标明「最近 20 条」，刷新间隔放列表设置。容量等待、取消进度与逻辑结论按该次运行的真实状态展示。 |
| 所选任务 → 详情／报告 | 首屏区分请求是否实际发出、执行状态、逻辑结论、失败原因、资源释放与报告归档。技术详情承载快照指纹、调度方式、策略版本与实际运行时等事实。无报告读取权限时仅展示获准的状态。 |
| 对应结果／项目工具 | 工作流轨迹、套件证据、压测基线与 HTML 导出、AI 分析跟随相应报告；可分享的结果就地提供发布。项目级「协作与分享」归入项目工具。 |
| 运行 → 定时任务／通知 | 在线保留各自入口。定时任务的目标和授权在其配置内查看与修改。 |

## 本地与在线的运行入口

两端进入「运行」后，前两个页签依次是「发起任务」「任务记录」。在线另有「定时任务」「通知」。本地保留「运行模块用例」，在线将该能力列入[低优先级需求池](backlog.md#execution-low-004)，本轮不提供该类型。此处归档交互约定；[本地发起任务样板](design/f8-frontend/project-workbench-parity/local-run-launch-proposal.png)供评审视觉布局。

| 操作 | 共同交互 | 与执行方式有关的差异 |
| --- | --- | --- |
| 发起任务 | 左侧选任务类型、查找并选中当前项目的目标。右侧显示目标名、执行范围、本次实际环境和执行位置。选目标只更新预览，点击「运行套件」「运行模块用例」等具体动作才开始执行。目标不可运行时，在按钮旁说明原因。 | 两端按实际能力提供已保存的用例、测试套件、工作流及压测入口；即席请求继续在接口页调试。本地模块另有范围预览。在线手动任务按目标能力和授权使用本机或代理。 |
| 从其他入口执行 | 在测试页、工作流或接口页继续使用原有执行入口。有对应记录时，「查看本次运行」定位到同一次执行；进入记录详情、返回表单或反复切页均不会再次执行。 | 调试历史和执行报告沿用各自的留存范围。复用已有标识和读取路径，避免同一执行因入口不同被重复统计。 |
| 任务记录 | 默认查看当前项目。左侧按时间列出类型、目标名、执行时间及结果；右侧显示所选执行的实际环境、位置、状态、结论和报告。返回列表保留选中项和滚动位置。首次没有记录时提供「发起任务」。 | 本地读取已有运行历史，支持的报告继续提供查看、导出或发布。在线按授权读取本机或代理记录，排队、取消、报告待归档等状态按任务能力展示。旧记录缺少环境或位置时标注「未记录」。 |

**本地模块用例的范围。** 用户选择模块后，预览该模块及子文件夹中对当前环境适用的接口用例；同一接口的多个用例分别列出。无适用用例的接口单列并说明跳过原因。底栏切换环境后重新计算预览。无可运行用例时说明原因并禁用「运行模块用例」。数字使用「接口数」「用例数」等具体单位，数据驱动的实际执行行数在运行后按报告展示。预览和发起执行均以同一套 Core 选例规则为准。仅本机可执行时，底栏保留环境快捷选择，「本次执行」仍明确显示位置为「本机」。

**记录详情的动作。** 点击记录只读该次事实；有报告时可就地打开，尚在运行时按能力提供取消。底栏修改只影响后续手动发起，不能改变所选历史记录的环境或位置。已结束但断言失败的任务同时显示「已结束」与「失败」及原因。

## 在线通知详情的两个跳转

已确认纳入本轮设计。每条通知在详情内同一位置依次提供「查看计划」「查看本次运行」；「标为已读」是独立动作，跳转本身不修改已读状态。

| 入口 | 定位与不可用状态 |
| --- | --- |
| 查看计划 | 按通知所属工作区、项目及计划 ID 打开「定时任务」，选中该计划的当前配置。若读取时发现计划已删除或权限已收回，保留来源通知并给出可读提示。 |
| 查看本次运行 | 按通知关联的任务 ID 与执行 ID 打开「任务记录」，核对身份后显示对应运行。记录在最近 20 条之外也可直接定位。无执行关联时按钮在原位置禁用，旁边说明“此通知没有关联运行”。报告尚未归档时，仍可查看有权读取的运行状态；若记录已不可访问，则反馈原因。 |

通知列表覆盖工作区内当前成员有权查看的项目。跨项目时使用**通知自身**的项目身份打开或复用目标标签，遵循原有草稿保护和服务端权限。返回通知时恢复来源项目、选中项及列表位置。复用[通知字段](../packages/execution/src/contract/scheduling.ts)、[计划详情读取](../apps/desktop/src/renderer/src/stores/onlineSchedules.ts)和[原运行定位](../apps/desktop/src/renderer/src/components/online/OnlineProjectAssets.vue)。

## 实施后的对照验收

以下均为待执行场景，样板图只用于视觉对照。

1. **两种模式走同一条路径。** 各打开一个项目，依次选接口、改参数、切环境、发送、看响应、切工作流再返回。核对入口位置、真实请求目标、响应展开、未保存状态与草稿恢复。
2. **区分快捷切换与管理。** 在本地和在线分别从底栏切环境，编辑位置保留；再从侧栏进入环境管理。核对长名、中英文、键盘操作、窄窗及响应区展开后的底栏。
3. **核对项目隔离与旧草稿。** 两个项目选不同环境，来回切换；覆盖旧请求签与草稿原选环境不同的场景。发送前显示的目标与实际执行一致，旧弹层无法改写新项目。
4. **核对能力差异。** 本地仅本机可执行；在线分别覆盖本机、可用代理、离线代理和只读成员。入口可达性、禁用原因、查看和执行权限分别核对。
5. **核对当前选择与执行事实。** 运行后切底栏再查看历史；同时打开已保存的定时任务或带显式环境的压测计划，确认执行记录及资产配置保持原值。核对「已结束但失败」、排队和已申请取消三类状态。
6. **从通知定位并返回。** 核对有执行记录（含列表首屏之外）、无执行关联、报告待归档、跨项目带草稿，以及目标被删除或权限已收回。两个入口次序固定，分别定位到正确对象；返回恢复原通知，已读状态仅随显式操作改变。
7. **核对本地模块范围。** 使用含子文件夹、多用例、数据集、无适用用例以及另一项目同名模块的夹具。切换环境后核对预览与实际选例；确认不跨项目、零用例不可启动、用例数和实际行数标示清楚。
8. **核对两端运行入口。** 分别从「发起任务」运行已有套件，再从原业务页发起一次运行。核对前两个页签顺序、每次执行仅有一条对应记录、打开详情不会重跑、返回后仍定位原记录。在线列表无模块用例选项，本地可从模块预览直接启动。
