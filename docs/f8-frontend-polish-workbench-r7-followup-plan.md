## 1. 评审结论与实现边界

| 需求 | 入口与交互 | 保留的能力 |
| --- | --- | --- |
| 项目资产 | 目录左下固定「项目工具 → 项目资产」。打开后直接显示模型和组件，省去两层同名折叠。请求体和响应契约有模型引用时，从「查看模型」定位该模型。 | 模型、组件、共享认证、引用检查及既有管理操作。 |
| Mock | 同一「项目工具 → Mock」，项目工具同时保留「外部规范同步」。目录收起或未显示时沿用模块栏的项目工具入口。 | 状态、规则、保存、启停、刷新、重载、地址复制、日志和新建自由请求。保持 Mock 已保存配置、草稿和当前运行实例各自的语义。 |
| 导入接口 | 目录右上「＋ → 导入接口」。只读显示当前目标项目，有合并目标时显示已选模块名。 | 默认在当前项目新建模块。原有显式合并、来源选择、冲突处理及预览确认继续可用。主页「导入项目」仍可选分组并创建项目。 |
| 凭据与 OAuth | 请求「认证」页签内显示认证方式、引用和状态，提供「管理凭据」与「OAuth 授权」。共享认证组件可直接定位到对应资产。 | 现有认证类型、凭据维护、OAuth 授权与刷新，保留本地和在线各自已有的能力与权限。 |
| AI 建议用例与管理模型 | 建议放在接口标题行、靠近「接口详情」。窄窗进入请求「…」。模型管理走现有「设置 → AI 设置」。缺配置时先打开建议抽屉，说明需要配置模型，用户点击「打开 AI 设置」后进入配置。 | 当前接口归属、数据范围确认、建议生成和采用、AI 配置与已有诊断。设计视图也保留从当前接口打开建议的入口。 |
| 响应展开与收起 | 响应栏右端同一位置显示「展开」或「收起」。辅助技术读到「展开响应」或「收起响应」。收起后为单行，编辑区接收腾出的高度。 | 结果、分隔比例、原始和格式化正文、搜索、复制、安全投影、错误详情及原有响应页签。 |
| 调试历史 | 响应标题栏右侧。收起条保留一键入口。设计视图和其他已有的历史直达入口沿用同一历史面板。 | 当前接口、当前项目与全部筛选，查看、恢复、重放及合格记录分享。 |
| 请求参数恢复 | 基线为最后一次成功保存的内容，首次打开用已加载的持久内容。原本缺省的值改回空白后恢复缺省，原本显式空保持空字符串。基线非空时，清空仍是修改。 | 其他字段、其他协议、设计控件的草稿及仍需补输入的历史恢复状态。界面、关签和退出使用一致的待保存结论。 |

样板展示位置和展开状态。响应按钮文案以上表为准。样板省略的已有动作和状态按上表及 [r7 原入口对照](f8-frontend-polish-workbench-r7-design.md#3-顶栏与主页入口迁移对照)保留。响应契约仍属接口编辑。布局使用现有主题和组件，数据格式、执行、鉴权、密钥保存、导入和部署沿用现有契约。

### 响应状态默认值

本轮按计划建议的默认值实施，在集中联验中核对。

- 新请求签尚无结果时默认收起。用户可随时手动展开看空态或历史。
- 当前签点击「发送」且进入运行后展开，便于观察运行和结果。用户在运行中手动收起后，结果到达只更新收起条摘要。预检拒绝沿用现有可读反馈，后台签的结果不会改变当前签布局。
- 展开偏好按当前打开的请求签记忆，切走再回来恢复各自状态。关闭请求签时释放状态。展开恢复最近一次有效分隔比例，当前窗口太短时继续用已有短高布局。

## 2. 分批实施与验收

沿用 r7 分工。一个 Sol xhigh 子代理负责开发，一个 Sol xhigh 子代理做独立审核。三个产品批次按下列顺序推进。相邻控件和对应回归合在同一批，避免两个实现同时改 `App.vue` 或 `RequestEditor.vue`。每批以可操作的完整路径交接，开发方记录变更、验证、首个失败及剩余项。独审者一次集中反馈，修正后只复核受影响项。第三批后再做一次覆盖三批的集成复查。

### 第一批　项目工具与目录导入

1. 在 `App.vue` 和 `SideTree.vue` 接入项目工具及目录菜单。项目身份使用当前工作区目录和完整项目定位，现有在线项目工具按原条件可达。只读、空项目和失去当前作用域分别遵循现有权限。项目资产、Mock 在原操作可由新入口完整访问后移走旧折叠。
2. 复用 `ProjectAssetsPanel.vue` 和 assets store。项目工具能在未打开接口时加载对应资产。通过模型或共享认证组件的稳定 ID 定位到目标，缺失时给可读反馈。关闭后回到触发位置，保留请求草稿与编辑位置。
3. 复用 `MockPanel.vue`。同一项目切接口或收起工具面板不应丢当前 Mock 草稿或重启运行实例。关闭面板应停止前台轮询，重新打开核对版本，已运行的 Mock 继续由原宿主管理。切项目后丢弃旧读取的迟到展示，操作反馈不串到新项目。新建自由请求沿用当前项目归属。
4. 复用 `ImportWizard.vue`，从目录打开时带入当前项目和已选模块的有效上下文。默认路径新建模块，合并只使用已选模块。切项目、工作区或目标模块失效后，旧预览不能应用到新目标。预览的来源、覆盖确认、取消、撤销能力及主页导入项目保持原路径。

**本批通过条件**　能从空请求区和已开接口分别打开资产、Mock、导入。两项目间切换不会错读、错写。导入预览与实际落盘同属当前项目，分别走一次新建模块和合并，原同步入口正常。复用 `App.test.ts`、`contractAssets.test.ts`、`MockPanel.test.ts`、`ImportWizard.test.ts` 的受影响场景。集中手验左下菜单、模型定位和目录导入路径，至少记录正常及窄窗各一张图。

### 第二批　请求认证、AI 入口与待保存状态

1. 将 `CredentialEditor.vue` 和 `OAuthManager.vue` 通过「认证」页签接入，复用现有认证上下文、环境、凭据存储与管理状态。表单显示引用和可读状态，避免将秘密值带入接口草稿、截图或日志。切换参数页签不能额外取消授权，切换请求或项目时继续按原规则隔离并处理在途动作。验证本地接口签、自由请求和已有旧入口。
2. 将 AI 建议入口移至接口标题，在窄布局走请求菜单。设计视图保留当前接口的 AI 建议入口。建议调用保留接口、草稿范围和可用条件，切签后旧反馈不落到新接口。缺模型时由建议抽屉提供「打开 AI 设置」，关闭设置后可回到建议流程。配置弹层可以独立打开，避免把凭据或供应商配置塞进请求表单。
3. 先用导入接口的缺省参数构造有效复现，再按字段基线处理参数值。覆盖路径、查询、请求头和 Cookie 的内联及组件引用。用原绑定身份匹配值，不用行索引判定，保留有意义的显式空值、其他改动和无效草稿。两种保存各自以已成功保存的范围更新基线，失败或迟到的保存不能清除其后的修改。

**本批通过条件**　认证页可见方式、引用和状态，凭据保存与授权归属正确。AI 建议在宽窄布局和设计视图可达，缺模型时能进入设置。原值缺省、空字符串及非空分别验证撤销、手动恢复、仍有其他改动、保存后新基线、关闭请求签和项目签。以 `App.test.ts`、`contractAssets.test.ts`、`AiSuggestionsDrawer.test.ts`、`AiConfigDialog.test.ts`、`stores/editor.test.ts` 和关签回归中受影响的测试为主。对于有差异的草稿源，验证退出确认仍生效。

### 第三批　响应与历史

1. 在 `App.vue` 和 `ResponseViewer.vue` 接入响应收起条、共享标题操作和分隔行为，复用已有请求签和运行状态。状态切换仅改变布局。收起时从布局和焦点序列撤出正文与分隔条，展开恢复当前交换、子页、滚动和分隔。保留拖动、键盘调整与复位。
2. 复用 `DebugHistory.vue`。展开和收起时使用同一入口位置，响应为空、发送中、成功、失败、取消均可进入历史。打开及退出历史不会发送请求，也不丢失未保存编辑。设计视图中通过接口级入口访问同一面板。
3. 清理已完成迁移的顶部重复按钮和对应窄窗工具组。逐条从原调用核对新入口和可用条件。确认发送、保存、响应工具和设计视图快捷操作都可达。

**本批通过条件**　收起后编辑区高度实际增加、单行仍可读，展开后对应同一响应。前台 200、503、同位取消及预检拒绝有正确状态，后台签完成不改变当前签布局。调试历史两种状态均能打开，确认至少一次筛选和一次恢复路径。复用 `App.test.ts`、`components.test.ts`、`stores/debug.test.ts`、`stores/requestTabs.test.ts` 的受影响场景。实际测分隔高度和恢复，验证窄窗、短高以及 Tab、Enter、Esc 和回焦。

## 3. 集成验收与归档

三批后固定同一候选，跑受影响回归、桌面类型检查与构建。使用隔离合成工作区和回环服务，取同一请求、同一窗口和缩放的 r7 前后图。集中确认项目工具、导入目标、认证和 AI 快捷方式、待保存状态，以及收起条在实际桌面可达。覆盖中文浅色常规窗与英文深色窄窗，测试涉及的远程功能使用已有夹具，实际未联验的路径单列。行为测试、源码预览、原生实包证据分别记录。

交付时从冻结候选制作一次 Windows x64 验证包，执行现有目录包冒烟。归档候选源码、`app.asar` 与 ZIP 哈希，记录布局实际尺寸、各条需求的测试与人工结果、已知缺口和独审回执。验收图及索引拟放 `docs/design/f8-frontend/r7-followup/`，原始测试、客户端日志和包拟放 `local/f8-frontend-r7-followup/`。保存历史失败与复验结果，更新工作日志和验收矩阵。本地全量或完整门禁逐次取得授权，提交、合并、推送沿用当次授权。
