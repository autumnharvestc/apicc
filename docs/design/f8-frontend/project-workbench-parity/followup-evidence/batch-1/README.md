# 第一批 · Windows 桌面实机

两份本地「订单服务」项目位于独立的磁盘工作区。在线「订单服务」使用新建的 HTTPS 控制端、合成订单服务及独立 Linux 代理，登录角色为项目所有者。客户端运行正式 Vite 产物，使用 Electron 的真实主进程、预载和文件／在线适配器。以下图片取自 Electron 的 Chromium 合成画面，中文、亮色、内容区 1672 × 941、设备像素比 1。

## 三个项目往返

初版 `index-6XYJ_d6H.js` 可复现本地 2 返回后侧栏仍高亮「数据集」、右侧却提示去运行场景。只切本地 1 和本地 2 也能复现。直接再点数据集未恢复正文。本文保留该次失败以便对照。[初版实拍](first-candidate-local2-missing.png)

修订候选 `index-CMUukLwV.js` 的三个项目首次新开都显示「接口」。设置好三个工作位置后，在同一个 Electron 进程按以下顺序切签。在线样本为合成一次性计划已经归档的任务，代理 1、任务 1、执行 2。表中「环境」为底栏选项。

| 步骤 | 项目 | 侧栏和正文 | 环境 | 实拍 |
| --- | --- | --- | --- | --- |
| 1 | 本地 1 | 环境，正在查看「本地 1」 | 无环境 | [打开](roundtrip-1-local1.png) |
| 2 | 本地 2 | 测试 → 数据集，正在编辑「订单样本」 | 集成环境 | [打开](roundtrip-2-local2.png) |
| 3 | 在线 | 运行 → 任务记录，故意失败的断言 | 代理环境 | [打开](roundtrip-3-online.png) |
| 4 | 本地 2 | 测试 → 数据集，「订单样本」列表与正文均恢复 | 集成环境 | [打开](roundtrip-4-local2.png) |
| 5 | 本地 1 | 环境 → 本地 1 | 无环境 | [打开](roundtrip-5-local1.png) |
| 6 | 在线 | 运行 → 任务记录，原执行 2 的失败详情 | 代理环境 | [打开](roundtrip-6-online.png) |

切签前、后从合成服务按时间戳计数，均有 5 条业务 HTTP 请求。在线项目代理任务数均为 1。两次回到在线均能看到归档详情中的失败节点。上述操作没有增加业务请求或任务。

## 目录、草稿与失效回退

| 场景 | 实机操作与可见结果 |
| --- | --- |
| 两端目录与搜索 | 展开「订单服务 → 售后服务 → 空文件夹」和单独的「空模块」。搜索 `collection.yaml`、`folder.yaml` 各得 0 个接口，搜索 `project.yaml` 只返回真实 GET 接口，选择后两端均能编辑其 `/health` 请求。点开两端项目工具和「订单服务」模块菜单并读取菜单项，均未出现配置文件。[本地实拍](local-directory-search.png) · [在线实拍](online-directory-search.png) |
| 接口与响应 | 初版实机在两端分别修改请求草稿为 `/fail`，由桌面本机取得 HTTP 503 和合成响应正文，离开再返回后可见原草稿和响应。本地另验证记住「设计」及随后切回「调试」时的响应。 |
| 工作流与环境 | 初版实机两端分别打开「02 V2 创建订单后查询」，选中 read 节点，修改名称并缩放画布。切出再回时，局部草稿值、所选节点与画布平移／缩放值逐项相同。本地缩放 1.13288，在线 0.870551。两端分别编辑具体环境的模块地址，侧栏往返后能继续编辑草稿。六步表第 1、5 步可见浏览「本地 1」时底栏仍为「无环境」。 |
| 测试与记录 | 初版在线测试数据集草稿在环境页往返后保留。本地 2 的数据集恢复以修订候选的六步表为准。本地显式执行故意失败的两节点工作流并从回执进入档案，切出再回仍显示该次失败。本地档案初版将环境展示为 UUID，列入第 5 批复核。[初版在线记录](first-candidate-online-record.png) |
| 离开时删除对象 | 修订候选在在线测试中选第二个同名「订单样本」后切去本地 1，通过合成服务删除该数据集，再切回在线。剩余的同名对象留在列表，详情清空，界面就地说明原内容已删除或权限变更。取证后将合成资产恢复。[删除后实拍](deleted-online-dataset.png) |
| 同名项目快速切换 | 另一独立桌面打开不同分组的两份「订单服务」。第一份停在环境「本地 1」，第二份选两个同名数据集中的第二个。快速切签五次后，两份分别恢复对应工作位置，第二份同名列表的高亮依次为否、是。 |
| Viewer 整项目撤权 | 只读成员查看数据集时，名称输入和保存按钮均禁用。离开在线签期间撤去整项目访问权，返回时旧详情与底栏均已撤去。[初版只显示原因](viewer-project-access-revoked.png)，第一次加返回按钮后曾[误入本地项目列表](first-return-local-home.png)。修订候选 `index-DfRmv6ts.js` 的[撤权提示与返回按钮](viewer-access-recovery.png)可回到[原在线工作区的项目列表](viewer-accessible-list.png)，从中打开了「售后订单 · 可访问」。用修订后的主进程启动全新 Viewer 窗口。确认撤权后，桌面实际使用的 GET /tree 只返回兄弟项目 2，首页也只出现这一张在线卡片。另一个 GET /projects 元数据端点仍返回两项名称。读取原项目资产返回 HTTP 403，读取兄弟项目资产返回 HTTP 200。主进程通过 tsc -p tsconfig.electron.json 编译，online/execution.js 的 SHA-256 前 12 位为 9407CF321EEC。取证后恢复原继承权限。 |
| 通知主动定位 | 修订候选从未读通知打开本次运行，定位到代理／任务／执行 `1/1/2`，返回原通知再打开对应计划，可见其发生记录。第二次返回时仍可手动标为已读。前后业务 HTTP 5→5、代理任务 1→1。 |
