## 数据集

1. 两端从「新建」建立与样板相同的三行两列订单，保存、离开并重选后核对类型、值及说明。另各建 101 行、16 列合成数据，通过界面的 JSON 导入预览查前 100 行、应用并保存。磁盘和服务器回读、重新选择后的导出预览均与输入 101 行逐值、逐类型相同。样本包含字符串、数字、空字符串、显式 null 及隔行省略字段。
2. 两端点击下一页均显示行号 101。宽表可见宽 1130 CSS 像素、实际内容宽 2317，水平滚动 1187 后左侧列表位置不变。取证后分别通过菜单删除本次创建的宽表，读盘、读服确认该 ID 消失。
3. 本地另在空草稿中添加两列、两行并输入值。移除含数据的列时先取消，保留两行两列；确认后再删一行，保存得到一行一列。草稿取消与同名保存／删除见[第二批四组身份验证](../batch-2/README.md)。

## 套件

本地「订单回归」同时指定了套件外层数据和查询子用例的数据驱动，预览明确提示冲突，当次业务请求增量为 0。将子用例切到「无」并保存后，套件预览为 2 个条目、2 轮、4 次执行。两端均显式运行，在合成业务端分别记录 POST /orders → GET /orders/ORD-1001 → POST /orders → GET /orders/ORD-1001。本地结果可按条目识别两轮，各 4 条通过；在线本机执行也产生四条请求。取证后将两端子用例恢复为订单样本。修订候选 `index-tYydF7qb.js` 的[展开预览](T05-expanded-preview.png)显示数据集「订单样本」、两条接口和用例名及每条预计执行两次。

本地另建并保存「遇错停止验证」，重开后实际只发送 GET /fail（503），下一个健康检查条目显示「跳过 · 遇错停止」。换用标签筛选「回归」时，预览只解析为查询接口（ID 末尾 0012）的 base 用例，一项有两条数据。套件报告与证据选项按宿主能力提供。

## 压测授权、启动与停止

- 初次进入保留列表和选择指引。新建显示未保存计划，启动禁用。选已保存的「订单查询压测」后，确认前后业务 HTTP 均为 19 条、在线代理任务均为 2 条。底栏环境、执行位置、授权 origin 以及压测目标分别变更后，原授权均失效。显式计划环境与项目环境不同时，界面出现就地提示。
- 回到集成环境和本机，重新确认并显式点击开始，回执 `bea46a9f-7b80-41e5-a1c1-cc9131fd26a8` 定位「订单查询压测」。服务端记录两条 GET /orders/ORD-1001，桌面详情给出 2 条合格完成请求。计划在本合成样本设了最多 2 次迭代。
- 使用另一份同名但独立 ID 的慢请求计划。切回原计划时停止按钮为 0 个，返回正在运行的计划才可停止。实际慢请求正在执行时操作，本机日志为 GET /slow，连接以 cancelled 结束，所选运行 ID 为 `687aeed2-4598-4c59-a9e0-9233860e4bc7`。[本机运行记录](T06-stop-record.png)
- 同一慢请求计划改为显式代理环境，通过底栏选择合成 Linux 代理提交后，切到另一同名计划同样无停止按钮。对原计划申请停止，只新增一个代理任务。最后一次控制端回读为代理 1／任务 7／执行 8，状态 preparing，取消 requested；此项记录的是服务已收到取消申请。

本机慢请求的取消已由业务端观察到，桌面回执仍显示「提交结果未确定」。另一次在请求尚未发出时取消，回执正确显示「已取消、确定未启动」。已把这两类回执交第 5 批核对。
