# 「运行」页视觉定稿与验收依据

**2026-11-19 用户确认。** 本目录中编号 01–08 的八张 PNG 是本地与在线「运行」页共同的视觉交付依据。开发、独审和最终验收均使用同一组图。历史讨论稿与旧包实拍用于追溯上次偏差。当前状态为**设计已定稿，产品视觉待实现、待真机验收**。[打开定稿图册](gallery.html)

## 历史依据

| 阶段 | 可以核实的事实 | 对交付的影响 |
| --- | --- | --- |
| 设计与归档 | 三批计划首页引用本地发起页、底栏和任务记录。本轮从当时会话的出图目录找回在线发起、定时和通知三张图，原计划没有链接它们。设计写明了两端一致、页签顺序、预览、底栏及通知跳转。 | 后续依据足以回答操作放在哪里。对于两端外观不同时以哪一张图为准，开发和审核缺少共同参照。 |
| 实现 | 两端都调用 `RunLaunchForm.vue`。本地 `RunView.vue` 提供「运行」页标题、16 px 页面内边距；在线 `OnlineRunRecordsHost.vue` 从页签开始，自行设置白色底面与页签边距。表单的两栏随内容撑高。 | 本地实拍中两块卡片在页面中段结束，和本地样板延伸到底栏上方的布局不同。在线实拍中缺少页标题，首张卡片贴近侧栏，按钮也随卡片内容高度上移。 |
| 审核与验收 | 计划确实要求看图。B 批的判据集中在目标、范围、跳过原因、按钮及请求证据。存档实拍包括本地模块预览和在线代理工作流，已经能看到两端标题与留白的差异。验收记录没有同一窗口尺寸、同一目标、同一选择状态下的双端对照结论。 | 执行范围正确、有截图、实际请求到达都获得了验证。主会话仍把存在视觉差异的版本作为本轮交付，这是最终验收的遗漏。 |

## 八张定稿与适用场景

[打开离线对照图册](gallery.html)。先看第一行。在同一「订单服务」项目中，两端都选「查询订单」的「已付款订单」，环境为「集成环境」，执行位置为本机。这里特意固定业务数据，让页标题、字体层级、分栏、间距和主按钮位置可以直接比较。评审范围是「运行」页面和项目底栏。顶栏图标、全局菜单、既有报告及执行操作仍依现行产品与权限提供。

| 核对场景 | 本地 | 在线 |
| --- | --- | --- |
| 同一用例已选 | [本地发起](02-local.png) | [在线发起](01-online.png) |
| 类型与选择状态 | [模块用例范围、预览及跳过原因](03-module.png) | [尚未选目标，预览与按钮状态](08-empty.png) |
| 同一类断言失败 | [本机运行历史](07-local-records.png) | [代理任务记录](04-records.png) |
| 在线计划与消息 | | [定时任务](05-schedule.png) · [通知](06-notice.png) |

- **共同外观。** 沿用在线原图的浅灰蓝工作区、白色细边框双栏、独立「运行」标题、蓝色下划线页签与底部细栏。发起页左侧约占 55%，右侧约占 45%。宽窗两张卡片从同一高度起排，下边缘接近项目底栏。未选、选中、列表很短时均保持主要操作位置稳定。窄窗或高度不足时，列表与详情可滚动，主操作可达。
- **模式差异。** 两端同名操作的标题、次序和位置一致。本地底栏仅显示环境，预览内可见实际位置「本机」。在线另有执行位置选择器及两个专属页签。计划显示自身保存的环境与代理，历史显示实际执行时的值，当前底栏表示后续手动运行的选择。
- **交互语义。** 选择目标只预览。未选目标时就地提示并禁用运行按钮。任务记录分别给出执行状态、结论和失败原因；取消、查看报告等操作按真实能力展示。通知详情保留「查看计划」「查看本次运行」两个入口，无对应运行时后者禁用并说明原因。示例展示了有关联的通知。

## 视觉验收标准

| 对照画面 | 真机必须看见的效果 |
| --- | --- |
| 在线与本地发起，图 01、02 | 按「运行」标题、页签、双栏、底栏的次序从上到下对齐。两端相同位置使用同一级字号、字重、留白和控件密度。浅灰蓝背景围住白色细边框卡片，选中行同时有浅蓝底与左侧蓝线。来回切换时，列分界、预览和右下角主按钮位置稳定。 |
| 空选择与模块预览，图 08、03 | 取消选择后，右侧保留整块预览区域及禁用按钮；短列表不会使卡片缩到窗口中段。选择模块后可以直接读出用例表和跳过原因，底栏上方仍留出边距。 |
| 本地与在线记录，图 07、04 | 列表和详情并排；选中行与右侧记录对应。首屏看得出执行已结束、断言失败及具体原因。中性执行状态与红色失败结论区分清楚。历史环境和位置取自此次记录。 |
| 在线定时任务与通知，图 05、06 | 复用同一页标题和页签位置，各按定稿分配列表与详情宽度。计划配置和触发规则分组清楚；通知中执行失败与投递成功可同时辨认，「查看计划」「查看本次运行」相邻，「标为已读」独立。 |

图 01、02 原尺寸均为 1672 × 941。可叠放两张图核对同一位置。以图片左上角为原点，两张卡片的上沿约在 y=198，下沿约在 y=880，项目底栏上沿约在 y=895。发起页两栏间约有 12–14 个图像像素的浅色间隙。这些坐标用于原尺寸图片对照；窗口或系统缩放变化时，按项目内容区域的相对位置核对，实际控件随主题与缩放适配。

**如何判定通过。** 一个开发负责人负责两端共同布局，首个可运行版本先拍图 01、02 对应状态。交付前用同一候选版本按八张定稿逐项回填「样板编号、项目与选择状态、窗口尺寸与缩放、主题、实拍链接、视觉结论」。双端场景用相同条件并排或切换对照；可复用本批已有实拍。窄窗另核对长列表、主操作和底栏的可达性。

独审查看定稿和实拍，主会话最终复核。缺少对应实拍的场景标为待验；标题缺失、卡片贴边或塌缩、按钮漂移、布局层级或状态表达偏离定稿的场景标为待修。所有场景有对应证据且可见偏差已处理，才记录为视觉通过。修复后复验受影响画面即可。
