## 初稿提示词

制作一张横向、高清、可直接评审的 Windows API 客户端 UI 样板图。第一张提供现有客户端整体布局作为编辑基础，第二张仅提供行菜单的旧界面参考。把相关交互绘制为同一张样板图：上方一张完整工作台主画面，下方并列两个清晰的目录菜单局部状态。三个区域的目录样式、层级和行内容一致。沿用现有浅蓝灰工作台、白色编辑卡、蓝色选中项、左侧竖向图标导航和橙色现有应用图标。字体用清晰中文系统无衬线，Windows 桌面实用风格，禁止原截图红色手绘线和水印。无需额外彩色装饰。

主画面（约画布上方 65%）：顶栏固定「主页」，项目签「p1」选中和「p2」，保留「demo-2」工作区标签，一处 p1 即可确认项目。目录标题「目录」右侧从左到右为一个加号和一个项目操作省略号，搜索在下一行。目录树第一行直接是模块「商店 API」，不要在树里显示项目 p1 节点。第二个模块为「库存 API」。模块名左右留出呼吸，所有模块和文件夹行的「⋯」最右对齐，右侧永远只有一个省略号按钮，没有行内铅笔或垃圾桶。模块内有文件夹「宠物」和接口 GET getPetById；另有目录「订单」，其中列 GET getOrderById。最底部单独一行模块「未分类接口」带小型「默认」标签，模块下面有一个简单示例接口，随后是左下固定的「项目工具」。右侧展示 GET getOrderById 的请求编辑器，标题上方层级仅「商店 API / 订单」，不重复 p1。保留调试、设计、查询参数、发送、保存、右下响应收起条和「调试历史」「展开」。接口或请求的内容使用少量真实示例，避免视觉噪音。

下方两个并排等宽目录局部，相当于同一 UI 的两种独立状态。左状态标题「目录标题菜单」，画出菜单锚在目录标题的「＋」上。菜单只有三项，依次「新建模块」「新建接口」「导入接口」。左图绝对不要在加号菜单显示「新建文件夹」。右状态标题「模块行菜单」，画出菜单锚在「商店 API」模块行最右侧的那个「⋯」。菜单依次「新建接口」「新建文件夹」「管理」「重命名」，分隔线后红色「删除」。上下文菜单不会同时打开，每个局部只打开其指定菜单。重点确保两组菜单的字逐项完整、位置区别明确，放大可读，中文准确。画布底部留足余量不截断删除菜单。

## 修订提示词

基于第一张样板图做一次局部校正。第一张是编辑目标，第二张原产品截图用于参考已有控件。保持第一张的画面构成、配色、尺寸、所有标题、扁平树、项目签、路径、两种菜单锚点和所有菜单文字。只修以下细节：一、主图请求签那一行最右恢复第二张已有的按钮「＋ 新建 HTTP 请求」。二、主图选中的接口 getOrderById 行最右用现有的细线铅笔和垃圾桶两枚悬停图标；三个视图中的接口行不要画省略号。每个模块行和文件夹行最右继续只用单个省略号，纵向对齐。三、主图蓝色选中「路径参数」，其后依次可见「查询参数」「请求头」「Cookie」「认证」「请求体」。把请求栏拆回原产品的「HTTP」「GET」「https://api.example.test」「/orders/{orderId}」四段，参数表展示 orderId=10001。其余内容按照第一张原样绘制。保持两种打开菜单的各自面板里只有一个弹出菜单，目录标题加号菜单精确为「新建模块」「新建接口」「导入接口」，模块行菜单精确为「新建接口」「新建文件夹」「管理」「重命名」「删除」，删除红色且位于分隔线后。不增加装饰、水印、标注。中文精确。
