## 整个 F7g 的补充审查

以 `b31b6b1a06d5b1d0788414e92c39e982b8824b5c` 为阶段基线，按客户端/Core、来源宿主/运行时/CI、在线服务/管理台分区读取完整文件及阶段差异，逐路径记录内容摘要、职责与哈希；锁文件、工作区闭包、工具依赖和产物接线包含在内。修复发现后由原审查者复核对应差异，不重复启动全阶段宽审。

补充审查发现并纳入本轮的四项问题：

1. 后台新结果不能替换正在确认的固定候选。保留原内容、决策和固定全文，明确提示已被替代；顶部刷新才切换结果并清空旧决策。并发旧查询不能解除已知替代状态。服务端成功保存/续期候选时，在原事务内使同来源其他候选过期；相同固定 ID 可合法续期，旧查询不因此获得回写新状态的权利。
2. 已确定未提交的有限拒绝不能永久占住旧操作意图。只对经逐项核实的 HTTP 状态/错误码释放意图；未知错误、丢响应、提交后异常和单次回执 404 继续保留身份，不自动重放。
3. 候选的新鲜度不要求当前读取者拥有“检查来源”能力。应用仍要求当前成员、读取、应用、授权世代、全部候选戳和脚本权限；有检查权限不自动获得应用权限。
4. 活动检查通过原有单次续约通路观察来源、资产、材料、授权和策略变化，并取消实际在途读取。使用版本元数据，不每轮读取整个项目/基线/持久快照；仍保留原有完整提交校验、独立单调期限、迟到 ACK 防护和不确定资源占用。仅在线计划字段改变时，已有独立手动读取保留原归属，最终来源版本校验不放宽。

新增观察不是“整个续约事务不读正文”：既有材料接口仍取加密信封，既有计费回调仍读取同步记录正文。一个物理私有目录由一个 Node 进程独占的部署边界保持不变。
