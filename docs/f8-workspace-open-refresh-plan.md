## 批次关系与交接

第一批交付同配置启动复用、实际目录去重和安全切换。第二批使用第一批的实际根目录、完整项目定位和会话切换保护，在这个基础上交付从磁盘刷新和草稿恢复。第一批可以独立交付。第二批的合成夹具和竞态用例可以提前准备，产品接线从第一批已验收候选继续。

每批由现有开发子代理实施、另一位子代理独审，沿用 Sol xhigh。每批分别冻结候选，按用例对照表核对实现、测试和证据。独审未关闭的发现修正后定向复核。第一批满足交接条件后直接开始第二批，中间的验收以用例证据为准。常规实现取舍、夹具修正、定向复跑和审查修正由执行者处理。出现实际阻塞时，先推进该批可独立的工作，留下受阻的用例、原因和已经取得的证据。第一批如果仍有目录身份或切换问题，第二批可准备夹具和测试，产品接线等这项依赖通过再开始。

两批分别记候选标识、改动文件、审查结论和证据。第二批会回归它实际用到的第一批入口。完整本地门禁按仓库约定逐次确认。产品范围以[产品设计第 2、3 节](f8-workspace-open-refresh-design.md)为准。新窗口打开、在线自动合并和本地自动合并及跨项目更新提示已各自归档。

## 第一批　启动复用与实际目录去重

### 技术详细设计

- **应用实例。** 在桌面主进程确认实际配置目录后、装配工作区和任务服务前请求 Electron 单实例锁。后发进程只发唤醒请求并退出。先发进程若尚未建窗则记一次待唤醒意图。窗口可用时恢复最小化状态并聚焦。沿用现有窗口创建、退出确认及 macOS 激活流程。`--user-data-dir` 使用真实独立目录验证，并核对原有隔离环境变量继续生效。[桌面主进程](../apps/desktop/src/main/main.ts)
- **目录身份与切换顺序。** 主进程通过文件系统解析实际目录，保留 Core 的路径与安全检查。按文件系统语义识别同址路径。物理复制目录即使内部 ID 一样也分别打开。将比较当前身份、校验并准备目标与提交切换放入同一串行流程。同址在目录重载、任务取消、Mock 切换和清调试状态之前返回复用。异址先准备可用目标，再进入原切换清理。目标取消、失效或读取失败时，原会话和任务继续可用。保持原有可打开只读工作区的规则。[会话](../apps/desktop/src/main/session.ts) · [IPC](../apps/desktop/src/main/ipc.ts)
- **渲染层归属。** 打开回执明确区分复用和实际切换，并携带主进程解析的根。同步共享类型、IPC 和测试适配器。工作区 store 对同址复用保留已有快照。项目签按实际根加完整项目定位激活，不因别名另开或覆盖其他项目的草稿。旧签恢复用可验证的路径归并同一项目。失效路径仍可见且可处理。解析目标后的打开路由是未来新窗口的接入点。[工作区 store](../apps/desktop/src/renderer/src/stores/workspace.ts) · [项目签 store](../apps/desktop/src/renderer/src/stores/tabs.ts) · [IPC 契约](../apps/desktop/src/shared/ipc-contract.ts)

## 第二批　显式磁盘刷新与草稿恢复

### 技术详细设计

- **稳定读取与发布。** 新增专用磁盘刷新操作。继续用 `TreeGet` 获取当前内存树。磁盘刷新捕获实际根、工作区 ID 和会话代次，与本地打开及写入按会话顺序执行，并允许磁盘版本领先。按 Core 现有诊断、根目录检查和事务规则读取，校验读取窗口内的版本一致性。校验通过后用同一份快照生成工作区、目录树和版本，再更新会话。有活动运行、导入、同步应用或写入占用时沿用现有状态判定并提示重试。读取失败、诊断阻碍、磁盘工作区被替换或会话已切走时保留原上下文。合并同一工作区重复点击产生的在途刷新。[会话](../apps/desktop/src/main/session.ts) · [IPC](../apps/desktop/src/main/ipc.ts) · [Core 文件存储](../packages/core/src/storage/fileStorage.ts)
- **错误契约与写入。** 通过共享 IPC 类型传递可区分的本地错误原因及必要的目标归属，覆盖版本过期、写入暂忙、只读或恢复问题及普通失败。核对共享契约、预加载与测试适配器。保存成功沿用现有行为。冲突写入保持失败状态、定位原目标并提供「从磁盘刷新」。刷新后仍由 Core 预期版本校验和写锁决定该次保存。在线入口维持现有冲突处理。
- **草稿基线。** 各编辑器按实际根、工作区、项目和资产范围留存最后确认的保存基线、当前草稿和保存提交快照。刷新结果按既有写入单元及实际依赖对照。干净目标更新到磁盘版。草稿基线及其依赖未变则保留编辑，更新保存前提，由用户重新保存。目标或依赖已变、已删或无法可靠比较时，保留原草稿和基线，限制该目标写入。放弃草稿或载入磁盘版本由用户明确确认。无正式保存目标的临时调试稿维持原归属。用编辑代次处理晚到回执，刷新过程中的新输入及环境分步保存中未成功的部分继续保留。
- **用户入口。** 在本地主页工作区菜单提供「从磁盘刷新」，保存冲突复用同一操作。更新时尽量保持当前签、页面、选中项和运行结果，目标确已删除时给出可用的下一步。提示写明目标、原因及可行动作，覆盖中英文、窄窗、键盘可达与回焦。对照正式接口、调试请求、用例、全局变量和参数、环境变量和模块基础 URL、工作流、数据集和套件的真实保存入口，也要覆盖已有缓存里的非活动草稿。
