# apicc 服务端组织与权限设计（含认证演进/水平扩展/执行记录规划）

日期：2026-09-08
状态：口径已获用户逐条拍板（澄清四问 + 追问收敛），规格终审中
范围：服务端组织模型（工作区单例化/分组/项目实体）、角色与账号（平台超管/团队管理员）、连接握手、控制台改造、桌面端适配；内容同步面维持 api.yaml 级。环境/工作流/用例的在线全量镜像与执行记录中心化为**下一轮服务端里程碑**（本文给出规划口径，不实现）。

## 1. 工作区层级：服务 = 单工作区（含多工作区扩展口）

- 服务端首次启动自动创建唯一「默认工作区」（名称固定 `默认工作区`）；`workspaces.name` 加唯一约束。工作区退化为内部实现，客户端无感知。
- **连接握手**：`GET /api/v1/connect`（认证后）→ `{workspaceId, workspaceName, myRole}`。本期实现忽略参数恒返默认工作区；未来扩展 = 请求携带工作区名按名解析（解析不到明确报错）——与「数据库连接 URL 带库名」同构。
- **客户端连接档案** = (服务器地址, 工作区名可选) 二元组：`OnlineServerProfile` 增可选 `workspace` 字段（本期恒空，向后兼容）。未来一个服务器的多个工作区 = 客户端连接列表多行（同地址不同工作区、各自命名），登录态按服务器共享。
- 内容/成员/ACL API 均已按 workspaceId 作用域，零改动。

## 2. 角色与账号

- **平台超级管理员（SUPERADMIN）= 账号管家型**：仅负责账号生命周期——创建账号（用户名+初始密码+昵称）、重置密码、停用/启用、把账号设为默认工作区成员并指定团队角色。**不天然获得内容可见性**（看数据同普通成员一样需被授权）。
- **产生方式**：启动引导创建的首个账号自动 `SUPERADMIN`（不另设超管创建流程）。
- **项目团队管理员**：即现有工作区 OWNER/ADMIN——在其有权限的工作区内保持全能（现状语义，不改）。
- 数据模型：`users` 加 `role`（`USER`/`SUPERADMIN`，默认 USER）与 `disabled` 列；停用 = 拒绝登录 + 吊销全部令牌 + AuthFilter 拦截。
- 守卫方式：沿用既有手写体系（控制器内校验 `user.role`，抛 `ApiException(403)`），不引入 Spring Security 全家桶。

## 3. 认证框架现状与演进路径

- 现状：**非 Spring Security 全家桶**——`spring-security-crypto` 单件（BCrypt-10）+ 自研 `AuthFilter`（`OncePerRequestFilter`，Bearer 不透明令牌 → SHA-256 查 `tokens` 表 → 请求属性注入身份）+ 手写 `PermissionService`/`WorkspaceGuard` 鉴权（403 走 `ApiException`）。
- **本期保持自行实现**：本期需求（超管守卫/停用）为几行守卫，引框架是纯重构。
- **统一认证的本质 = 会话中心**：不透明 Bearer 令牌 + 服务端 `tokens` 会话表（刻意不用 JWT）——未来任何登录方式（密码/OIDC/LDAP/扫码）都汇聚为「往 tokens 表写一条记录」，下游 API/桌面端/控制台零改动；后续新服务模块复用同一 users/tokens 体系，不再各建账号。
- **演进路径**：未来对接企业 IdP 时，新增「凭据换令牌」登录端点（OIDC 回调 → 校验 → 签发本体系令牌）；届时登录入口的可插拔替换再选型（Sa-Token / Spring Security OAuth2 client 二选一均可），账号/权限/会话模型不动。

## 4. 分组与项目实体化（含契约修订）

- 新增 `groups` 表（id、workspace_id、name、created_at）：同工作区内**名称唯一**（管理面与映射需要；客户端本地同名分组推送时按名归并到同一服务端分组，组只是容器）。
- 新增 `projects` 表（id、workspace_id、group_id、name、created_at）：**项目名允许同名**（与客户端同名放开口径一致，内容按项目 id 目录隔离）。
- `project_acl.project_id` 语义改为项目实体 UUID，弃用 `SHA-256(项目路径)`——M3「项目改名换路径致 ACL 失效」缺陷就此消灭。
- 内容树按项目挂载：`file_versions.path` 与内容路径根变为 `<projectId>/...`。
- 契约修订（M3）：`tree.projects` 改由实体表产出（id/name/分组/myRole）；`projectId` = 实体 UUID。桌面端在线链路（OnlineApiEditor/在线树/ACL 视图/迁移向导）适配实体 id；迁移的本地→服务端映射 = 分组按名归并 + 项目同名并存。
- 服务端默认分组：同工作区内不可删改的「默认分组」（与客户端语义一致）。
- 分组/项目管理权限：工作区 ADMIN+（建/改名/删除分组（空才可删）/建项目/改名/移动分组/删除项目（删实体+内容，确认语义））。

## 5. 内容入库（水平扩展前置改造）

- 内容全部为文本（yaml/md，KB 量级）→ 入库：`file_versions` 扩 `content` 列，一行 = 一路径的元数据+字节，同表同事务（乐观并发 `UPDATE ... WHERE version=?` 直接罩住内容）。
- 收益：元数据与字节同源（消灭「元数据在库、内容在盘」分裂）；备份=DB 备份单一故事；compose/k8s 不再需要内容卷；换 PostgreSQL 后服务端容器完全无状态。
- 磁盘 `server-data/workspaces` 内容树退役；`ContentService` 保持唯一 IO 边界（为远期大文件/二进制外部存储预留替换点，API 不动）。

## 6. 控制台（admin-web）改造

- 新增「用户管理」页（仅 SUPERADMIN 可见）：账号清单/创建/重置密码/停用启用/入区定角色。
- 工作区页简化为「工作区概览」（唯一空间 + 分组管理 + 成员入口）；分组管理 = 建/改名/删除/列表。
- 「项目 ACL」页项目清单改实体表来源，支持按分组过滤。
- `/me` 返回 role；前端按角色显隐超管入口。团队管理员页面（成员管理）不变。

## 7. 桌面端连接适配

- 连接 = 握手解析默认工作区，直接进入该服务的分组/项目树；主页服务器视图不再列「空间清单」（单工作区下无清单可列）。
- 旧在线档案 localStorage 向后兼容（新字段可选）。
- 迁移向导目标从「工作区」语义收敛为「服务器」（默认工作区），分组按名归并。

## 9. 认证演进 / 水平扩展 / 执行记录（规划口径，下轮实现）

### 9.1 认证演进
见第 3 节：会话中心架构保证「统一认证 = 加法不是重写」；OIDC/LDAP 对接时新增凭据换令牌端点，框架选型（Sa-Token / Spring Security OAuth2 client）届时按对接对象定。

### 9.2 水平扩展
- 当前阻碍：H2 文件库、内容在本地盘（第 5 节入库后消除）、JVM 内运行态（压测活动句柄）。
- 阶段 0（本轮纪律）：实体全入库、内容入库、启动引导幂等（唯一约束+冲突忽略）、schema 保持可移植 SQL 子集、内容 IO 收口 ContentService。
- 阶段 1：H2 → PostgreSQL（换 datasource + 一次迁移；CI 加 PG 测试）——**多实例的全部剩余工作**。
- 阶段 2：多副本 RollingUpdate（DB 令牌无粘滞需求；授权查库无缓存失效）；k8s 清单改副本数即可；后台清扫类任务用 DB 锁/选主防重复。
- 远期预案：大文件/二进制附件 → 按文件种类引入外部存储；读写分离/CDN 不做。
- 对象存储抽象（执行记录归档用，见 9.3）：`BlobStore` 接口（put/get/delete/list/流式读写），本地磁盘默认实现 + S3 兼容适配器（覆盖 S3/MinIO/OSS/COS），配置驱动可换供应商。

### 9.3 执行记录与海量样本
- **引擎侧（流式三分支，内存恒定）**：①增量聚合器（t-digest/直方图+计数器）产出分位数/状态分布/错误分类；②失败定向捕获——失败样本带响应快照（状态/头/体截断 4KB/耗时/用例关联），**错误指纹去重**（状态+错误分类+体前缀哈希，同形态仅存前 N 条+计数）+ 每轮总量上限（默认 50 条，可配，压缩内嵌报告）——失败风暴下入库量与失败次数无关；③**全量样本流式写轮次归档**（gzip JSONL，一行一请求：时间戳/状态/耗时/用例/断言摘要；失败行附响应快照；成功行不含响应体）。
- **存储分层**：热 = 报告聚合行 + 有界失败快照（DB/报告内）；温冷 = 全量样本归档文件入 BlobStore，报告行存指针，**可供下载**。
- **归档查看器**（桌面端）：流式逐行解压解析 + 虚拟化分页 + 过滤下推（状态/耗时区间/错误指纹/用例）+ 摘要条；绝不全量载入内存（大量请求展示不卡死）。本地与服务端下载的归档同一查看器。
- **保留与清理**：归档保留期可配（N 天/N 轮）；定时清扫 + 管理员手动清理（DB 锁防多实例重复执行）。
- **使用约定**：业务 code 差异靠用例断言转成失败（带响应快照被捕获）；无断言的 200 在归档中仅元数据行（无响应体）。
- **明确不做**：样本逐条入主库（写入吞吐/膨胀不可接受，分析型负载与主库分离）。
