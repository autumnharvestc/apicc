# 项目页签栏与工作区会话化（跨工作区切换）设计

日期：2026-09-09
状态：已获用户逐节确认（2026-09-09），规格终审中
前置：服务端组织模型计划 A/B 已交付（main @ f3d4430）；服务端零改动

## 背景

用户实测（2026-09-09）：打开在线工作区导致本地工作区「记录被挤没」，且无法跨工作区切换已打开的项目。根因有二：①启动恢复为单一 lastWorkspace 槽（在线打开覆盖本地记录）；②工作区状态为单例——打开另一工作区即清场重开（`activeProjectId`/侧树/编辑器/环境选中态全为全局单例）。用户明确诉求：**跨工作区切换打开的项目**，各工作区状态独立保留（含编辑器草稿——用户裁定选项 C「草稿驻留」）。

## 1. 并存形态：本地 1 + 在线 N（多本地延后）

- **本地工作区**：同时最多 1 个打开（本地目录磁盘并发、主进程 session 单例不动——多本地目录并存无诉求证据且需主进程会话表化 + IPC 全量路由改造，等真实场景再立项）。
- **在线工作区**：N 个并存驻留——主进程 online session 表化（`Map<workspaceId, {树缓存, 编辑缓冲}>` + 活跃指针），服务端乐观并发天然支持 N 桌面会话。
- **留门**：渲染层会话状态键控用工作区身份 key（本地=目录路径，在线=workspaceId），未来扩多本地时 store 结构不再动，仅扩主进程。

## 2. 项目页签栏（核心交互）

- **页签 = 项目**（非接口；接口级页签留待后续，落位接口编辑区顶部）。页签跨本地/在线：每签 `{ tabId, workspaceRef, projectId, projectName, workspaceName }`，`workspaceRef = {kind:"local", dir} | {kind:"online", workspaceId}`；激活签 id 单列。
- **工作区驻留语义**：活跃工作区 = 激活签的 workspaceRef；同一 workspaceRef 可挂多签（同项目一签，不同项目各签——重复打开已打开项目不另成签，只激活既有签）。
- **顶栏横向页签条**：位置取顶栏第二行（或工作区名右侧横向区域，实现计划定）；项目名 + 关闭 `×`；激活签高亮；页签多时横向滚动 + 两侧低对比箭头（仅溢出时出现）；`×` 关闭当前签（有未保存修改时弹确认，见 §3/§4）。`v-for :key` 防 path 碰撞（拼 index）。
- **点签 = 切换**：项目所在工作区自动激活（在线签激活前先 token 验证——失效走既有 resume/重登链路，不静默打开）；**工作区不再是显式切换对象**，用户感知只有项目。
- **持久化**：页签集合 + 激活签记 localStorage（workspaceRef + projectId 列表）；启动恢复按签重建（本地重开目录、在线 resume 后重开会话并 token 验证；失败的签标记离线态不可激活）。
- 主页左栏点项目卡片：已打开 → 激活其签；未打开 → 成签（自动连带打开工作区，在线则 token 验证+开会话）。

## 3. 编辑器会话表化（草稿驻留，用户裁定 C）

- `editor` store 从单会话重构为会话表：`Map<apiId, {api, snapshot, envs}>`（本地与在线 apiId 全局唯一免前缀）；激活签切换时编辑器**换入换出对应会话**（内存操作毫秒级）；dirty 判定按各会话自己的 snapshot。
- 切签不再弹 dirty 确认——**草稿天然驻留**（覆盖此前「dirty 确认后切换」的交互，用户裁定草稿优先）。
- `debug`（发送结果/环境选中态）随签驻留；`workflowDesign` 已是按 workflowId 的会话表，仅扩工作区维度核对。
- **草稿驻留的边界 = 签存续期间（用户裁定 2026-09-09 修正）**：切签免确认、草稿驻留；**关签是项目关闭**——该项目后台一并关闭，编辑器会话表中该项目的会话（草稿）随之驱逐。故关签有未保存修改时**弹确认**（提示将丢弃的草稿，确认才关），无未保存修改直接关。

## 4. 生命周期

- **成签**：主页点项目卡片 / 页签栏「打开新工作区」入口走既有流程。
- **关闭签**：`×` → 项目关闭（编辑器会话驱逐、草稿丢弃；有未保存修改先弹确认）。某工作区的全部签被关闭 → 该工作区转入后台驻留（本地会话保留、在线会话保留在表中），可经主页或页签栏「打开新工作区」再激活。
- **重启恢复**：按持久化签重建（在线 resume 优先验证）。草稿不落盘，关闭/退出确认后即丢弃，恢复的是签结构不是草稿。
- **退出程序**：任一编辑器会话有未保存修改 → 退出前确认（列出有草稿的项目），确认后才退；无未保存修改直接退。
- **工作区级关闭**（退出在线工作区按钮）：确认弹窗列出受影响项目数 → 关会话出表（草稿随会话丢弃）→ 其签全部移除；本地工作区同理但暂无入口（预留）。

## 5. 服务端

零改动（在线会话表化在桌面主进程；服务端乐观并发天然支持 N 会话）。仅「激活在线项目签时 token 验证」复用既有 `/api/v1/me`。

## 6. 测试口径

- store：签注册表 CRUD/持久化重建/激活切换/在线 token 失效拦截；editor 会话表驻留与 dirty 隔离（切签草稿保留、互不污染）；关签确认分支（有 dirty 弹确认且确认后会话驱逐、无 dirty 直关）；退出程序 dirty 拦截。
- 组件：顶栏页签栏渲染（滚动箭头/激活高亮/关闭钮）、主页卡片成签。
- 真机：本地+在线各开两项目 → 交叉切换（草稿驻留断言）→ 重启恢复 → 在线 token 失效拦截。

## 7. 明确不做（本轮）

接口级页签（后续，落位接口编辑区顶部）；本地多工作区并存；工作区级关闭后的状态落盘（内存驻留即可，重启走签重建）。
