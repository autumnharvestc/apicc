比较过三条路线：

1. **推荐：复用现有内核，分三个可验证单元交付。** 请求标签/自由请求、网络配置、OAuth2 工具按依赖顺序实施；公开接口契约不承载本机代理路径和授权会话。改动集中，先得到实际可用能力。
2. 一次性改成通用资产标签系统、完整 OAuth2 契约类型和跨端网络配置资产。长期扩展空间大，但会把 F3/F7 资产和 SDK 改造提前，增加解析器、克隆、导入导出的联动面，不适合本轮赶进度。
3. 桌面单独发请求。实现局部 UI 快，但会与 CLI、集合、流程、压测产生第二套传输、凭据、历史语义，不采用。

这是方案选择，不是安全专项改名。OAuth2/代理/TLS 是正常客户端功能；真实凭据仅由用户显式配置，验证使用自建本地服务和合成值，不访问第三方真实账户。

## 4. B1：顶栏导航、请求标签与自由请求

### 4.0 主页/项目统一标签及顶栏布局

用户截图作为“主页与项目在同一标签序列”的交互参考，不照搬其品牌、图标或整套界面。本节只优化应用顶栏，不自定义或改造系统原生菜单/窗口控制。

**页面状态：** `selectedPage = home | project(tabId)` 是当前页面和标签高亮的唯一来源；后台仍驻留的项目上下文单独记录为 contextTabId，不能拿后台上下文当当前页面。既有 activeTabId/activeTab 读取改为导航派生值，项目归属、在线/本地上下文切换和工作流草稿判断使用明确的上下文引用，不继续依赖两份独立可写的 view/home 与活跃项目标记碰巧同步。

- 主页恒为第一个、不可关闭、不可移动的标签；即使没有项目也存在。它不伪装成项目，不进入项目 Session、dirty 聚合或项目数量统计；持久化继续只存项目清单和活动索引，主页对应 activeIndex=null，不造假的 workspaceRef。
- 点主页只改变导航，不关闭项目、不驱逐草稿、不取消项目请求、不重置所选环境。项目/请求草稿与在途结果仍属原项目；主页没有自由请求发送入口。
- 从主页点击唯一已开项目，必须切回项目，无需先点另一个项目、重复打开或重载工作区；有两个项目时也沿同一入口。若项目上下文已就绪，可直接恢复其原栏目/请求签/视图状态，不因“上下文已经激活”忽略页面选择。
- 导航意图递增 epoch。点主页后旧异步项目激活不得将页面拖回；激活失败/离线重试保留当前页面并显示错误，不提前画成功高亮。
- 主页不等于项目关闭。工作流草稿仍按真实 retained context 判断：A→主页→B 不可绕过既有离开 A 的工作流草稿确认；取消切换应停在主页且保留 A 草稿。A→主页→A 不触发无意义的丢弃确认。
- 在主页关闭后台项目仍停在主页；在项目页关闭当前项目沿现有邻签规则，最后一个项目关闭后回主页。启动恢复若 activeIndex=null 则停在主页，不被后台 Session 恢复强行切走；已保存活动项目且恢复成功时可进入该项目。在线连接/工作区浏览入口继续可用，未选项目时不开放项目级请求操作。

**推荐布局：** 顶栏采用一条紧凑横向导航/工具行，左侧为“主页｜项目 A ×｜项目 B × …”同一标签条，右侧为压缩的工作区/连接状态与工具。主页固定可见，项目区占可伸缩宽度、溢出横向滚动；长名称省略并可查看完整归属，必要时以工作区/分组提示区分同名项目。请求标签仍在项目编辑区内，不混到这一排。

工具区保留在线连接/状态、设置、语言/主题和现有工作区操作的可达性；低频动作收进更多/设置菜单，旧项目下拉改为“打开/查找项目”的次级入口，不与活动标签并列展示第二份选中状态。工作区长名称不把主页挤出屏幕。窄窗口优先压缩辅助文字/收进更多菜单，标签区滚动，不让整页横向溢出或把顶栏挤到侧面；顶部高度不随项目数量增长。组件样式限定作用域，不新增泛用 header/nav 规则污染工作流画布。

主页和项目共享 tablist 的视觉和键盘语义，当前项 aria-selected/高亮一致，关闭按钮不触发标签激活；可用键盘切标签和操作关闭，主页没有关闭按钮。中文/英文、明暗主题、正常/窄窗口及打开工作流后都检查布局。截图精确像素复刻不是验收条件，统一层级、可达性和不回归才是。

### 4.1 身份与上下文

保留本地同时一个工作区的边界。请求标签属于 root＋完整 ProjectLocator；正式接口以完整 ApiLocator 去重，自由请求使用新的 UUID draftId。打开已有接口激活其唯一请求标签；自由请求可复制为新的独立 draftId，不支持同一正式接口的两个竞争编辑副本。

自由请求属于当前已激活的本地项目工作区，不提供项目选择器、跨项目发送或主页发送。点击“新建请求”无需先建模块/文件夹/接口/用例，即使项目没有任何模块也可输入完整 URL 发送。新建请求默认 HTTP，同时复用已有 WebSocket/SOAP 请求形状与现有能力，不扩展其传输语义。

新增独立的 `mode: free` 调用：project 为完整 ProjectLocator，另有 draftId、request、parameters、fields、environmentId、settings；project 由原请求签的当前项目上下文捕获，不让用户另选目标。既有 request/case 调用保留，不把不存在的 apiId/collectionId 填进正式 locator。主进程验证真实 root、项目及环境存在性；启动后切项目不改变原调用归属。

输入完整 URL 时按现有契约约束拆分 baseUrl/path/query，保留有序重复 Query 与有效编码，不更改 F1 地址拼接规则。自由请求消费当前项目变量、所选环境的普通变量、项目全局参数、项目资产引用、凭据和网络配置；它没有模块继承链，不隐式选第一个模块、不使用环境的模块 baseUrls 映射或自动运行任意模块/文件夹前后置操作。完整 URL 或其项目/环境模板必须提供可解析地址，不能借临时模块 ID 猜基础地址。普通参数优先级沿现有请求物化规则，未提供的模块变量不得从其他模块补齐。

执行准备只在本次不可变快照里构造临时模块/API/用例并委托同一 CollectionRunner；临时模块变量为空、操作列表为空，不复制真实模块的祖先操作。临时身份不进入正式文件、树、索引、导出或公开身份摘要。来源标为 free，只有 sourceProjectRevision 和 draftRevision，不能把临时 API hash 命名为 sourceApiRevision。正式接口的祖先操作和已批准本地脚本行为不变；本节不是跳过正式接口脚本后报成功。

### 4.2 标签状态与生命周期

每签独立保存：请求/正式资产草稿、协议草稿、所选环境和用例、请求设置、普通参数、历史恢复字段、dirty、generation、runId/starting/sending/error/result，以及编辑/响应面板选择、滚动位置。

- 切签不保存、不丢草稿、不取消正在执行的请求；不同标签可以同时发送，同签最多一个在途调用，不引入额外全局并发限制。
- 迟到启动确认、结果、取消响应、保存响应只作用于原 root＋签身份＋generation；新开同源标签不能接收旧签回调。
- 关签时，dirty 或在途请求合并为一次确认；确认后取消其请求、丢弃草稿、驱逐状态，取消关闭则所有状态不变。项目关闭和程序正常退出聚合该检查，不能先删状态再确认。
- 草稿及请求标签清单仅内存驻留，重启仍按既有项目标签恢复，不恢复未保存请求；明确提示边界，不新增 localStorage 请求正文。正常退出有丢弃提示；意外关机恢复不属于本轮。
- 请求标签在项目编辑区顶部；主页/项目统一标签条归应用顶栏，顶栏保持在顶部。回主页不显示或发送项目请求。中文/英文、亮/暗主题和窄窗口有基本手工检查。

### 4.3 保存、历史和重放

正式接口沿 F2a 保存契约/保存用例的修订检查，不自动保存后发送。

自由请求“保存为接口”此时才显式选择当前项目内目标模块/文件夹和名称，在同一 Session 写事务中新建完整 ApiAsset；不能先建空 API、再第二次保存正文。没有模块时由用户显式新建模块后再保存，这不妨碍此前的自由发送。文件失败、只读和修订冲突不创建残留空接口，保留自由草稿。成功后转换成正式接口标签，后续才可保存为该接口的用例；不自动修改别的接口、跨项目保存或覆盖同名资产。转换后按正式接口的模块继承语义执行，界面提示后续运行会使用目标模块配置，不假称转换前后继承上下文完全相同。

自由历史来源记录 project＋draftId，root 归属继续由宿主私有 ownerHash 校验，不能靠渲染器传入路径取得归属。恢复只在该记录所属的当前项目内新建自由请求标签，不依赖旧 draftId 的内存会话；同一历史的“恢复”每次均可新建签。来自其他项目的记录可查看，但执行/恢复须先由用户切到其所属项目，不在历史按钮内暗中借用或切换项目。项目不可用时保留只读历史；删除或重命名任何真实模块不影响无模块自由历史的归属。历史恢复和重放仍是使用当前文件/当前绑定重新执行，不承诺逐字节原样重放。

新写历史 `formatVersion: 2`，v1 读取转换只发生在内存，历史记录原件不覆写；有效旧 sidecar 不为格式升级而覆写，失效或缺失的摘要允许按既有缓存规则重建，但不改历史记录。结果来源采用显式 asset/free 联合，v1 结果可以兼容读入；未知版本诊断不放宽。列表保留所有既有筛选，并新增来源类别；free 不命中“当前接口”筛选，能进入所属项目/全部历史。保留计数/大小/脱敏预算及不足字段 needsInput。

## 5. B2：本机网络配置

### 5.1 存储、选择与快照

新增私有 `NetworkProfileStore` 端口及文件适配器，默认根为 `join(homedir(), '.apicc', 'private', 'network', 'v1')`。桌面和 CLI 共用；验证必须注入临时根。配置按 canonical root＋完整 ProjectLocator、可选 environmentId 保存绑定，不依赖 cwd，不在共享项目 YAML 存本机证书路径或代理秘密。

配置包含命名 profile 和精确 origin 的 TLS 绑定；每个 scope 的默认代理可选择 direct 或显式代理。选择优先级：本次宿主显式选择 > 当前环境绑定 > 项目绑定 > direct＋运行时默认 TLS。环境绑定不存在才继承，显式 direct 不回退到项目代理。UI 明示作用范围及来源，不猜生产/测试环境。首批不自动读取 HTTP_PROXY/HTTPS_PROXY/NO_PROXY、系统/PAC 配置。

配置原文不含密码、私钥、PEM 内容：代理密码、客户端私钥 PEM、私钥口令保存在现有 SecretStore；配置只存 SecretRef。用户选择私钥文件后，通过宿主读取并加密保存，随后运行不依赖原私钥文件。CA 和公开证书链为路径引用，不自动导入/复制进工作区。凭据/配置部分成功沿 F1 口径明确显示，不宣称跨介质原子事务。

每次运行开始固定网络 profile 修订、公开证书文件内容及所需凭据；文件准备设每文件 1 MiB、每次证书总量 4 MiB 的上限，先检查再按实际读取累计。取消/缺文件/非法 PEM/未绑定引用在业务发包前明确失败，不改用其他文件或降级直连。只读取被当前运行选中的配置，不枚举用户证书/凭据。

### 5.2 HTTP 代理与 TLS

- 支持显式 HTTP/HTTPS 代理到 HTTP/HTTPS 业务目标；代理认证首批 Basic。地址禁止 URL userinfo，密码走 SecretRef，Proxy-Authorization 仅交给代理层。
- HTTP 目标使用转发，HTTPS 目标使用 CONNECT，由锁定 undici ProxyAgent 的实现承担；不自己写隧道协议。HTTPS 代理信任和目标信任是两份配置，不混用 requestTls/proxyTls。
- 自定义 CA 首批“追加当前运行时默认 CA”模式；不全局修改系统信任或 NODE_TLS_REJECT_UNAUTHORIZED。证书链和主机名校验默认开启；允许用户对精确目标 profile 显式关闭校验，界面持续显示醒目警告，不能影响其他目标。
- mTLS 首批 PEM 公开证书链＋SecretRef 私钥，支持加密 PEM 的口令。客户端证书绑定精确 scheme/host/port；重定向到其他 origin 不沿用原 mTLS 身份，只有新 origin 自身绑定才可使用。
- HTTP 专属配置不能对 WS/SOAP 悄悄无效：选择不支持的配置时明确 config 失败和说明，本轮不宣称这两个协议已获得新代理/TLS 能力。
- 连接池键包含有效 timeout、代理/目标 TLS 指纹、凭据版本及连接模式，不用私钥或密码字符串作公开 key/日志。准备后文件变化不能改变已有运行；新运行再捕获。

传输仅由宿主装配到 `HttpRuntimeOptions`，纯 JSON RequestSettings 不存 Agent、PEM、文件句柄或解密值。各入口的执行快照不包含这些材料。

### 5.3 所有入口、计时与旧 Minor

桌面调试、集合、流程、压测和 CLI 均在运行准备时消费相同网络绑定；插件自定义协议不能自动获得秘密，未支持能力明确拒绝。准备耗时不伪装为服务端请求耗时。压测运行准备一次，各 VU 使用运行绑定，不逐次读配置文件/系统库，不运行中切配置，不新增分布式职责。

- M1：每个 ManagedProtocolClient 最多缓存 16 个无在途租用的闲置 dispatcher；活跃项不强制逐出，释放后超额关闭，client.close 回收全部。不改变请求并发上限，不增加 OOM/FD 专项。
- M2：设置覆盖不适用协议时，拒绝信息包含完整 CaseLocator，保留“不写入”结果。
- M3：跨 origin 剥离认证后，实际请求来源标签同步移除对应 auth 来源，不改正确的剥离行为。

M2 在 B1 请求保存链处理，M1/M3 在 B2 网络链处理。已知 terminal result 长期保留容量和其他 F1/F2a 非阻断项继续记账，不借本阶段无关重构全部清理。

## 6. B3：OAuth2 获取/刷新工具

### 6.1 产品取舍

本轮以本地 **OAuth2 工具获取/刷新 Bearer** 交付，不引入新的 `AuthBinding.kind`。正式请求仍保存 `{ kind: bearer, token: SecretRef }`；OAuth2 profile 保存于宿主私有配置，UI 在 Bearer 旁展示“由 OAuth2 管理”、获取/刷新/解除关联。None/Basic/API Key 的既有行为不变。

这使拿到的 token 可立即用于现有调试/集合/流程/压测/CLI，不必为了获取 token 改写全部契约消费者。完整 OAuth2 安全方案元数据的共享、导入导出、组件编辑不在本阶段标完成；F3 接入这些信息时须另行设计，而不能导出成“已完整保留 OAuth2 配置”。此取舍已随更新后的整阶段规格集中获批。

### 6.2 流程与本机边界

支持客户端凭据 `client_credentials`、授权码＋PKCE S256，以及 refresh_token。配置含 profileId、作用域、绑定环境、authorization/token endpoint、clientId、scope、客户端认证方式 none/client_secret_basic/client_secret_post、目标 Bearer ref。客户端凭据流必须选择 secret 认证；授权码可选公共客户端或用户提供的客户端秘密，不内置产品 client secret。

交互授权仅由用户点击获取启动：系统默认浏览器＋本机 loopback 回调；随机 state、PKCE verifier 仅在该次主进程会话内，绑定配置修订和原 owner。回调仅监听 loopback，可选 IPv4/IPv6、随机端口或用户明确指定固定端口，路径固定为 `/oauth/callback`；同时校验本次绑定的 host/port/path、state、返回 code/error 的唯一性，不作为通用转发器。会话默认 5 分钟超时，成功/取消/超时/owner 销毁均关闭监听。打开 profile/项目/历史不会自动弹浏览器。

授权端点及 token endpoint 默认要求 HTTPS；本地自建服务可用明确的 loopback HTTP，普通远程 HTTP 不在本轮支持。token endpoint 不自动跟随重定向；上游 OAuth error 只投影稳定错误码和短说明，不原样回显可能含 token 的正文。token 请求总超时 30 秒、响应体上限 1 MiB；不复用业务 Cookie jar、业务前后脚本或业务 Authorization。

token 换取/刷新用 B2 同一传输配置解析，但使用 token endpoint 自身的 origin 绑定。浏览器授权页面由外部浏览器负责，不能承诺其采用 apicc 的代理/CA。

### 6.3 保存、刷新与执行

access token 保存到既有 Bearer SecretRef；client secret 和 refresh token 分别使用 SecretRef，过期时间、scope、配置指纹及绑定版本等非秘密元数据留本机。profile 按 root＋完整项目＋environmentId 绑定；同一 Bearer ref 不允许同时登记两个不同 profile/环境，以免切环境偷偷替换另一环境的 token。UI 为新 profile 默认创建新 ref，并允许用户显式解除旧关联。

获取成功先保存 access token，再保存 refresh token/元数据；每一步各自反馈，后一步失败不能假称全部已保存或回滚已生效 token。刷新返回新 refresh token 必须替换旧值；保存失败明确要求重新授权，不能循环自动重试。元数据与实际凭据版本不匹配时按配置冲突处理，不能把过期时间套到手工换入的新 token；“改为普通 Bearer”是用户显式动作。

运行准备先解析本次真正使用的 Bearer refs：未关联 OAuth2 的沿原规则；已关联的若有效则固定当前绑定；已到期或 30 秒内到期时，至多刷新一次；无 refresh token 的客户端凭据流可重新获取一次，授权码流须提示用户主动授权。未知过期时间显示未知，不伪造有效期；用户可显式刷新。

同 profile 进程内 single-flight，桌面与 CLI 使用同一私有 profile 写锁；锁忙可取消/超时返回忙，不强抢。普通凭据 UI 修改已关联 ref 时须显式解除关联或通过同一协调端口更新；记录版本冲突，不静默覆盖。已启动运行始终固定 token，运行中不自动刷新、不因 401 重放业务请求、不在每个 VU 访问授权端点。压测准备显示有效期风险，过期导致的真实失败照实计入报告，不假装持续授权；长时 token 更新归后续能力。

CLI 支持 profile 列表/状态、显式获取客户端凭据/刷新/解除关联；不在无交互运行中自动打开浏览器。授权码首次获取由桌面工具完成；此后 CLI 可独立使用保存的 token 和 refresh token，不依赖桌面常驻。真实第三方身份提供方不作为阶段自动测试前置。

### 6.4 输出与权限

沿用 test-auto 体验；不新增主密码、反复解锁或生产环境识别。秘密保存/使用仍不意味着允许进入日志、历史、复制结果、分享、导出或 AI 输入。OAuth UI 只显示状态/时间/遮罩，不回传 refresh token、client secret 和完整换取响应；业务 access token 进入普通本地测试逻辑的可见性沿 F1 §8.3，不虚称脚本不可读。

OAuth profile 和本机传输配置不随工作区分享/克隆；工作区复制后该机缺少配置/凭据时明确未绑定，不自动读取源机内容。解除 profile 不自动撤销远程授权，也不自动删除仍被请求引用的 access token；另提供明确的本机凭据删除操作，沿 F1 删除失败语义。

## 9. 技术依据与归档入口

已读本机安装的 undici 8.10.1 `types/proxy-agent.d.ts`、`types/connector.d.ts`；其 ProxyAgent 有 requestTls/proxyTls，具体 API 以本机锁定版本为准，不把 main 分支文档当集成验证。

- [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749)：客户端凭据、授权码与 refresh 的标准交换。
- [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252)：原生客户端使用外部浏览器、PKCE 与 loopback 回调。本文的 5 分钟及 UI 行为是产品选择，不是 RFC 强制数值。
- [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)：不采用密码模式/隐式路线；本阶段不声称实现完整身份系统或全部规范认证。
- [Undici ProxyAgent](https://github.com/nodejs/undici/blob/main/docs/docs/api/ProxyAgent.md)：目标与代理 TLS 参数分离，须核对锁定版本。
- [Node TLS](https://nodejs.org/docs/latest-v22.x/api/tls.html)：取得运行时默认 CA 和构建请求级 TLS 配置，不修改全局信任。
- [Electron shell](https://www.electronjs.org/docs/latest/api/shell)：授权页通过宿主打开外部浏览器，不将身份页面嵌入请求编辑器。
