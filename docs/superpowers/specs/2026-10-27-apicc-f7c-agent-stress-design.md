## 1. 目标与范围

在客户端选定的在线项目中，配置已有 Core 压测计划，选择本机或一个已授权代理执行；代理使用现有 Core，不经 Java 或控制网络逐请求调度。客户端关闭后，已开始的代理任务仍可按固定本地期限执行，结果按 F7b 机制补传、查询和下载。

包含：

- 现有 `StressPlan` 的 HTTP 用例、HTTP 工作流目标；常量 VU、常量到达率、分阶段负载；预热、思考时间、节奏、优雅收束、生命周期、数据、阈值和连接模式。
- 同一台代理内的单执行进程或本机多 worker；同一 Core 的安全准入、门禁、时钟映射、数值汇总、私有标记联合脱敏和报告语义。
- 项目内保存/选择计划、本机/代理位置选择、运行/停止/历史、可读中英文报告、既有六项基线比较和离线 HTML 导出。
- 代理资源额度及工作区/项目限制、输入固定、授权、取消、进程树退出、完整性和补传。

不包含：跨代理分布式压测、远程 worker 时钟对齐、生产级性能容量承诺、到达率方案 B、长连接、定时任务、插件自动安装或不受信任脚本。DEF-001 不恢复。F7b 三项低优先级遗留继续见 [backlog](../../backlog.md)；按 2026-10-28 用户决定，统一排在 F7g 完成后处理，不纳入 F7c–F7g，不因接触同一路径自动承诺关闭。

本阶段使用现有计划格式，不把单接口调试、整个套件和压测混为同一个目标类型；套件直接作为压测目标不在现有 Core 范围。旧本地压测入口和历史报告继续可读，不强制迁移。

## 3. 组件与进程边界

```text
客户端项目：计划 / 环境 / 执行位置 / 本次目标确认
       │ 固定快照、材料、计划和执行参数
       ▼
Java 控制：权限、队列、资源预留、启动许可、状态、归档
       │ 长轮询任务与许可（不是逐请求调度）
       ▼
代理主进程：账本 / 总任务槽 / 压测预算 / 子进程监督
       └─ 独占任务执行进程：Core 计划协调器
              ├─ workerCount=1：本进程运行 VU，不再派生 worker
              └─ workerCount=N>1：派生 N 个本机 worker，使用 Core 私有 IPC
```

这里的进程数不含常驻代理主进程。定义 `processUnits = workerCount === 1 ? 1 : workerCount + 1`。一个工作流的节点、迭代和请求不各开进程。无论有无脚本，压测均不进入 F7b 共享调试 worker。

本机在线压测使用相同准备/调用边界，但拥有本机的生命周期和预算，不占代理额度，不承诺客户端关闭后继续。多 worker 的 Node 入口按实际运行身份装配；Windows Electron 本机路径若需以 Node 模式启动，必须验证真实环境和退出，不能只凭代理 Node 通过推定 Electron 已通过。

### 3.1 资源预留

每个压测任务的固定预留向量为：一个普通任务槽、一个压测任务槽、`processUnits`、`plan.maxVus`、编译后的请求并发、有效最大 RPS，以及 `processUnits × stressMetricMemoryBytes`。worker 数还必须不大于 `plan.maxVus`。本阶段代理压测的有效最大 RPS 始终有限，由项目/管理员上限补足未填写的运行值。

- Java 在领取事务内依既有代理锁/项目锁顺序，核验并原子保存预留；agent 在拉材料/创建任务进程前同样核验。不能信任客户端自报剩余资源，也不能仅靠长轮询的 availableSlots 通过。
- 单任务需求超过配置总容量：提交/准入拒绝，目标请求为零。需求合法但当前被其他任务占用：留队，显示资源等待原因，不降 VU、改速率、换代理或重跑。等待中的大任务不应挡住可准入的普通调试；不另开发通用优先级调度器。
- 多项目共享代理按代理总额求和，不能各自得到完整节点额度。RPS 通过各任务固定上限之和预留，不让后端或代理主进程成为逐请求远程令牌服务。
- 已准入、未确认退出的任务持续占资源；取消请求、超时通知、IPC 断开、报告开始上传均不等于释放。全部任务执行进程及 worker 确认退出后才允许 `executionReleased=true`。
- 执行资源与待上传报告字节的生命周期分开。报告归档 ACK 前仍占缓存预算；重连只补传原字节，不重新请求目标。
- 配置降额不强杀在途任务；阻止新准入并显示超额排空状态。领取后到启动许可之间的降额按既有持久 start-rejected 路径收束，不让任务永远占槽。
- 代理进程/容器重启从服务端预留和本机账本恢复占用及待传结果，不恢复业务执行。老进程退出不明时，拒绝新准入，不因重启把占用清零。

CPU、RSS 与连接数是观测，不是上述数值预算自动提供的硬隔离。沿用部署层 CPU/内存限额和子进程 heap；不把数值预算总和说成整机内存上限。默认仅一个压测任务，管理员提高并发后，报告提示其他任务可能造成竞争，不承诺互不影响。

## 4. 配置清单与生效规则

新增项按下表建议冻结。Web 由对应级别管理员维护额度；客户端只维护计划和本次运行，不重复建设节点管理界面。原有超时、脚本模式/时限、任务总槽、输入/输出/保留和刷新配置继续复用。

| 字段 | 建议默认 | 合法范围 / 单位 | 入口与用途 |
| --- | --- | --- | --- |
| `agent.maxConcurrentStressJobs` | 1 | 0 到 `maxConcurrentJobs`，项；0 表示不接新压测 | 平台节点；全代理并发压测数 |
| `agent.maxStressProcesses` | 5 | 正安全整数，进程 | 平台节点；协调器和 worker 合计，不含主进程 |
| `agent.maxStressVus` | 100 | 1–1000，VU | 平台节点；所有已预留压测合计 |
| `agent.maxStressRequestConcurrency` | 100 | 1–1000，请求 | 平台节点；所有压测有效并发预留合计 |
| `agent.maxStressRps` | 1000 | 正有限数，请求/秒 | 平台节点；所有压测有效 RPS 上限合计 |
| `agent.maxStressMetricMemoryBytes` | 335544320 | 正安全整数，字节 | 平台节点；所有压测数值预算合计，默认 320 MiB |
| `policy.maxStressWorkers` | 4 | 正整数；运行时与节点进程容量及maxVus取交集 | 部署默认 / 工作区 / 项目；每任务 worker 数上限 |
| `policy.maxStressVus` | 1000 | 1–1000，VU | 同上；每任务容量上限；选中节点默认再限制为100 |
| `policy.maxStressRequestConcurrency` | 1000 | 1–1000，请求 | 同上；每任务真实请求并发上限；选中节点默认再限制为100 |
| `policy.maxStressRps` | 1000 | 正有限数，请求/秒 | 同上；每任务 RPS 上限 |
| `policy.stressMetricMemoryBytes` | 67108864 | 1048576–67108864，字节/执行进程 | 同上；数值统计预算，默认 64 MiB；上界为本阶段实现边界 |
| `policy.stressEvidenceMaxSamples` | 20 | 1–20，条/最终报告 | 同上；整任务失败样本，不是每 worker 可公开 20 条 |
| `agent.stressProgressIntervalMs` | 1000 | 250–60000，毫秒 | 平台节点；累计快照发布间隔，终态可立即发布 |
| `run.stress.workerCount` | 1 | 正整数，受上述额度和 maxVus 约束 | 客户端本次运行；不写进纯 Core 负载计划 |
| `run.stress.confirmedTargetOrigins` | 空数组 | 规范 HTTP(S) origin 集合 | 客户端本次确认，绑定本次 intent、位置、环境和快照，不保存为长期信任 |

VU 和请求并发 1000、阶段数 32、测量计划七天等 Core 边界不因配置可调而扩大；默认最大任务期限仍受现有 24 小时管理员上限控制。没有配置项可以绕过权限、脚本批准、目标安全或完整性要求。

继承使用现有 effective config 的来源与版本表达；各层只收紧继承上限，最终还与选定节点可用总容量核对。继承策略的上限可以高于某一节点容量，选择该节点时显示交集；不能因此拒绝保存一个本来能运行低负载任务的节点配置。例如节点进程上限3、策略worker上限4时，有效worker上限2，而worker=1仍可运行。新增配置必须在 TS 与 Java 采用同一默认/合法范围，并纳入保存冲突、已保存/已应用和来源展示。旧的已保存配置补新增默认项，不要求手工重录。

计划的显式值超额则拒绝，不静默裁剪；未填的请求上限可由管理员补足，界面同时展示请求值、有效值及来源。到达率是“逻辑迭代启动/秒”，不等于请求 RPS，尤其不能用节点 RPS 偷换工作流到达率。

证据正文/值/用例/整报告字节沿用 `bodyPreviewBytes`、`valuePreviewBytes`、`caseEvidenceBytes`、`reportBytes`、`workflowMetadataBytes`。Core 编译器接收可选运行限制和证据预算，默认调用保留旧行为；固定 histogram、时间桶和节点维度不被变成任意无界选项。各 worker 单独持有数值预算，代理按进程数预留其总和；最终公开报告与私有标记通道仍受既有总上限约束。

开始前固定完整配置、数据、脚本和材料版本，并在启动许可重核当前授权/额度。父任务期限包含准备，不通过另起 worker 重置；预热、测量和优雅收束的明确时长之和超过任务期限则拒绝。生命周期剩余时长不可预知，实际到期保留 timed-out/未完成事实，不能保证一定跑完 teardown。worker 的生存期限跟随任务剩余期限及既有取消收束预算，不复制 CLI 默认 300 秒硬截止。

## 5. 契约与共用宿主

### 5.1 公共边界

- `TaskTargetSchema` 增加 `{ kind: "stress", plan: StressPlanSchema }`。保存计划仍是项目资产；提交的是固定解析后的计划，不允许代理运行时重读“最新计划”。外层环境与 `plan.environmentId` 必须相同或仅存在一个，冲突拒绝。
- `RunConfigSchema` 增加上述 `stress` 配置，只允许用于 stress 目标；`debugSessionId` 对压测无效。提交、固定 inputs、digest、许可及代理重新准备均绑定同一计划、运行配置、有效限制和材料。
- 新能力为 `task:stress`；多 worker 另要求 `stress:local-workers-v1`，HTTP 能力和实际脚本能力仍逐项要求。补齐 TS 能力清单、构建清单和 Java allowed capabilities，不仅在 UI 增加选项。
- 结果扩展为 `InvocationOutput` 的 `kind: "stress"`、`result: StressReportV2`。外层在线报告保存 `StressExecutionMetadata`：位置、代理身份/名称、worker 数、进程预算、资源请求/实际值、Core/运行身份、准备/执行/上传状态及争用提示。Core 报告不伪造普通用例 totals，不在任意 JSON summary 中隐藏新增语义。
- 增加 `kind: "stress-progress"` 累计消息：`sequence`、Core `StressProgress`、真实请求计数及完整性提示。复用持久消息/去重，不为每个 HTTP 请求上送事件；状态查询和进度不查询报告 BLOB。不得把“进度暂未更新”当作目标请求停止。
- Java 仍只验证结构、权限、预算和状态；从 TS 生成并严格校验输入 JSON Schema。`StressPlanSchema` 自定义 refinement 的 JSON 传输元数据须显式描述；不删 refinement、不导出 any/unknown 来让生成通过。语义编译继续由 Core 承担。

继续使用现有长轮询/启动许可/归档协议，不开发第二条压测控制链。新增 v1 目标靠能力和实际构建身份准入；控制端、客户端和代理按本阶段配套升级。旧代理明确显示不兼容、不可选，不向它发无法解析的新配置或压测；不承诺任意新旧版本滚动混用。历史普通任务和报告不删除，升级前先排空旧在途任务。

### 5.2 在线计划存储

新增可选 `ContractProject.stressPlans: SavedStressPlan[]`，同时接入 `ContractProjectSchema`、`project.yaml` 文件 Schema 和项目文件编解码；保存时保留完整 id/name/updatedAt/plan，拒绝重复 id。不提供字段的旧项目保持可读，空集合不强制重写旧项目；本机现有 repository 行为不改，不自动迁移其私有目录。

在线计划随项目资产的 expectedVersion 原子保存，删除只影响明确选中的计划，不能因保存整个项目丢弃其他成员的计划。运行固定本次计划和资产版本，后续改名、删除或修改不改变已领取任务。发布本地项目不会静默附带 `.apicc` 中的计划；要带入在线项目，用户在项目入口显式选择并保存，现有本地记录保留。

计划快照可以由新客户端正常读取和再次保存；不承诺旧版本客户端能够编辑新增字段，旧版应保留其已有未知结构/只读保护，不通过忽略字段造成覆盖丢失。

### 5.3 固定依赖与脚本

共用准备首先验证在线文件 hash/manifest、生成唯一 snapshot，然后编译目标及 setup、vuSetup、vuTeardown、teardown 的闭包。复用 `compiled.targets` 的请求和数据选择；脚本依赖还覆盖工作流条件、分支、子流程、onError/finally 和模块/目录继承，不能仅扫目标接口。

实际脚本版本映射到 F7b 文件来源与内容摘要，节点模式和项目批准同时成立才可启动；不存在脚本时真正使用 no-script registry，不装一个空引擎。凭据、数据集、附件、网络/TLS 材料和脱敏标记按完整闭包装配一次；仅本机材料不能用于代理，不自动上传、去认证或寻找同名替代。

共用调用使用 Core 原入口和同一 registry 工厂。增加运行级 `requestSettings` 向用例、工作流及生命周期叶请求传递，复用 F7b 已有优先级/适用性校验；不在代理另写超时算法。前后置脚本仍是现有同步 pm API，不扩大脚本能力或隔离承诺。

worker 使用父任务已固定的输入和专有材料，不接受 renderer 的可执行代码、任意路径或 CLI 工作区地址。每个子进程重新核验真实构建和固定输入；私有 IPC 核验 generation / executionId / runId / workerId / scope。派生 worker 继承同一租约/epoch保护；孤儿退出未确认时，代理恢复不能重接任务。

## 6. 控制、时钟、取消与输出

- 到达率继续使用 A 和原策略接缝；协调器在代理本机调度并统一请求门禁，控制网络只传低频进度与最终结果。目标请求耗时不含任务排队、快照传输和报告上传；本机 IPC 调度成本不能冒称不存在，应反映到启动延迟、生成器及负载完整性。
- Node 时钟及可信本机 channel 装配从既有 CLI 宿主提取为可共用模块。只有实际同机 channel 与对应 native clock 获得系统坐标能力；声明一个字符串不等于可信时钟。未知时钟保留 RTT 不确定度和未对齐标记，不把跨机器单调时钟相减。
- 单 worker 调 `runStressPlan`；多 worker 调 `runLocalStressWorkers` / `serveLocalStressWorker`。不得另写百分位平均、各 worker 相加 RPS、独立全局迭代计数或省略 marker union。汇总故障保留不完整原因，不把缺失数据补零或改成功。
- 每 worker、协调器的私有标记联合并重投影后，才可公开富证据。失败屏障中有参与者可能知道未知标记时，抑制富内容；仅保留已确认安全的数值事实和明确限制，不能把未知标记写入错误、stdout、日志或控制进度。
- 取消依既有身份仅作用于本压测；收束 VU、关闭网络资源和所有后代进程。先停止新迭代，再按剩余取消/任务预算尝试 cleanup；任务到期或强制退出后不保证 cleanup 业务请求发生。不能取消相邻普通调试或以整台代理重启作为日常停止。
- 监督进程故障、worker 退出及主进程重启均不自动重试目标请求。保留 started/not-started/uncertain、逻辑结论、请求失败、execution/metrics/load 完整性、归档状态的区别。阈值无违规不等于不完整压测通过，零请求不是成功压测。
- 旧待传结果按其已验证 hash/字节补传，不因重连重新序列化或重取密钥。重试上传不重复业务；报告超过固定总预算走既有明确容量故障，不删掉失败事实来压成 passed。

## 7. 页面、报告与基线

### 7.1 客户端

在线项目工作区增加压测入口，复用 `StressLoadEditor`、计划模型和 `StressReportView`/`StressTrendView`；保存采用项目现有 expectedVersion，不在主页建立项目外发送入口。环境与位置独立；更改位置使本次目标确认失效。`localhost/127.0.0.1` 在代理执行时指代理自身，必须直接提示。

展示计划、有效限制/来源、worker 与实际进程数、代理及能力/应用状态、任务排队与执行/上传状态；容量不足说明缺哪种资源和已占数量，不靠 JSON 展示。停止只作用所选执行身份；项目/账户切换隔离运行上下文，迟到响应不能更新另一个项目。

桌面关闭不影响代理已开始任务；重开从服务端历史恢复查看，不创建新任务。关闭本机运行沿用本机语义并明确提示，不能显示“已交给后端继续”。仅支持本阶段真实可用入口，不提供未实现 B 策略或跨代理选项。

### 7.2 报告和导出

沿用中英文、毫秒及明确时区、短指纹可展开、局部滚动、未采集/不适用/不可计算区别和单桶说明。默认摘要分列逻辑迭代、真实请求/失败、HTTP exchanges、阈值和三类完整性；趋势、阶段、节点、生命周期和失败证据使用可读表格/展开详情，原始数据次级且默认折叠。API 正文本身允许 JSON。

节点 CPU、RSS、event loop 与生成器能力以现有实际观测提供；如只有各进程峰值的最大值，不能标成“同一时刻总 RSS 峰值”。多人共享的争用提示只显示数量/限制，不泄露其他项目名称或任务内容。

基线显式选择已授权报告，执行 `compareStressReports` 的六项指标，不重算它的差异公式。增加外层执行比较：位置、代理、worker 数、Core/运行档位及有效资源差异/缺失时，不标为“相同执行条件下可直接比较”；保留可读差异和原 `environment-definition-not-compared` 限制。旧报告缺执行元数据仍可读，不猜测补齐。

离线 HTML 仍复用 `renderStressHtml`，为已类型化的执行摘要/比较提示增加可选展示参数；Core 不依赖 execution 包，不接受任意 HTML 字符串/脚本作为扩展。在线和导出使用同一安全投影，不能导出一份未经统一脱敏的原始报告。

### 7.3 管理台

扩展已有节点、工作区策略和项目执行设置表单，不另起压测管理后台。节点管理员配置全局容量；工作区/项目管理员只收紧本层上限，客户端成员只能选用。新增字段均展示默认、显式、有效值、来源、单位和保存/应用版本；长表局部滚动，中英文不挤断表头。
