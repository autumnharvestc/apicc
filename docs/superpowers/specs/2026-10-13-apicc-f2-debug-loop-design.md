## 3. 草稿、发送请求、运行用例、保存的语义

### 3.1 草稿

调试草稿属于当前 root + 完整 ApiLocator + editor generation；使用正式 ApiRequest Schema，另带本次请求设置。创建时复制有效编辑请求，编辑/切协议不回写 Session 或磁盘。

发送入口传完整 locator、草稿副本、模式、环境引用、请求设置及调用身份。主进程以当前工作区验证 locator，复制项目，替换当前 API 的有效 request，再建立只读运行快照；不能让渲染层指定其他项目凭据地址或传解密凭据。引用模型/组件来自当前已保存项目，未保存的模型/组件变更需先明确保存，不暗中混用。

发出后草稿变更、切项目、切工作区或关闭标签不会改变正在运行的输入。迟到结果只能归原会话，不覆盖后来激活的会话。已通过 Schema/项目上下文校验的调用在主进程产生唯一 runId；非法 IPC 输入不执行也不写伪历史。采用启动确认、等待结果、取消三个宿主动作：启动在异步文件/凭据准备和网络等待之前交付 runId；等待/取消须绑定原调用会话与归属，早到取消必须阻止后续发包。待结果不是启动确认，不要求 UI 等响应结束才拿到取消身份。

草稿携带主进程提供的 `sourceApiRevision`（正式 ApiAsset 的稳定内容 hash，包含其用例）及 `sourceProjectRevision`；运行另有 `executionSnapshotRevision`，不可把替换草稿后项目的 hash 标为正式源 revision。保存契约/用例入参携带 expectedSourceApiRevision，在同一主进程事务中与现存 API 比较，旧草稿遇同 Session 内的接口/用例更新也须冲突拒绝。磁盘外部改动继续由现有 storage expectedRevision 门处理，不用当前 Session 的最新 revision 替代编辑者的基准；不建设自动合并/整项目回滚。

### 3.2 两个执行模式

- **发送请求**：不要求已有 case，不运行任意一个“默认第一用例”。构造仅属于本次快照的临时 base 用例，复用选中接口/真实祖先链的环境、普通变量、全局参数、认证和现有容器生命周期操作；不附带其他正式用例的参数、数据驱动、前后置操作或断言。界面明确区分该模式。
- **运行用例**：显式选择 caseId/scope，使用既有环境选择和完整用例语义。默认读取该用例有效请求，不把当前未保存草稿自动保存或偷偷套到所选用例；用户若要使用草稿应明确保存为用例。已有脚本/断言不能静默跳过后报成功。

用例选择保持 F1 的逻辑 caseId + 环境继承链最近覆盖语义，展示实际 effective scope；用户选择与有效版本不一致要说明，而非假称执行了点击的另一版本。历史记录实际完整 CaseLocator（含 effective scope），用例重放须能找到该版本且当前环境仍选择该版本；删除/不适用或当前最近覆盖变为别的 scope 时明确拒绝并提示用户重新选择，不自动转成另一用例/请求模式。

请求模式的 HTTP 4xx/5xx 仍保留真实响应和现有 http 失败分类；没有断言不代表服务响应被伪造为测试通过。WS/SOAP 保持已有执行行为和快照消费，HTTP 专属文件/Cookie/重定向设置对非 HTTP 明确拒绝，不当作适用。

### 3.3 保存动作

- 保存契约：用户显式将请求草稿应用到当前接口 request，再走现有事务/只读/修订检查；不改接口身份、响应设计、模型和组件。
- 保存契约若改变协议，主进程事务同时校验既有 requestOverride 和 requestSettingsOverride；存在协议不兼容或设置不适用的覆盖时拒绝保存并列明 CaseLocator，保留草稿，要求用户先显式移除或修改相应覆盖，不自动改写或删除用例。
- 保存为用例：创建或经确认覆盖一个明确定位的用例，保存请求覆盖、请求设置覆盖、环境 scope、普通 parameters 和用户选择的断言草稿；不把响应或真实凭据写入用例，不改接口默认 request。
- 失败保存保留草稿；冲突不能覆盖别人的新修订；不使用历史快照替换整个项目。

为使“保存为用例”真实成立，新增可选 `requestOverride: ApiRequest`（完整请求覆盖）到正式 ApiTestCase。缺失时沿用接口默认请求；存在时仅替代 request，不替代设计元数据、响应和项目资源。明确显示它是独立的测试覆盖：默认接口 request 后续变化不自动覆盖已有完整 requestOverride，用户可显式移除覆盖来恢复继承。

覆盖协议须与该接口默认协议一致；不同协议草稿仍可按显式请求模式处理，但保存为原接口用例时拒绝并提示另建/显式修改接口，不暗中改变接口类型。保存输入若仍包含已知凭据字面值，拒绝并要求改为引用；不把通用脱敏后的掩码请求写成正式资产。

同时新增纯 JSON、可选的 `requestSettingsOverride`（仅超时/重定向等可持久化设置，不含 signal、文件句柄、Cookie jar 或回调）。缺失使用入口缺省；优先级为缺省设置 < 用例覆盖 < 本次显式运行覆盖。本次调用的默认值不能假称显式覆盖而抹掉用例设置。保存契约只保存其 ApiRequest，不把临时调试设置暗中写入无对应字段的契约；界面说明设置可随用例/历史保存。单次/集合/流程/压测/CLI统一消费用例设置，不丢弃后声称保存成功。

Cookie jar 的当前内容不保存为用例；若草稿依赖会话 Cookie，要明确提示本次状态未被持久化，可改为显式参数/引用或后续登录流程。跨入口一致性验收使用同一显式输入及相同初始会话，不拿已有桌面登录态与全新CLI会话硬说逐字节相等。

这是新正式字段，不是旧 ApiDefinition 兼容层。不另建重复的接口事实源：文档/Mock 仍使用 ApiContract，测试请求覆盖仅属于用例。新增字段采用现有格式 1 的可选扩展，新读取器兼容原格式 1 的无覆盖用例；旧严格读取器不能识别时必须明确诊断/只读，不允许删除字段后保存。若实现发现此口径无法被真实存储/旧读取器证据支持，停止并由用户裁定版本方案，不擅自改格式号或建设旧工作区迁移器。

资产引用扫描、克隆/导入闭包、删除阻断、凭据 ref 收集、执行选择、存储/Schema 和 CLI 消费均须包含 requestOverride。不能只更新类型/编辑器：有效请求在物化前通过选中覆盖的引用/参数诊断，不能错用默认 request 的诊断或凭据准备。普通本地脚本看到当前运行请求的既有 F1 边界保持；不扩脚本 API。

## 4. 文件传输

仅接通既有 HTTP multipart/Binary：

- 文本字段支持启用/禁用、重复名称、顺序、空值和模板值；文件字段支持本地文件引用、文件名、内容类型。
- 文件选择只通过桌面/CLI 宿主；物化与浏览器轻量 Schema 不导入 fs、原生提供方或任意文件 API。
- 相对文件路径按工作区根解析，不依赖进程 cwd；绝对路径为用户显式本机引用，工作区分享/复制不附送文件。文件定位失败提示重新选择，不自动下载或猜其他目录。
- 在本次调用准备阶段根据有效请求捕获文件来源。网络客户端读取这些捕获来源；脚本不能通过修改一个新字符串字段把文件读取转到任意未捕获文件。本轮不把这称为恶意脚本隔离证明。
- 捕获来源使用宿主内部绑定而非后续可自由重新解释的 path。需要重复发送时，仅从同一可重复读取绑定新建流（如捕获的本地文件句柄），不重跑脚本/变量副作用，不改读新的路径；不可重复来源或检测到来源变化时给 FILE_SOURCE_NOT_REPLAYABLE/FILE_SOURCE_CHANGED。不声称流式读取对外部并发写入提供原子文件内容快照。
- 使用流和背压，不把大文件整体塞入 IPC、项目快照、日志或历史。文件引用解析/可读性检查在发包前完成；读取中失败/取消回收流和请求。
- multipart 的 boundary 由编码器生成。用户显式 Content-Type 若与编码冲突要诊断，不能发一个缺 boundary 的报文；Binary 保留指定 Content-Type。
- 单次上传总量默认 64 MiB，可调至最高 1 GiB；按实际读取的文件内容字节、累计整条重定向链实施，重复发送也计入。multipart 文本/编码开销另记实际网络字节，不冒充文件长度。预检查不能替代读取中检查。上限属于普通客户端工程约束，不进行引擎 allocator 故障专项。

历史保存文件引用/名称/长度等必要元数据，不保存文件内容；恢复后重新解析当前文件。文件缺失、大小变化或内容变化不能声称“原始报文逐字节重放”；页面明确这是重新执行，文件内容按本次发送时读取。

## 5. 会话、请求设置与取消

- Cookie jar 按 root + 完整 ProjectLocator + 环境身份隔离；同上下文连续调试可复用，切上下文不串扰。集合/流程/VU 会话仍按已有 run/VU 生命周期隔离，不能引入全局单例 jar。
- Cookie jar 为会话内存，关闭程序不保存 Cookie 原文。支持查看/清空；普通凭据仍按 F1 的系统库加密持久化、免主动解锁策略使用。
- 使用成熟 Cookie jar 的域/路径/过期/Secure 语义，不用简单字典模拟；新增依赖须精确锁定、核实许可/Node22/Electron适配，不升级无关依赖。
- 显式 Cookie header 优先；否则合并声明参数与 jar，同名显式请求值优先。响应 Set-Cookie 逐条处理，不能拼成逗号字符串后错误解析。
- 本次请求设置包含 connect/headers/body/total 超时及是否跟随重定向；缺省保持 connect 10s，其余 30s，正数校验。body 超时为读取闲置超时，total 覆盖整次网络尝试/重定向链；报告说明口径。
- 重定向默认不跟随，启用最多 10 次跟随；保留初始请求及每个后继 hop。303 转 GET（原 HEAD 保持 HEAD），301/302 的 POST 转 GET，307/308 保留方法/Body；转无 Body 请求时移除旧实体头。307/308 文件流按上一节同绑定重建，不能复用已消费的流。total 超时和上传预算覆盖整链。
- 每跳按新 URL 重新取 Cookie 作用域。跨 origin 不携带原 origin 的认证头、认证生成的 query API key、显式 Cookie，也不重新套用该 origin 的认证；不能因 Location 重复了原认证 query 而再次发送该绑定值。下一跳仍须通过任何已配置的既有目标保护，不因新增重定向扩大发压目标权限。下一跳被拒绝时保留前跳响应并注明该下一跳未发出。
- 桌面以 runId 取消当前网络任务；总超时与用户取消通过同一宿主 AbortSignal 装配，清理 timer、body 流、文件流和 run-scoped client。后台结束后再次取消为明确无在途任务，不误取消后来运行。
- 不承诺中断现有同步本地脚本；取消等到该同步段退出后才能被网络阶段观察，不恢复 DEF-001 或扩展脚本引擎。
- 文件准备/编码耗时属于迭代准备开销；requestTimeMs 仍从实际网络发送计至完整 body 读取结束。上传流读取随网络发送发生的时间如实算入请求耗时，不伪称纯服务端耗时。

## 6. 实际请求、响应和查看器

新增独立、可序列化的只读 DebugExchange，不广播包含可变解密绑定的 ExecutableRequest：

- 请求模式/runId、正式来源及执行快照 revision、完整 locator、实际用例身份/数据行、环境、开始结束、设置、失败阶段/机器码和传输状态。区分尚未进入传输、已进入传输但是否送达未知、已获响应；现有 requestStarted 不能直接更名为“已实际发送”。
- 用户草稿、最终有效 URL/方法、Query、Header、Cookie 及 Body 摘要；标明环境/项目/模块/请求覆盖/认证/会话等主要来源。
- 最终请求观测点位于前置操作、认证、Cookie/传输编码和最终保护处理之后，在每跳客户端传输准备处采集；不能用 beforeRequest/Core认证前快照充当真正的最终请求。文件 Body 以编码/来源元数据观察，不消耗或复制流；不能为了观察而发第二次请求。
- 不保留 Socket 内部状态或假称抓到全部传输层自动头；生成的 Content-Type/长度等可确定值要展示，无法确定的值不臆造。
- 响应包含状态、逐条响应头、Cookie、内容类型/编码、请求耗时和有界内容。分别记录 encodedReceivedBytes、decodedReceivedBytes、可选声明的 Content-Length，以及完整读取后才可给出的完整长度；声明长度不是实测完整长度。完成/摘要截断/接收超限中止分别标记，未读完的完整长度为未知。
- 旧插件仅给 bodyText 时是“旧文本观察”，允许记录该字符串的展示字节数，不补造网络原始字节、重复头或真实 Content-Length。

响应接收默认上限 32 MiB，可调但硬上限 128 MiB；网络编码字节与解压后字节分别计数，两个层面都受该上限约束。支持 identity/gzip/deflate/br；未知或损坏的 Content-Encoding 明确诊断，不偷当文本。超限为 RESPONSE_LIMIT_EXCEEDED/response-body 阶段诊断并中止读取，保留头/已接收长度等元数据，不将不完整 bodyText 交给脚本/断言当作完整响应。

既有脚本/断言消费的是完整且有界的本次宿主响应，不是 UI/历史摘要。Binary 没有可靠文本视图时不伪造 bodyText：状态/头断言可用，文本/JSON操作明确报告不适用；旧文本协议客户端继续提供其原文本。历史/展示单 Body 摘要默认上限 1 MiB；每次调试调用所有 exchange 的 Body 摘要合计预算 2 MiB。截断仅说明已知完整内容长度/已接收长度及安全摘要长度，未知长度不填估算值。先投影再截断，不泄露跨截断边界的已知凭据片段。

查看器支持 JSON/XML/Text 的 Raw/Pretty、搜索、复制与下载；不支持的编码给诊断而非偷偷替换。Binary 提供类型/长度及有界十六进制预览；复制/下载标明是否截断或脱敏，不能将改变过的内容说成原文件。HTML 本轮按文本查看，不执行脚本/加载远程内容。

Cookies、实际请求、断言、控制台分别展示；没有相关数据就明确空态。沿用现有输出边界，在 IPC、日志、历史、复制/下载前投影已知普通凭据和认证信息；不能仅在屏幕上遮罩。受脱敏影响而无法保真导出的二进制只展示诊断元数据，不提供假原始文件。

二进制在编码成 hex/base64、传 IPC 或下载前，必须对当前已知凭据字节序列及既有标准认证表示做投影判断，不能指望编码后再按原字符串遮罩。匹配到凭据或无法可靠判断时，只提供元数据，不给内容预览/原文件下载。不扩展为任意秘密发现/任意编码对抗证明；现有字符串脱敏器不能直接宣称具备新的字节判断能力，实施需有独立的有界字节投影步骤。

## 7. 调试历史及重放

新历史与已有运行报告分离，不把 runs JSON 改造成不同格式。

- 在本机应用私有目录保存，根由宿主配置注入；以规范化工作区根和完整 workspace/group/project/API 归属索引。不进入工作区/Git/导入导出/项目克隆；复制工作区不自动复制本机历史。
- 新历史记录有 formatVersion=1、随机唯一 historyId/runId、模式/正式来源及运行 revision、locator、环境、replay descriptor、已投影意图/设置及 exchanges、结果/错误/截断/重放限制。记录不是新的正式接口资产。
- replay descriptor 分模式：请求模式保留安全请求模板/引用/普通草稿参数；用例模式保留实际完整 CaseLocator、有效 scope 和当前重放所需环境引用。SecretRef/locator 等结构身份经 Schema/归属校验保存，不对其身份字段做通用字符串替换；展示文本与可恢复意图分离。
- 意图另带结构化字段状态（路径、redacted/truncated/missing、needsInput），不是通过匹配某个掩码字面量来猜。正常用户输入的掩码样式字符串仍是正常值；被投影改变或截断的字面值不能当作完整请求。恢复后保留这些状态，发送/保存契约/保存用例在所消费字段未补齐前拒绝；引用/模板可重新解析则不需要原凭据字面值。无法保留键名等请求结构时，记录只可查看；只有安全完整的用例描述符仍存在时才可重放该用例，不提供假草稿恢复。结构身份与已知凭据发生冲突、无法同时保留身份及脱敏时也降级，不绕过输出边界保存该原文。
- 记录来源为主进程，每次已校验调试尝试完成后写一次（成功、HTTP失败、网络失败和取消），包括实际未发送的已授权配置失败。不得把同一次请求的前后事件写成多个历史。
- 数据驱动的一次用例调用仍是一条历史，内部按真实数据行与 hop 保留多个 exchange，标明 rowIndex/CaseLocator/hopIndex/顺序，而不是只保存最后一次响应。查看或恢复请求草稿要明确选择某个 exchange，不把最后一行当整个用例。记录最多保留100个 exchange元数据，超出有总数/省略标记，既有用例运行结论仍按全部行聚合；这不是新增逐行历史资产或数据中心。
- 缺省开启，保留 30 天、最多 1000 条，可关闭或调整（最多 10000 条）；过期和数量清理由历史服务仅操作自己的已校验记录，不清理用户工作区。支持按项目/API/时间/方法/结果筛选及关键字搜索。
- 单条写入采用临时文件到完整记录的原子提交、唯一身份；不依赖一个容易被多进程覆盖的权威可变索引。损坏/未来版本记录隔离并给诊断，不删除原件、不当作成功；历史不可写时保留网络结果并显示明确告警。
- 查询分页默认50条、最多200条；列表/过滤读取非权威可重建摘要，不把所有Body常驻内存。读取单记录有4 MiB序列化上限；超过预算时缩减展示摘要/标记不完整意图，不能静默截断可执行结构。有效记录的天数/条数/单条预算不是整个私有目录的总字节保证，损坏/未来版本原件另列占用告警，不能为控量擅自删除。
- 历史删除/清空在 UI 显式确认，运行结果不因历史写失败或被删除而变成未执行。

三个动作明确区分：

1. 查看历史：只展示既有不可变记录，不执行。
2. 恢复编辑：请求模式恢复记录模板/引用；用例模式选择一个 exchange，恢复其安全有效请求意图及该行普通参数为请求草稿，不隐式带出用例脚本/断言。界面说明已切为请求草稿。保留 needsInput，已有 dirty 草稿先确认，不回写正式契约。
3. 重放：请求模式从其安全意图创建新请求调用；用例模式按实际完整 CaseLocator 重跑当前同一用例（全部数据行/操作/断言），不套用历史最后一行的已解析报文。两者均使用当前项目资源、当前指定环境和当前普通凭据，新 runId/new historyId 关联原 historyId；源 revision 变化明确提示“按当前资源重新执行”，不是重发持久化的脱敏字节。

环境/引用/凭据缺失时明确拒绝，不能改用当前偶然选中的项目或无认证发送。已脱敏的字面值若无 SecretRef/变量可重新解析，记录相应字段需重新填写；不能把掩码作为真实参数发送。文件重新读取规则见第4节。源接口已删除时允许查看，不能自动迁移到另一接口执行；自由请求恢复属于后续范围。

## 9. 阶段验收矩阵

| AC | 必须证明的结果 |
| --- | --- |
| F2-01 | 修改草稿后发送，服务端收到新值；正式接口/磁盘/其他会话不变；没有已有case也可发送 |
| F2-02 | 显式运行用例保留完整环境/祖先/操作/数据/断言；草稿不被偷偷套用或保存 |
| F2-03 | 草稿保存为requestOverride用例，保存重开后单次/集合/流程/单迭代压测与CLI使用同一有效请求；接口默认request不变，源API修订冲突（含同Session变更）不覆盖 |
| F2-04 | 覆盖中的模型/组件/SecretRef引用在删除、克隆、导入、未绑定凭据和执行诊断中闭合；旧格式1无覆盖用例可读 |
| F2-05 | 本地HTTP服务验证multipart字段/文件名/类型/字节、Binary字节、禁用项与重复项；缺文件、读失败、超限、取消明确失败且回收 |
| F2-06 | 同上下文Cookie连续生效，跨项目/环境不串扰；逐条Set-Cookie、过期、作用域及显式Cookie优先有聚焦证据 |
| F2-07 | 四种超时、取消和重定向设置实际生效；跨origin认证不转发、跳数有界；不改变既有最终目标保护 |
| F2-08 | 显示的逐跳最终请求与服务端实际收到一致；响应重复头/编码/二进制/摘要截断/接收超限与长度不被伪造；来源、发送状态与计时明确 |
| F2-09 | 每次已校验调试尝试恰一条历史，关闭重开后可查；保留/关闭/删除/损坏/写失败只影响历史服务，不改正式项目 |
| F2-10 | 查看不执行；恢复不保存且needsInput未补齐不可发送/保存；两种重放模式保留语义/用例身份/数据行口径，新run、新凭据解析，历史不变；迟到结果不串会话 |
| F2-11 | 已知合成凭据不进入IPC快照、日志、历史、复制/下载和保存用例的原文；不将普通本地脚本边界夸大成沙箱 |
| F2-12 | 受影响Core/CLI/Desktop类型构建测试、品牌门及真实Windows包闭环通过；主界面顶栏/工作流布局修复不回退 |

验收用受控本地HTTP服务、临时文件/目录和合成凭据，不访问用户真实服务/文件/凭据。复用现有测试及少量必要的新历史/传输行为测试；不做每个配置的全乘积、不重复未改Admin/Java/延期引擎专项。发布前阶段整体门只在最终候选跑一次；实际失败按增量复验，原始失败与告警不擦除。
