## 3. 运行模型与唯一事实源

### 3.1 聚合边界

- `ApiContract`：唯一可编辑的接口定义，包含 `formatVersion`、UUID `id`、`metadata`、协议区分的 `request`、`responses`。
- `ApiAsset`：宿主聚合 `{ contract, cases, documentation }`。`cases` 和 Markdown 是独立资产/侧文件，不在契约内复制请求；聚合不再另存同名 `method/url/auth`。
- 现有 `Collection.apis`、`Folder.apis` 改为 `ApiAsset[]`；接口树身份和标题从 `contract.id/metadata.name` 派生。旧公开 `ApiDefinition` 类型、宽松旧形状和旧保存入口移除，不用兼容别名维持第二编辑模型。
- `Project` 增加 `models` 和 `components`；保留 workspace/group/project/collection/folder 关系、环境、全局参数、用例、工作流和压测策略，不建立平行项目树。
- 物理文件身份继续使用 UUID。项目内接口、模型、组件的 ID 唯一；用例按 `(caseId, scope)` 保留既有同逻辑用例的环境覆盖语义，不能误判成重复或让 SQLite 主键覆盖。
- 新格式脚本操作只用 `preOperations/postOperations`；夹具同步更新，不新增 `preScript/postScript/scripts` 旧格式迁移器。现有操作顺序和行为保留。

### 3.2 格式与业务版本

工作区入口和接口/模型/组件文件都显式 `formatVersion: 1`；元数据的业务 `version` 仍为字符串，两者不可混用。

缺失格式版本属于旧工作区，拒绝打开写入模式并解释如何在新目录新建。未来版本明确拒绝；未知字段严格报错，不通过 Zod strip 或保存白名单静默丢弃。不能因测试夹具还是旧格式就放宽生产解析器。

## 4. 契约结构

### 4.1 元数据与协议

`metadata`：`name`、`description`、`tags`、业务 `version`、`status`（`draft/published/deprecated`）。新接口默认 `draft`；状态只是生命周期展示，不用于猜测真实生产环境。

`request` 是 `protocol` 判别联合，只有当前协议的有效载荷字段：

| 协议 | 请求字段 |
|---|---|
| http | `method`、`baseUrl`、`path`、`pathParams/query/headers/cookies`、`auth`、`body` |
| websocket | `baseUrl`、`path`、四类参数、`auth`、可选 `message`；不虚构 HTTP Body 或业务方法 |
| soap | `method: POST`、`baseUrl`、`path`、四类参数、`auth`、`envelope`、可选 `soapAction` |

WebSocket 保持现有仅连接、发送文本、等待首文本帧、超时和关闭语义；SOAP 保持 XML 信封、SOAPAction 和 Fault 的当前处理，不当作普通 HTTP 成功。

### 4.2 参数与实例

- 四类参数独立；条目含 UUID `id`、`name`、`schema`、`required`、`enabled`、`description`、可选实例 `value`。类型枚举、默认值和示例仅存于 `schema`，参数外层不另设同义字段；参数说明描述参数用途，Schema 说明描述值类型。
- 参数外层 `required` 表达是否必须提供此参数，object Schema 的 `required` 表达哪些属性必需，二者不是重复来源。参数组件引用不复制 Schema 的枚举、默认值或示例；变更后编辑视图、文档与保存重开均读取同一来源。
- 参数 `schema` 描述设计类型；实例 `value` 是请求模板字符串，支持既有变量语法。Schema、默认值、示例不隐式复制为请求值。编辑器可以提供显式“使用示例”操作。
- 参数使用 `inline` 或类型化 `componentRef`，引用参数可单独提供实例 `value/enabled` 覆盖，但不能局部复制组件的设计字段。组件必须匹配所在 Path/Query/Header/Cookie 位置。
- 同一参数位置的重复名称给出设计诊断；Header 比较不区分大小写，其他位置区分大小写。跨位置同名合法。
- 未提供必须的 Path 值无法物化 URL，执行前 `config` 失败；Query/Body 的“缺失必填”等可构造负向测试，F1 不因设计 Schema 不符合就统一阻止发送。

### 4.3 Body、响应和实例分离

- Body 判别值：`none/json/xml/text/graphql/urlencoded/multipart/binary`。
- JSON/XML/Text 保存请求内容模板与可选设计 Schema；不把 OpenAPI Schema 写成 JSON 请求实例。GraphQL 保存 query、可选 variables 与 operationName。
- urlencoded 保存有序字段；multipart 保存有序文本/文件条目，文件以本地文件引用描述，不把文件内容塞进契约；binary 保存文件引用和 contentType。F1 设计可用、落盘完整，未接通传输返回 `UNSUPPORTED_BODY_ENCODING`，网络请求数为 0。
- `responses`：多个响应条目，每条具有 UUID `id`、`status`（具体状态码、类别或 default）、说明、响应 headers，以及按 contentType 区分的 Schema/具名示例。相同 status/contentType 组合重复为设计诊断。
- 示例保存 JSON 值或相应文本，不覆盖实际收到的响应。响应和示例支持组件引用；设计响应不能改变执行结果、断言或报告状态。

### 4.4 模型语法与引用

模型资产具有格式版本、ID、名称、说明和一个 `SchemaNode`。首次支持集：object/properties/required/additionalProperties、array/items、string/number/integer/boolean/null、enum、嵌套、allOf/oneOf/anyOf、类型化 modelRef。共同设计注释包括说明、默认值、示例；未支持外部关键字不能无提示丢弃。

引用只指向同项目资产 ID 并携带期望类型，不隐式解析外部 URL/文件。缺失、错类型、重复 ID 和纯引用环有稳定诊断；结构性的递归模型可保存、展示与导出，不无限展开。组合/递归按图访问，不能通过深拷贝展开形成另一份可编辑模型。

F1 验收模型结构与引用有效性，不宣称提供完整 JSON Schema 标准运行校验器。运行值 Schema 断言进入 F4；不能为了绿灯阻断所有故意无效的测试请求。

## 5. 项目资产服务与快照

Core 的项目资产服务提供按 ID 定位、反向引用查询、重命名、变更影响、拒绝删除被引用资产、导入闭包和克隆映射。它是域服务，不依赖 Pinia、Electron 或 SQLite 全局单例。

- 重命名不改变 ID；删除被引用资产默认拒绝并列出引用方，不静默级联或自动展开。
- 保存结构有效的草稿允许未完成的语义，附诊断；发布/执行必须通过对应语义门。新增非法字段不属于“草稿未完成”，仍然拒绝。
- 模块导入包括其所引用的模型/组件依赖闭包。目标 ID 冲突显式拒绝整次导入，不能覆盖；完整克隆为所有本地资产建立一个统一映射，再重写整个引用图。用例的同 ID 不同 scope 按同一逻辑映射。
- 克隆后的秘密引用不自动复制真实凭据；新项目明确显示未绑定。跨项目引用不能悄悄继续指向源项目。
- 2026-10-08 用户批准方案 A：项目凭据按工作区／分组／项目隔离，允许不同分组存在相同项目 ID。分组重命名（ID 不变）保留绑定；跨组移动保留项目及非秘密资产 ID，但统一换新本项目全部 SecretRef ID，重写 inline 认证与认证组件中的引用并保持别名关系，目标明确未绑定，不复制、读取、迁移或删除源凭据。目标已有同 project.id 时整次拒绝；移动须明确源/目标 group，不按项目 ID 首项匹配。先生成候选、校验、以预期修订和明确删除清单保存，成功后更新内存；失败保持源和目标不变，已启动运行继续使用原固定绑定。该要求包含未被接口使用的认证组件。
- 每次调试、集合、场景、压测运行固定一份契约与资产快照。所有节点/VU 使用同一只读修订，变量和请求仍按运行/节点/VU 隔离；运行中编辑不修改已有快照。
- 解析器、执行前校验、请求物化、Markdown 接收同一显式 `ProjectAssetContext`，不分别从文件系统再读一份。编辑后新运行/新文档使用新修订。

快照元数据的 `revision` 由规范序列化后的项目定义计算；不含解密值，不把运行时请求/密钥表写入可分享快照。

## 6. 持久化与索引

### 6.1 文件布局

沿用 UUID 组织路径，接口目录保存 `api.yaml`（纯 `ApiContract`）、`design.md`、`cases/<id>[.<scope>].yaml`。项目增加 `models/<id>.yaml` 和 `components/<kind>/<id>.yaml`，kind 为 parameter/auth/response/example。

聚合中的 cases/documentation 与目录文件各有单一来源；保存接口文件不能重复写入它们。工作区/项目/容器元数据文件不序列化整个子树。序列化以明确的文件 DTO 与 Schema 对称，不继续用遗漏新字段的手写旧白名单。

### 6.2 加载与写保护

- `StorageAdapter.load` 除 workspace/problems 外返回修订和只读状态。结构/格式问题所在文件不覆写；工作区有未解决加载问题时整体只读，禁止普通保存和孤儿清理。
- 缺失模型引用等语义问题与损坏文件区分：能解析的草稿保留原内容，给出语义诊断；不能因为无法执行就清空资产。
- 孤儿删除改为显式已验证删除清单，不根据部分加载内存“不存在”做目录清理。桌面 Session 必须消费只读状态，不能只在 Core 提示一次。
- 保存具有预期修订。外部修改/第二写入者冲突返回诊断，不静默覆盖；更新内存活动模型须晚于持久化成功。

### 6.3 多文件一致性

实现单写者锁、保存前完整校验、可恢复写入日志：先在 `.apicc/write-journal/<operationId>/` 暂存新文件和备份/变更清单，再应用写入，最后写完成标记。显式删除也纳入同一记录。保存失败回滚；回滚失败保留日志并只读，不能报告成功。

启动检测未完成记录：恢复到保存前的已知一致状态，恢复失败只读并保留原文件/日志。检测已完成记录后再清理该次暂存副本。不得自动抢占未知写入者锁或删除用户目录。

这保证应用可见的失败/重开有明确恢复语义，不宣称多文件天然事务或已验证所有掉电文件系统情形。阶段测试覆盖异常注入、重开恢复、回滚失败只读和修订冲突，不以只调用 Schema.parse 代替写入一致性。

### 6.4 可重建索引

SQLite 仍是缓存。统一复用 UUID 规范路径和任意深度遍历，加入模型、组件、反向引用；用例环境版本使用复合定位键，不用单一 caseId 覆盖。删掉缓存后可从文件重建并定位真实文件，不保存认证明文或第二份可编辑契约。

## 7. 唯一请求物化与现有语义

物化输入是契约快照、项目资产上下文、环境、实例值和本次宿主凭据绑定；输出是临时 `ExecutableRequest`，绝不回写旧接口定义。

### 7.1 基础地址、变量与参数

- 非空 `request.baseUrl` 经变量解析后作为基础地址；为空时使用当前环境对模块的 `baseUrls[collectionId]`；保留既有 `{{baseUrl}}` 内置变量。
- 新契约明确使用“基础地址路径前缀 + path”的连接规则：仅归一连接边界的斜杠，不截取 origin。基础地址 `https://example.test/v1` 或 `https://example.test/v1/`，与 `users` 或 `/users` 的四种组合，均得到 `https://example.test/v1/users`。这不是旧 `new URL(path, baseUrl)` 根相对解析的等价保留，是随本规格确认的新语义；两个导入器与所有执行入口统一使用它。
- 空 path 使用基础地址本身（保留其有效路径）；非空 path 必须是路径模板，不能放完整绝对 URL、网络路径引用、原始 query 或 fragment。完整请求地址须拆入 baseUrl/path，Query 独立保存；基础地址必须为当前协议可接受的绝对地址，不能内嵌 query/fragment。变量解析后再检查，违反规则在发送前给出 `config` 诊断，不猜测或静默改写。Path 参数按路径段编码一次，不把 Path 追加进 Query；需要路径字面问号/井号时用百分号编码。
- 单次请求变量优先级：运行时（数据行覆盖用例参数，用例参数覆盖本次运行累计变量）> 当前合并环境及模块基础地址变量 > 模块变量 > 项目变量。工作流/VU 已有附加上下文按原链路显式传入，不回退为全局共享。
- 保留全局参数与接口实例的覆盖口径：接口同名项优先，包括禁用覆盖。Header 按大小写不敏感比较是本轮明确收敛，不能声称旧合并点已经实现；验收包含 `Authorization`/`authorization` 的启用与禁用覆盖。全局 cookies 与接口 cookies 合并，显式 Cookie Header 保持原来的整头优先口径。全局 Body 参数只作用于相应表单，不改变 Body 类型。
- 认证与脚本处理后的最终 URL 仍经过既有目标保护。不得因新契约可保存 baseUrl 而跳过确认、协议分派、取消或超时。

### 7.2 运行与测量

调试、单用例、集合、工作流与压测复用该物化入口和执行内核。保留数据行、前后操作顺序、断言、HTTP/transport/config/script/aborted 分类以及剪枝/失败/中止的区分。

请求计时、脚本计时、迭代计时继续遵循已修正的边界；凭据读取/资产解析在运行准备或配置阶段计入，不伪装为服务端请求耗时。压测启动时取得所需凭据的运行绑定，各 VU 的可变请求独立；不能每个请求访问系统凭据库，也不能把解密值塞进共享可变请求。

## 8. 凭据策略及已确认的运行语义

### 8.1 已确认的存取要求

- 默认 `test-auto`：普通 API 测试 Token/密码加密持久化、自动读取，不设应用主密码、无每会话主动解锁、无每次请求重复输入。正常重启后仍可使用已保存值。
- 将来更严格策略仅保留抽象边界；F1 不提供虚假的高敏/不可读取模式。请求使用未支持策略，发送前 `CREDENTIAL_POLICY_UNSUPPORTED`。
- 接口认证只保存类型化 `SecretRef`（稳定 ID 与策略）；作用域来自完整的 workspaceId/groupId/projectId。认证覆盖和模型引用不复制明文。SecretRef.id 的正式接受域仍为 string，不强改为 UUID；三个位置 ID 与正式 UUID Schema 接受域一致（包括 NIL/MAX），不得由提供方额外收紧。
- 存取策略不等于访问权限。默认内部公开不等于默认向互联网分享，持久日志/导出/历史继续脱敏；UI 正常保存/发送不反复弹风险确认。

### 8.2 端口、默认适配器与真实验证

Core 定义异步 `SecretStore` 端口：`put(scope, ref, value)`、`resolve(scope, ref)`、`remove(scope, ref)`、不返回原文的 `status(scope, ref)`。宿主注入适配器，执行器不知道文件路径、加密算法、Electron 或第三方 API；`SecretStore` 不注入脚本。

默认适配器拟采用桌面/Node 共用的本机系统凭据库，候选依赖为精确版本 `@napi-rs/keyring@2.1.0`。服务命名空间含产品/地址版本/workspaceId/groupId/projectId，账户键由 refId 与 generation 无歧义编码产生；非秘密活动指针和互斥锁采用同一完整作用域。方案 A 使用新的 v2 地址命名空间，不回退到缺 groupId 的旧地址，不扫描或自动迁移旧条目，旧绑定需重新填写。地址编码保留正式字符串身份，不把原始 ref 当路径，不因大小写、分隔符或 Unicode 编码损失混用引用。地址版本与共享契约 formatVersion、value envelope 格式独立。保存由系统保护，读取通过同一身份自动取得，避免自存裸主密钥。条目内记录格式/策略版本；本机提供方映射不写入共享契约。

桌面和 CLI 使用 Core 的同一个纯 Node 路径函数 `defaultCredentialPrivateRoot()`，返回 `join(homedir(), '.apicc', 'private', 'test-credentials', 'v1')`；不依赖 cwd、Electron userData 或共享工作区路径。该根目录版本与凭据地址 v2 不混用；根目录名不构成 Windows ACL 已验证的证据。SystemSecretStore 仍接收显式 privateRoot；没有自动搜索旧根目录或环境变量路径覆盖。

这不是已验证的依赖承诺：进入对应实现任务前，先核对已发布包接口、Node 22/24 与 Electron 当前版本的预编译绑定、安装/打包、真实保存/重开/读取/删除及错误分类。不能把仓库 main 文档的接口直接当作已发布包实现。若候选不满足要求，保持端口不变，集中报告实际缺口；不能悄悄退回明文、固定密钥、主密码或桌面常驻桥。

F1 本机交付证据以 Windows x64 为必需；不据此宣称 macOS/Linux 后端验证通过。通用构建不静态加载原生提供方；无凭据的普通运行不因提供方缺失而无法启动。系统服务不可用/锁定时给出明确诊断，不偷偷调用应用解锁流程；系统自身授权提示不等于应用新增主密码。

存取缺失、不可用、未知格式/策略、解密/读取/保存失败必须区分；错误只含错误码和引用，不输出底层异常中可能包含的值。不删除失败保存前的有效记录；删除失败不报告成功。运行中凭据绑定固定，编辑后的下一次运行再取新值。

凭据保存/删除是独立的明确操作，界面分别反馈凭据操作和项目文件保存结果，不宣称二者是原子事务。文件日志、备份、修订与索引绝不记录凭据原文：

- 更新已有 ref：提供方保存并读取校验成功后，该 ref 的新值即对下一次运行生效；随后 YAML 保存失败不会回滚该值，界面明确显示“凭据已保存、项目保存失败”，已有运行绑定不变。
- 新建 ref：先保存并校验凭据，再允许保存认证引用。凭据失败不激活新引用；凭据成功而文件失败时可能留下未引用条目，保留并提示待重试，不擅自清除。单独保存未绑定引用必须显式展示未绑定状态，不能假称可执行。
- `put` 或读取校验失败：保留此前有效绑定，不显示新值已生效；具体提供方必须满足此端口契约，否则不能准入。文件保存成功并不代表凭据保存成功，未绑定状态执行前明确失败。
- 删除凭据须提示当前引用会失去绑定；删除成功立即对下一次运行生效，后续文件失败不撤销删除。删除失败保留有效绑定且不报告成功；移除契约引用不会自动删除凭据。

故障注入验收使用合成样本和替身，覆盖凭据成功/文件失败、文件成功/凭据失败、同 ref 替换或读取校验失败、删除失败以及重开，核对 UI、下一次运行与已启动运行各自状态。实际提供方另做真实往返验证，不读取用户已有凭据。

跨机器/账号复制工作区不自动复制真实凭据，缺失时重新绑定；导出、分享、克隆不附送凭据。替换策略保留 refId，迁移成功校验后才切换，失败保留旧有效记录。F1 只实现默认提供方与端口契约测试，不建设完整迁移 UI。

既有 AI key/登录 Token 封装保留，登记其明文降级与新要求不一致，不自动重构或改写用户旧凭据。
