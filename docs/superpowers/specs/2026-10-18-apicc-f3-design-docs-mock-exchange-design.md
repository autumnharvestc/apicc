## 4. 共用契约消费、来源和输出

### 4.1 草稿与已保存状态

- 设计表单编辑当前接口的既有 editor session，沿用完整 locator、generation、readOnly 和保存 revision；不复制出另一份可写契约。说明仍写 `ApiAsset.documentation`。
- 文档预览可使用当前接口草稿；主进程将其替换入同项目快照副本，模型/组件取同一已保存项目版本。预览标注“草稿/未保存”，禁止迟到响应覆盖别的项目或请求签。
- 预览输入包含 locator、`sourceProjectRevision`、当前 `ApiAsset` 草稿；本地 revision 变化返回冲突诊断，不能混用旧模型和新草稿。草稿结构暂不合法时返回字段诊断，保留用户编辑，不能把上一成功预览伪装为当前结果。
- 导出默认使用已保存快照；当前接口有未保存变更时明确提示“导出不含未保存变更”，提供先保存/取消，不自动保存或丢弃草稿。首版不加入整项目多草稿合并导出。
- Mock 只消费已保存项目。Desktop 成功保存相关契约、模型、组件、Mock 配置后通知重载；CLI 首版启动时固定快照，修改后重启。外部文件修改需显式刷新/重载，不承诺文件系统实时监听。

### 4.2 共享派生数据

新增 `design/projection.ts` 负责从 `ProjectSnapshot` 和明确的接口 ID 范围生成数据型文档投影；包含源 revision、接口元数据、各协议请求、响应、模型/组件闭包、说明及诊断。不把面向 AI 的弱类型展示对象升级为事实模型。

统一诊断最小字段为 `severity: warning|error`、`code`、`path`、`message`、`lossy: boolean`、可选 `ownerId`。既有 importer 的 `reason` 经适配进入 `message`；不能仅凭warning一概判断损失。缺失/错误引用返回具体路径；不能静默以空 Schema、空响应或 200 成功替代。错误文本不附整份原始输入。

投影和导出不读取 SecretStore，不换取 OAuth token，不应用本机网络私有配置，不读取文件 Body 引用指向的内容。认证保留类型、API Key 名称/位置等结构，值使用占位符；SecretRef ID、本机绝对路径、真实认证值不进入输出。普通字段/说明复用已有敏感字段及文本遮罩规则，不声称能识别任意未标注字符串中的秘密。

## 6. 本地声明式 Mock 单元（计划 B）

### 6.1 配置与范围

当前项目增加可选 `mock` 配置，结构自身 `formatVersion:1`，随项目文本文件保存、受现有事务/revision 规则保护。缺省为未配置，不批量重写已有接口，不更改 ApiContract formatVersion。新配置同步纳入快照、项目克隆的 ID 重映射及必要的导入诊断；不能新增字段后被旧 clone/encoder 静默丢弃。

配置包含固定 seed、启用接口 ID、按显示顺序排列的规则。规则包含 ID、启用状态、contractId、条件列表、responseBindingId、可选具体 status、mediaType、响应来源、delayMs。响应来源为选定 exampleBindingId、Schema 生成，或显式字面文本；不执行表达式、不取真实凭据、不解引用本机文件/远端 URL。

首版监听仅为 `127.0.0.1`，端口允许0（系统分配）或1–65535，实际地址可复制。不含 LAN 绑定/共享开关；不主动开启 CORS。配置可选择一个静态响应或按规则匹配，未配置/无启用接口时拒绝启动，不自动模拟项目全部接口。

### 6.2 路由、规则和响应

- 路由按 HTTP 方法＋路径模板编译，查询串不参与路由。路径大小写、结尾斜杠均保留；按段处理 Path 参数，单次解码，错误编码400。字面路径优先于参数路径，相同规范模板/方法的歧义拒绝启动并指认接口，不靠加载顺序选择。
- 条件只含 Path/Query/Header 的 equals/exists，及 JSON Body 的 JSON Pointer＋标量 equals/exists；同规则条件 AND，多规则按显示顺序首个命中。重复 Query/Header 值按任一值 equals。没有 regex、JS、模板执行、外部请求或动态回显。
- 有路由但规则未命中时使用显式默认响应；未设默认则返回明确的 Mock 未命中响应，不返回后端真实数据。未知路由404，未命中配置501，运行配置失效503；命中原因均可追溯。
- `default`/`2XX` 等契约状态不是可直接发出的状态，需选择具体状态；未选择则配置校验失败。HEAD 无响应 Body，204/304 无响应 Body；Content-Length 由最终字节计算，传输专用头不照搬示例。
- JSON 生成覆盖现有 scalar/object/array、enum、default/examples、模型引用和组合节点。候选值必须满足当前 Schema 子集；oneOf 需恰好匹配一支，anyOf 至少一支，allOf 全部满足。无法在有界生成中得到值、必填递归或矛盾 Schema，明确报不可生成，用户可选择合法显式示例；不承诺完整 JSON Schema 标准。
- 同一保存快照、seed、ruleId/contractId 得到相同响应，不用请求到达顺序作为随机种子。示例/生成结果是 Mock 数据，不是认证执行。XML/Text 只使用显式文本示例，不自动发明 XML 序列化语义。

### 6.3 生命周期、更新与资源

core 编译快照及配置，Node HTTP 宿主只监听和发送；Desktop main 与 CLI 使用同一编译/匹配内核，renderer 不创建服务器、不导入 Node 模块。

一个 Desktop 项目上下文最多一个实例；身份含工作区根、workspace/group/projectId 和 generation，不能只看 projectId。切项目不把另一项目的控制权/日志绑定过来；关闭项目/切工作区/退出客户端会停止对应实例。CLI `mock <projectPath> --port <n> --seed <value>` 是独立前台进程，不受桌面关闭影响，首版没有后台守护进程/定时任务。

成功保存触发重载：新请求在重载期503，已有请求继续按捕获的旧快照完成；编译成功后原子替换，新请求使用新 revision。编译失败进入 invalid，新请求继续503，界面显示失效字段，不悄悄服务旧契约；修复并重载后恢复。监听端口错误、过期上下文回调、停止期间到达请求分别有明确状态，不弹后台成功提示。

首版边界：请求体/单响应各1MiB、活动请求64、规则每项目256/每规则条件32、延时0–30000ms、生成深度16/节点1000、日志环200条；超限明确拒绝。停止5秒内取消剩余延时/连接并释放监听，不增加无限队列。数值是本阶段推荐产品默认，不是性能平台容量承诺。

日志仅内存保存 requestId、时间、方法、路由模板、接口/规则/响应ID、实际状态、耗时、源revision和未命中原因码；不保存原始 Authorization/Cookie、完整 Query/Body。规则未命中原因不能夹带实际敏感值。界面提供状态、规则配置、日志、复制地址及“在当前项目新建自由请求”；不自动覆盖正式接口 baseUrl，不自动发送。

## 7. 格式交换单元（计划 C）

### 7.1 支持矩阵

| 入口 | 本阶段承诺 | 明确不承诺 |
| --- | --- | --- |
| OpenAPI 导入 | 复用已有2.0/3.0/3.1解析；补统一诊断和回归 | 任意外部ref抓取、完整标准所有keyword |
| 集合v2.1导入 | 保留目录/请求/现有转换能力及损失提示 | 执行导入脚本/自动读取文件Body |
| cURL导入 | 单条POSIX命令的数据解析；URL、method、header、cookie、常见body/form/file声明 | 执行命令、管道/重定向/命令替换、读取@文件、任意curl参数及PowerShell/cmd语法 |
| OpenAPI导出 | 3.1及3.0，JSON/YAML，四种范围，受支持契约子集 | WS、完整SOAP/GraphQL语义、测试脚本/用例/Mock行为的通用标准映射 |
| 文档导出 | 计划A的Markdown/自包含HTML | 在线分享、Word、集合格式导出、Wiki同步 |

外部格式不能代表的内容逐项返回 code/path/原因。不是“入口接受任意文件就支持全部格式”。请求/响应/模型的实际语义损失标记lossy=true，导入/导出默认阻止，用户显式确认（CLI `--allow-lossy`）后才能应用/产生输出，并附诊断；结构无效/引用错误不能通过该开关绕过。遮罩及已声明的格式范围（例如OpenAPI不携带apicc用例/工作流/Mock执行配置）仍有信息诊断，但lossy=false，不让每次正常接口导出都被本地用例的存在阻塞。

OpenAPI `info.version` 独立于规范版本；界面允许明确填写，单接口默认取接口版本，其余默认1.0.0并标注为导出元数据，不冒称项目有版本字段。同一路径/方法冲突、空范围、无法解析引用为错误。Schema映射只使用已有表达能力，不为格式数量扩成另一套契约模型。`{{变量}}`不自动替换为选中环境或本机值；不能映射成合法标准声明时给字段损失诊断，若连合法目标结构都无法产生则始终报错，不伪造真实服务地址。语义往返比较忽略导入新UUID/SecretRef和脱敏值，不要求字节相等或恢复真实秘密。

cURL解析支持 `curl`/`curl.exe` 命令名、POSIX引号/续行、`--url`、`-X`、`-H`、`-b`、`-u`、`--data/--data-raw/--data-binary/--data-urlencode`、`-F/--form`；按各选项明确语义编码，不能将有序重复字段压成字典。未知或具有非声明含义的选项拒绝并指出位置。认证值转为空 SecretRef/遮罩诊断，文件仅成为待用户重新绑定的引用，不自动读取。输入只解析一条命令，不运行任何 shell。

### 7.2 导入目标、冲突与原子性

保留主页“导入为新项目（当前工作区内选分组）”和工作区“导入为当前项目新模块”，新增显式“合并到当前项目的已选模块”。不在项目工作区提供跨项目目标选择，不默认覆盖原资产；同名并存的旧入口行为保持。

合并匹配只限选中模块，以协议＋方法＋规范路径生成候选；多候选必须显式选择，不能仅凭名字、URL或新生成UUID直接覆盖。逐项策略：跳过、重命名后新增、覆盖；默认跳过冲突，取消整批不写盘。覆盖保留目标contractId、本地用例/说明；新依赖模型/组件经既有clone映射生成新ID。协议不兼容、本地用例或Mock引用被破坏时预检拒绝，明确列出资产；不静默删用例或扩大覆盖范围。

预览由宿主持有完整结果/diagnostics，renderer只持预览token及用户决策；token绑定 root、完整目标locator、generation、workspace revision和来源摘要。Apply不接受任意renderer传来的完整项目来绕过预览。来源、目标或revision变化要重新预览；失去写权限/只读即拒绝。

应用顺序：解析→诊断确认→生成候选合并计划→完整契约/引用预检→单次`storage.save(expectedRevision)`→成功后更新session和树。复用现有journal处理失败回滚，不能逐接口落盘后宣称整批原子。存盘成功但刷新失败须显示“已导入，刷新失败”，不能再次点击创建第二批。

桌面成功导入后提供当前会话内的一次撤销；仅工作区revision仍等于导入后revision时允许，使用同一事务层恢复前状态并删除本批新增定义。已有后续修改时拒绝撤销，不覆盖用户新数据。重启后不提供该内存撤销；CLI首版提供预览和原子失败回滚，不承诺持久化成功撤销命令，结果清楚说明边界。不以删除并重建整个用户目录实现撤销。

## 9. 测试、审查与停止规则

每个交付任务只复用/新增能证明本次行为的最少断言，先确认真实失败再修复；已有成功证据在候选未变时复用。禁止源码grep充当功能测试、jsdom充当几何证明、加超时代替诊断、为了绿删除测试。Mock网络测试只用本机合成服务；不调用真实第三方账号。

显式目标用 `pnpm -C <package> exec vitest run <file...> --maxWorkers=2`，不能用 `test --` 转发，不能省略目标而误跑整包。CLI子进程需要构建时先构建其依赖一次，不每个用例重复。开发任务完成后由独立Sol进行规格/质量审核，root汇总，避免多层重复全阶段审计。

阶段末进行一次受影响范围门禁：Core排除明确延期专项、CLI、Desktop按低并发顺序执行；同候选不重跑整套，修复后只重跑受影响文件。构建遵循Core→CLI/Desktop依赖，Desktop正常完整build一次；打包复用该构建，不再调用重复build的包装命令。真实包几何和OS滚轮分别记录。最终实际退出码、未验平台/格式、继承开放项及包路径归档，用户检查后另行决定Git集成。

本阶段只规划 Windows 本地交付。明确不承诺绝不会出现平台拦截；如有真实拒绝，停止该具体请求，报告已完成/剩余项和需要用户决定的最小选择，不换主体绕过或悄悄扩展延期专项。
