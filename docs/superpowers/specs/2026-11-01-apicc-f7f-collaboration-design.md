## 3. 范围与非目标

### 3.1 本阶段交付

1. 项目内共享历史索引、可读报告与显式发布的单项本机历史/报告。
2. 从已保存的在线契约发布文档；从已归档报告或已接受的成员上传报告发布只读副本。
3. 成员查看和外部持有链接查看分开授权；固定版本、到期、撤销、换钥、下载开关及清理。
4. 从固定在线项目版本发布共享声明式 Mock，提供独立调用密钥、停用、版本和有界命中日志。
5. 细化脚本编辑、项目凭据绑定、普通任务执行、发布与分享、Mock 管理、历史读取和审计权限；沿用 F7d 独立调度授权。
6. 客户端日常发布/查看，Web 对应级别管理员管理策略、权限、分享和审计；公开浏览器只读页面。
7. 必要本地化、可读展示、真实跨端故障验收及部署交付。

### 3.2 不包含

- 实时共同编辑、评论、审批流程、通用文档 Wiki、邀请邮件/外部访客账号体系或 SSO 新接入。
- 从分享页调试真实接口、启动测试/压测/定时任务、取得凭据、下载完整项目或调用 MCP 执行工具。
- 共享脚本化 Mock、后端透传/录制真实接口、任意上游 URL、WebSocket Mock 或完整 SOAP 服务模拟。已有 HTTP 承载的 SOAP/XML 静态文本例子仍按 Core 的实际支持范围说明。
- 团队共享 AI、后端 AI 代调用、无人值守 AI 分析、AI-FUTURE-001–005。
- F7g 外部规范同步、独立调度 B、到达率 B、跨代理分布式压测和 DEF-001。

## 4. 架构建议：Java 控制＋可选 Node 协作运行服务

### 4.1 三个宿主的职责

| 单元 | 负责 | 不负责 |
| --- | --- | --- |
| Java 在线服务 | 成员/项目授权、策略与版本、固定源读取、发布记录与副本存储、访问密钥摘要、公开入口、配额及审计 | 不用 Java 重写 Core 的契约、Mock 或报告算法 |
| 新增 `apps/collaboration-runtime` | 以同构建 Core 解码契约、生成安全投影、校验/转换报告、编译并响应声明式 Mock；有限私有 RPC | 不持有登录令牌、项目凭据、代理身份或数据库权限；不装配 Runner、JS 引擎、插件加载和目标请求客户端 |
| 现有执行代理 | 保持 F7b–F7e 的任务执行职责和主动长轮询连接 | 不承接共享 Mock 的常驻公网入口，不增加后端主动连接代理或代理入站端口 |

协作运行服务是 **Core 的受限宿主**，不是第二套执行内核或新的测试代理。生产建议部署为与 Java 同站点、内网可达的独立 Node 容器；Java 只调用固定部署地址，运行端口不对外发布。首次提供这一种装配，不添加没有实现的宿主选择开关。

备选比较：把共享 Mock 放到测试代理，会引入长期占槽、私网入站或逐请求反向隧道，并改变现有离线语义；在 Java 重写 Mock 容易造成两套规则。单独的协作运行服务需要多一个可选容器，但职责和失效边界清楚，故推荐此项。

### 4.2 数据流与接口边界

发布：成员选择已保存版本/已结束结果 → Java 鉴权并固定源版本和摘要 → 私有 RPC 调用 Core 投影/校验 → 返回有预算的派生 DTO → 用户预览 → Java 再核对权限、策略和候选摘要，原子保存发布版本 → 单独创建访问授权。

访问文档/报告：公开页面只拿专用安全 DTO；Java 每次核对授权、到期、发布状态及当前上级策略。已保存副本的读取不依赖 Node 在线，也不回查“项目最新版本”。

调用 Mock：Java 验证专用调用授权、当前发布状态及容量 → 将规范化方法/路径/安全业务头/有界正文和固定计划摘要送入协作运行服务 → Core 匹配与生成响应 → Java 约束响应头并返回，同时写元数据日志。不得在此流程调用业务接口或执行任务。

私有 RPC 使用版本化的有限操作：`project-document`、`project-report`、`classify-asset-mutation`、`compile-mock`、`respond-mock`、`health`。全部严格校验、限长、有期限/取消；无通用 eval、文件路径读取、URL fetch、shell 或动态模块操作。部署地址只由部署管理员配置，不能由项目文件或分享请求提供；默认禁止重定向。

RPC 用独立部署秘密文件认证，不复用用户/代理令牌；请求包含操作、请求 ID、输入摘要、输出预算和期限，响应绑定输入摘要、协议版本、Core 构建身份及实际字节数。远程部署如启用加密连接必须正常验证证书；同机私有网络的 HTTP 仅用于明确受信网络，不通过关闭全局 TLS 校验实现。应用边界不是 OS 强隔离，容器出站、CPU/RSS 与文件系统权限需部署约束。

此处“不持有项目凭据”指不读取凭据库、不解析运行密钥和不持有长期控制身份，不等于保证用户契约中从未硬编码过秘密。传入的授权源内容仍按敏感材料处理，原文不写日志/缓存；派生输出经白名单和脱敏后才可发布。

### 4.3 Core 复用与失效

- 复用 `decodeContractProjectFiles`、`createProjectSnapshot`、文档投影、证据输出边界和报告解析/展示；新增薄的公开子路径导出，避免协作运行服务装配执行能力。
- Mock 从当前 `server.ts` 提取传输无关的匹配/响应单元，本地 HTTP 适配器和协作运行服务共用。原本地监听、配置、固定种子与命中解释不能退化。
- 允许缓存固定摘要对应的编译计划；缓存不持有访问授权，Java 不把缓存命中当权限证据。缓存丢失可从已发布计划重新装载；重建不是重发之前的 Mock 请求。
- Node 不可用：新投影/发布检查及 Mock 返回明确的能力不可用；不退回 Java 模拟、不自动重试 Mock 请求、不声称已生效。本地功能和原有代理任务不受其可用性控制。
- 只部署旧 Java 服务的用户可以不启用协作运行服务。新增 UI 显示未配置原因，不显示可成功开启的空开关。

## 5. 发布对象、来源与固定版本

### 5.1 两种对象，不能混成执行身份

`SharedArtifact` 是项目内不可变的派生内容，种类为 `document`、`report`、`debug-history`、`mock`；每个发布版本有内部实体 ID、项目范围、递增发布版本、内容摘要、投影格式/脱敏策略版本、来源身份/修订、创建人及创建时间。内部数据库实体 ID 对外沿用字符串化数字；契约 UUID 和定义指纹不改为自增版本。

`AccessGrant` 是对一个具体发布版本的访问许可，包含随机公开 ID、受众（`members` 或 `link`）、用途（查看/Mock 调用）、下载权限、到期时刻、授权代次和密钥摘要。发布内容不携带访问密钥，分享 ID 也不等于原任务/报告 ID。

### 5.2 各来源的处理

| 来源 | 处理与对外标记 |
| --- | --- |
| 代理/定时任务已归档报告 | Java 从本项目真实记录固定读取，不接受客户端指定用户、代理或结论；保留真实运行身份、快照、运行时和完整性限制 |
| 在线项目本机执行的结果 | 用户显式选择单项，服务端验证类型、范围与预算，再生成共享投影；标为“成员上传／本机执行声明”，不能称服务端验证了该请求确已发送 |
| 私有本地调试历史 | 用户先选在线目标项目，在本机经 Core 投影并预览，明确确认后才上传安全单项；不自动推送相关文件、整个项目、Cookie 会话或同目录历史 |
| 在线契约文档 | 以服务端固定的 `contract-files-v1` 版本及选定接口/模块/目录范围构造；只带必要模型/组件依赖，不带全项目内容 |
| 共享 Mock | 以固定已保存版本及启用规则编译，只发布可执行的声明式计划；不携带环境实值、脚本、附件材料或认证凭据 |

对旧报告格式只接受已有解析器明确支持的内容；缺真实请求证据时保留“未采集/不支持”的限制，不能补造请求、定位或完整性。源报告待传、缺正文、摘要不匹配或已到期时拒绝创建副本。新发布读取须在同一固定版本中核对状态与正文；不能组合旧 `report()` 的两次查询再宣称不存在竞争，也不修改其延期项范围。

### 5.3 预览和提交

预览绑定项目、源版本/摘要、选择范围、投影与策略版本、操作者、预览有效期及候选摘要。提交不能由客户端替换任意候选正文；Java 保存由受信协作运行服务计算且与候选摘要一致的结果。源版本变化、额度/权限变化或预览到期须重新预览，不能静默切到最新版本。

本机来源多一道上传前确认：在本机先构建严格的安全输入 DTO，移除私有标记、会话、路径和非选定内容，展示将发送的范围/大小；用户确认后才跨网络发送。服务端不信任客户端“已脱敏”标志，仍校验来源、schema 与预算，并由协作运行服务作二次投影。上传不能包含完整本地项目或未知字段；来源可信程度保留为成员声明。

发布副本独立于原报告保留期：创建时明确“此副本会按分享策略独立保存”，占用项目存储额度。删除本地历史不自动撤回已发布副本；删除项目或发布版本则阻止其后续访问。发布新版本不自动改变旧链接；用户显式生成新授权或撤销旧授权，旧内容不被原地替换。

## 6. 权限：沿用角色，增加有限业务权限点

### 6.1 计算方式

顺序为有效账号 → 工作区成员关系 → 项目存在与 ACL → 角色最低档 → 业务权限点 → 本次对象/源归属 → 当前策略/版本。项目 ACL 的 `NONE` 不回退为默认允许，分享密钥不参与成员角色计算。

为新业务定义有限权限集合，不做通用 IAM/任意表达式。配置支持工作区默认与项目覆盖，针对已有成员设置 `inherit/allow/deny`；`allow` 不能突破角色最低档。项目管理员在 Web 编辑且有期望版本、有效来源和审计；仍有管理权限的管理员可恢复策略，不引入强制职责分离。新增权限默认尽量保留旧行为，外部分享和共享 Mock 的新增管理能力默认只给 ADMIN/OWNER。

| 权限点 | 默认授予 | 可授权的最低角色 | 要求 |
| --- | --- | --- | --- |
| `history.read` | VIEWER+ | VIEWER | 约束项目历史、结果及报告读取；不授予任务执行 |
| `history.publish` | EDITOR+ | EDITOR | 选中单项本机结果发布到项目内，不能自动对外创建链接 |
| `script.edit` | EDITOR+ | EDITOR | 修改/删除脚本及旧 JS 条件单独判定，编辑权不等于远程脚本批准 |
| `credential.manage` | EDITOR+（兼容现有绑定入口） | EDITOR | 写入/删除项目凭据绑定；不是密钥原文读取权限，不继承为外部分享能力 |
| `task.execute` | EDITOR+ | EDITOR | 普通任务准备、提交、启动和在途敏感材料获取；不替代 F7d 调度授权 |
| `publication.manage` | ADMIN+ | EDITOR | 可明确授权编辑者发布文档/报告版本与管理分享；历史上传者默认不能绕过此项 |
| `mock.manage` | ADMIN+ | EDITOR | 可明确授权编辑者发布、停用 Mock 和管理调用密钥；普通调用密钥不允许管理 |
| `mock.logs.read`、`audit.read` | ADMIN+ | VIEWER | 两项独立可授予的只读权限；能看文档或调用 Mock 不代表能看日志/审计 |

既有取消规则保留：本人或有效项目 ADMIN/OWNER，且仍满足执行权限；不会因可分享报告而获得取消他人任务的权限。F7d 的计划管理/执行主体批准与远程脚本版本批准继续单独核对。

`history.read` 控制历史列表/结果正文，不把 `task.execute` 变成不可观察的盲执行：用户仍有当前执行权时，可查看自己未结束任务的最小状态并按原规则取消，但不因此取得其他成员历史或完整报告。发布报告须同时具有源历史读取权与发布管理权；文档/Mock 则核对对应契约读权与管理权，不能用发布权限绕过源权限。

### 6.2 不能只做 UI 隐藏

- `task.execute` 接入既有准备/提交/代理启动核验等权威入口，MCP/CLI/桌面不能各有一套判断。撤销阻止后续准入，不把断线在途任务误报为已经取消。
- `credential.manage` 接入真实凭据写入/删除及新审计，不返回值或内部解密材料。
- `script.edit` 必须覆盖结构化原子 delta 以及旧文件 PUT/batch/delete 的可达路径。缺权限时，使用 Core 对固定旧/新版本比较真实脚本字段，包含模块/祖先目录、用例、子流程与旧 JS 条件；不靠关键词或文件后缀判断。检查后提交仍核对原项目版本，不能在检查与写入之间换内容。
- 对无法解析的旧布局，缺 `script.edit` 的写入先拒绝并提示原因，不能假设“未检测到脚本”即允许。拥有既有完整编辑能力的正常路径不因未启用协作服务被全面锁死；不自动转换旧项目。
- 角色、ACL、停用和业务权限变更须接到相关真实写入入口及可读审计。必要事务只围绕此次授权/记录，不趁机重构全部旧服务。

### 6.3 R1：按实际 ACL 评估设置权限基础前置工作

早期 `PermissionService` 是角色解析器，不是完整的授权服务：它可以给非成员的预设 ACL 返回角色，但真实内容/资产/执行入口另有成员守卫。复用 Role/ACL、稳定 ID、NONE/继承和现有业务重检点，在 Java 增加统一项目授权权威；不能让 F7f 新接口直接用 `effectiveRole` 的结果放行，也不在 Node 复制一套 ACL。

实施计划须先纳入以下有界工作，再接发布/外链/Mock：

1. **OWNER 不变量。** 真实 HTTP 诊断发现超管入区定角色入口可将当前 OWNER 降为 VIEWER，使 OWNER 数变为 0；原有普通成员入口则 403。必须先以正式真实 API 回归复现，再修正各写入口的目标状态保护；本次未修复。
2. **角色与能力。** 保留项目 ACL 可相对工作区角色提级/降级的既有明确授予；业务权限的角色门槛使用有效项目角色。工作区管理权限、项目管理权限、内容读权分别计算，不能互相冒用。
3. **版本/事务/审计。** 旧 ACL 没有期望版本与事务审计；扩展版本和变更来源，并适配仓储写法。覆盖超管入区、成员转让/移除和旧文件写入等可达旁路，不只为新控制器增加判断。
4. **管理与内容目录。** 被 NONE 隐藏的项目可能仍可由工作区管理员修改 ACL；权限恢复页面使用管理目录，新内容/历史/分享页使用有权内容目录，不以 UI 可选为理由扩大内容权限。
5. **成员生命周期。** 采用用户确认的评估 §7 的 A：移除后旧显式角色/allow 和新增业务授权失效，重新加入有旧覆盖的项目须管理员重新确认；NONE 不被简单删除而意外放宽。无旧覆盖的项目按新工作区角色及当前策略计算。恢复覆盖或恢复继承均为显式、版本化管理操作；外链/Mock 旧秘密不因重入或恢复资格复活。B 仅保留为评估中的历史备选，不实施。

已完成的评估证据为两批现有 Java 定向回归 225 项、管理台 25 项，以及真实回环 HTTP 合成诊断；不是新功能验收。OWNER 诊断断言实际失败（exit1）作为缺陷证据保留，不能把既有回归通过说成该缺口已解决。配套评估列明代码范围、复用程度和最小接线/验证清单；这些改动不涉及 F7b 延期的代理去重元数据或旧报告下载竞争。

## 7. 对外访问、撤销与敏感信息

### 7.1 两类受众

成员受众使用既有登录身份和项目权限，成员链接仅是定位；转发不能授予陌生人访问。公开浏览器页若需要成员身份，转到受保护的成员页面，不要求把现有 Bearer 令牌放入分享 URL。

外部受众须同时满足部署、工作区和项目三层允许，并由有权成员明确创建。使用随机 32 字节访问秘密、独立随机公开 ID；库中只保存秘密摘要，常量时间比较。密钥只在创建/轮换时回显供复制；丢失就换钥，不提供明文回查。

若创建/轮换在回显前网络中断，客户端查询原操作结果、显示“授权已创建但密钥未取得”，由用户显式轮换；不能自动再建一份授权或为了重放明文而长期保存秘密。成员受众的查看定位无需生成共享秘密。

文档/报告链接采用 `/s/{publicId}#key=…`：固定页面读取 fragment 后仅在内存中使用，数据请求把密钥放入专用认证头，不放 query/path、不保存到本地存储；目录定位用同一受控 fragment 的独立字段，避免锚点覆盖密钥导致刷新失效。页面不展示秘密，日志不记录认证头。fragment 不是抗泄漏机制：复制、浏览器历史、扩展或截图仍可能泄露链接，故只用于已批准的外部只读内容。[MDN 对 fragment 的说明](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)确认其不随初始资源请求发送到服务端；[OWASP REST 安全指南](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)支持将敏感凭据排除在请求 URL 外。

共享 Mock 使用独立的 `X-Apicc-Mock-Key` 调用头，不把调用密钥嵌入 Base URL；每个调用授权只绑定一份 Mock 发布版本。不得接受成员登录令牌、文档查看密钥或其他项目的密钥代替。

Mock 授权也区分受众：成员范围须同时校验当前登录身份/项目读权与 Mock 调用密钥，外部范围才允许仅持专用密钥调用，并受三层外部开关控制。关闭外部访问不能靠创建“成员范围”的可转发裸密钥绕过。网关核验后不向 Core 传递成员认证或 Mock 密钥。

### 7.2 可撤销性的确切含义

- 每次内容读取、下载和 Mock 调用，都从权威状态重新校验有效期、授权代次、发布状态及上级开关；缓存只缓存内容，不缓存长期允许结论。
- 授权状态为有效、已撤销或已到期；已撤销/到期不重新激活同一秘密，恢复须新建授权。轮换原子递增代次并废止旧秘密。
- 对外授权依赖当前发布责任人的成员、源读取与对应发布/Mock 管理资格；其停用、离开或资格被撤销后暂停对外访问。项目管理员可显式接管责任并生成新授权，不静默把旧秘密重新启用。
- 撤销/停用提交后，尚未准入的新请求拒绝；已通过准入并开始发送的响应可能完成，已经下载的文件或截图不能收回。管理页同时显示请求收束状态，不声称远程抹除。
- 公开入口不返回“这个私有项目存在但你没有权限”等枚举信息。无效密钥/随机 ID 统一一般性拒绝；在有效授权范围内可解释到期、撤销、源不可用及容量限制。

### 7.3 公开内容和来源隔离

对外浏览器页面不复用管理台登录存储，部署需配置与管理台 **不同 origin** 的公开 Base URL；反向代理和 Java 均按配置的 Host/origin 区分路由，不从不受信 Host/转发头生成分享地址。公开 origin 不提供管理 API、Cookie 或控制台 bundle。未配置隔离来源时，成员历史/报告和管理功能可用；对外查看与共享 Mock 调用入口须在隔离来源就绪后开放。单机验收可用两个回环端口和合成数据，不需公网域名或额外 CA。

对公网部署要求由受信入口提供 HTTPS 并按配置验证来源；HTTP 验收仅用于明确的本机/隔离合成环境，不修改全局信任、不关闭证书校验，也不把本轮准备变成真实公开部署。

公开页面只渲染经转义的文本和结构化安全 DTO，不执行用户 HTML、Markdown 内嵌 HTML、远程图片或自定义 JS。采用固定页面脚本、严格 CSP、`no-store`、`nosniff`、`no-referrer` 和禁止嵌入策略。离线 HTML 下载复用已受控的生成器，下载文件不得包含访问秘密。共享 Mock 原始业务正文保持业务内容，但对顶层 HTML 等主动内容响应施加 CSP sandbox，不能成为可读管理台身份的页面；不开放用户自定义 CSP/Set-Cookie 等控制头。[MDN CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)说明其限制及不应混同为应用权限的性质。

### 7.4 脱敏和证据分层

- 默认对外仅公开文档必要投影，或报告摘要、逻辑结论、真实请求统计、可读失败类别/安全定位和完整性限制；请求/响应正文、Cookie、认证头、变量/环境实值、控制 token、真实文件路径、脚本和内部项目快照不在默认投影中。
- 可选的受限证据详情必须由发布人显式选择，先做 Core 二次投影与预览；受上级策略和单字段/单报告预算限制。认证、Cookie、私有路径等不可因此解禁。没有原始脱敏依据的旧证据只给安全摘要，不把“看似已脱敏”当完整证明。
- 配置额外敏感 header/query/JSON 字段名及 JSON Pointer 路径；本期不引入任意正则/脚本脱敏。下级只能增加遮罩或减少内容，不能移除强制遮罩。已知密钥和标记、跨平台路径在生成边界检查；对不认识的业务秘密不作万能识别承诺，预览显示范围和风险。
- 发布候选与最终安全 DTO 都必须扫描，而不是扫内部快照的序列化结果；内部材料为生成而存在不表示可公开。公开 DTO 使用白名单 schema，禁止含私有对象的任意对象序列化回退。
- 统计不重算成功口径、不删除历史失败以美化结果；缺失、未采集、被遮罩、预算截断及不支持分别表示。

## 8. 共享声明式 Mock

### 8.1 发布与调用

只接受已保存在线版本中明确启用的接口和规则；示例、Schema、固定种子、状态码、媒体类型、响应头和延时沿用 Core。先预览编译诊断与命中样例，再创建不可变发布版本，默认停用；启用后仍需独立调用授权。修改项目不会热更新正在共享的版本。

发布计划已去除无关资产；规则引用丢失、路由歧义、不支持协议/条件、超预算或含被禁止的敏感材料时拒绝发布，不能静默丢规则后成功。含真实附件依赖、运行时秘密占位符、脚本或转发目标的计划不接受。

公开路径为 `/mock/{publicId}/{业务相对路径}`，Java 分离路由前缀和业务 path/query，再按同一 Core 规范化规则匹配。拒绝绝对 URI、越界/畸形编码及连接隧道方法；保留重复 query/大小写等已有业务语义，不自行猜测或二次解码。

网关去除控制认证头、Cookie、Authorization、Proxy-Authorization 等敏感输入，不写入日志、不传给协作运行服务；发布时拒绝依赖这些被去除头的条件并可读定位。业务响应 header 经约束，禁止 Set-Cookie、Location、hop-by-hop 头和覆盖平台安全/CORS 头；冲突在发布预览中报错，不让接口运行时才悄悄变化。CORS 默认关闭，仅允许管理员配置的精确 origin，不支持带凭据的通配放行。

### 8.2 容量、取消和日志

Mock 不占代理执行槽；单独核算服务端入口、协作运行服务及项目/发布版本的 RPS、在途数、请求/响应字节、延时和期限。容量不足立即 429，不在后台排队积压，不自动重试请求。默认额度是开发阶段保护，不是吞吐能力承诺。

请求截止、客户端断开或服务停止后取消当前延时/响应，确认完成或收束后释放在途额度。协作运行服务重启使正在处理的调用失败，新调用可按固定计划重新装载；不能补发旧调用或返回伪造成功。

命中日志只记录发布版本、时间、方法、路由模板/规则 ID、状态、耗时、拒绝/未命中原因、相关请求 ID 及访问授权的非秘密标识；默认不记录原始 query/header/body、IP 或响应正文。读取日志需要 `mock.logs.read`，调用者不能凭调用密钥查询日志。请求准入不依赖逐条同步写审计，日志暂不可用则显示观测缺失，不伪称完整留存。

| Mock 单请求/响应字节 | 1 MiB／1 MiB | 各 1 KiB–8 MiB，受总在途内存限制 | 头/正文均有界，取消后释放 |
| Mock 最大配置延时/调用期限 | 30 秒／35 秒 | 延时 0–30 秒（现 Core 规则硬上限）；期限 1–120 秒，须大于启用规则最大延时并留处理余量 | 新发布校验组合；调用按当前不更宽松限制准入 |
| Mock 日志条数/保留 | 每发布版本 200 条／24 小时 | 0–10,000 条／1 小时–30 天；0 为关闭命中留存 | 有界丢旧，管理审计另算；不记录业务报文 |
| 额外敏感字段/路径 | 空 | 每项目合计 0–200 项，每项≤256 字符；受支持字段名/JSON Pointer，无任意正则 | 并集；增加后暂停不符合旧投影的授权 |
| CORS 允许来源 | 空（关闭） | 0–50 个精确 origin，每项≤512 字符；无通配、无用户口令 | 每次浏览器调用；不是鉴权替代 |
| 管理/访问审计保留 | 90 天／7 天 | 管理 7–3,650 天，访问 0–90 天；受全局存储上限，访问 0 为关闭明细 | 清理前显示影响；必要管理审计不允许随意关闭 |
| 清理批次/间隔 | 100 项／1 小时 | 1–1,000 项／1 分钟–24 小时 | 新周期；活动引用和有效授权不能被直接淘汰 |
| 协作 RPC 连接/普通调用期限 | 3 秒／10 秒 | 连接 0.1–30 秒，调用 1–300 秒；不得超过所属操作剩余期限 | 新调用；Mock 延时按其调用期限单独预算 |

部署还需设置全站总存储、总在途、总 RPS、RPC 最大消息和 Node 进程 CPU/RSS 限额，不能把每项目额度当整机额度。默认总存储 1 GiB、公共读取 100 次/秒/64 在途、Mock 100 次/秒/64 在途、有效外部授权总数 1,000；总存储允许 64 MiB–100 GiB，速率 1–10,000 次/秒，在途 1–1,024，授权总数 1–100,000，仍受部署硬资源约束。计费包含成员上传、预览、安全副本、已保存计划和有界日志，不能只统计发布正文。

Node 缓存默认 64 MiB、可设 8 MiB–1 GiB；RPC 实际消息默认上限 32 MiB、可设 1–128 MiB，连同 JSON/base64 封装后的实际字节检查，不因源字节合法就忽略线路额度。建议容器默认 1 vCPU／768 MiB 总内存、Node 堆 384 MiB；部署可设 CPU 0.25–8 vCPU、总内存 256 MiB–8 GiB、堆 128 MiB–4 GiB，堆与缓存及在途预算必须留在总内存之内并留宿主余量。CPU 为可配置小数，其他数值额度用整数/毫秒单位存储；未配置外部硬限制时明确展示“未配置”，不声称 Node 堆上限约束了总 RSS。R0 不以这些参数为由执行高负载或长稳测试。

## 10. 存储、接口和并发语义

### 10.1 存储单元

新增逻辑记录为：业务权限策略/覆盖及版本、发布预览、不可变发布版本及安全正文、访问授权及摘要/代次、成员上传的来源元数据、Mock 命中日志和协作审计。沿用既有 DB/ID 与受控二进制存储方式；大正文不进入列表/审计行。

发布时原子检查项目存在、操作者权限、固定源身份/策略版本、候选摘要及项目/部署配额，然后写版本、计费和审计。网络投影在事务外进行，提交再核对版本，不在持有项目行锁时等待 Node。并发同一 `publicationIntentId` 返回同一固定结果；相同意图改变来源/候选则冲突，网络中断不自动换意图重复发布。

访问在同一权威读取中取得授权状态与对应正文身份；撤销在请求准入处线性化。删除/清理必须与活动引用和授权关系协调，不出现“返回 200 但正文已被清空”。这仅为新分享路径要求，不冒称修好了旧下载接口的延期项。

备份包括发布正文、授权摘要、策略、计费及必要审计；Node 缓存无需备份。恢复后仍按当前数据库时间校验到期，不因重启延长 TTL、启用暂停对象或恢复已撤销秘密。保持单站 Java＋单协作运行服务的首版部署，不无证据宣称多副本全局限流。

### 10.2 对外接口面

| 接口面 | 主要操作 | 授权 |
| --- | --- | --- |
| 成员项目历史 | 列表/过滤、读取安全报告、显式上传单项、删除本人上传或管理员处理 | 登录＋项目可见＋history 对应权限 |
| 发布管理 | 预览、确认发布、版本列表、创建/撤销/轮换授权、停用/删除版本 | 登录＋publication/mock 对应权限＋期望版本 |
| 项目业务权限/协作策略 | 读取有效值及来源、管理员版本化修改 | 对应工作区/项目管理员 |
| 公开 `/s/{publicId}` | 固定页面、查看专用 DTO、获准下载 | 仅专用分享认证；不得放行整个 `/api/v1/**` |
| 公开 `/mock/{publicId}/…` | 有界 HTTP Mock 调用 | 专用 Mock 调用认证，每次独立核验 |
| 审计/Mock 日志 | 有界分页、按对象/操作者/时间过滤 | 对应 read 权限，无秘密值 |
| 内网协作 RPC | 有限 Core 派生/匹配操作 | 部署秘密、固定协议与构建身份，不作为用户 API |

建议成员端点归在 `/api/v1/workspaces/{ws}/projects/{project}/collaboration` 下；公开入口的静态页与受控数据路由有独立过滤器/Host 限制。现有 AuthFilter 对其他业务路径的要求保留，不能以公开浏览器页为由放开内容或 Runner 路由。

### 10.3 错误与审计

稳定错误包括：权限不足、源/项目版本冲突、源结果未归档/已到期、格式不支持、预览到期、投影不满足策略、容量超限、授权无效、发布停用、运行服务不可用、Mock 未命中及处理超时。UI 显示可理解的原因和安全下一步；没有结果就不能显示成功，也不指导用户通过放宽敏感信息限制绕过拒绝。

新增管理事件包含成员/ACL 与业务权限变化、脚本修改（只记位置/摘要）、凭据绑定变化（仅引用/版本）、发布/授权/换钥/停用/删除、Mock 配置及策略修改。关联 actor、scope、对象与修订、动作、结果、原因码、时间和相关 ID；不记录秘密、完整请求、脚本正文或内部快照。成员/ACL 的既有操作从接入后开始记，不补造过往记录。现有 execution 审计按真实可关联范围展示，不能靠猜测映射到项目。

必要管理变更与审计在相同事务成功或失败。高频访问/Mock 命中明细可有界异步/聚合，允许关闭或过期，但页面明确其完整性，不将缺失明细当“没有访问”。审计留存不是不可篡改合规账本承诺。

## 11. 页面与日常使用入口

- **客户端在线项目：** 增加清晰的“协作与分享”入口；历史/报告提供“发布到项目”或“创建分享”快捷动作，文档/Mock 提供已保存版本选择及预览。选中项目、来源、执行位置、版本、范围、大小、遮罩/未采集说明、有效期和受众在确认前可读。
- **Web 管理台：** 在项目管理下放“协作权限与策略”“发布与分享”“共享 Mock”“审计”；工作区显示上级策略和允许能力，平台显示部署就绪与公共入口。管理员管理基础策略，日常契约/规则编辑仍在客户端，不把业务编辑搬到 Web。
- **公开只读页：** 默认中文，可切 English；固定侧栏目录/搜索，右侧内容独立可读。报告先显示真实结论、统计总体、时间/时区和完整性，节点/轨迹用表格/时间线，原始安全数据次级且默认折叠。文档保留契约、模型、示例及受支持片段，不提供真实接口发送按钮。
- **版本/状态：** 发布版本用简短递增号，定义/内容指纹短显且可展开完整值。时间到三位毫秒并显示时区；到期倒计时不替代绝对时刻。未配置、未发布、待处理、停用、撤销、到期、超额和观测缺失各自解释。
- **布局：** 长名不被按钮挤成单字符，悬停不换行或改变行高，操作用固定占位；长表局部横/纵滚动，不挤断表头。敏感配置为表单/列表，不直出 JSON。API 正文/Schema 仍可按既有约定显示原格式。
- **离线边界：** 在线能力不可用不遮挡本地设计、调试、Mock、测试、编排、压测和报告；本地操作不会自动改为上传或使用共享 Mock。

## 12. 必要验证与交付边界

以下 AC 是实施计划的验收映射，不是本次已执行测试。优先扩展现有夹具与真实行为，不新增全角色×全协议×全页面组合矩阵。

| AC | 最小验收事实 |
| --- | --- |
| AC01 来源与固定版本 | 真实代理归档报告与单项成员上传身份不同；项目编辑后旧发布内容不变，跨项目/伪造代理身份拒绝 |
| AC02 隐私上传 | 不选择就不上传；只处理选中单项；公开 DTO 无项目快照、Cookie、控制令牌、Windows/POSIX 私有路径和已知敏感值 |
| AC03 预览原子提交 | 源/权限/策略变化及超额先拒绝；同意图重交不重复建版本，更换候选冲突 |
| AC04 权限权威 | 角色/ACL/业务权限分别约束真实 API；脚本变更覆盖 delta 与旧可达文件写入口，凭据/执行拒绝不能靠 CLI/MCP 绕过 |
| AC05 分享授权 | 成员定位不授予陌生人权限；外链显式开启才可创建；文档密钥、Mock 密钥、项目/版本互不通用 |
| AC06 撤销与责任 | 已打开页后撤销/到期/换钥/发布责任人失权，下一内容读取/下载拒绝；管理员显式接管产生新授权；已下载文件不宣称收回 |
| AC07 清理与额度 | 有效授权、预览和活动引用不被驱逐；新分享路径在受控读取/清理交错中只有完整有效正文或明确拒绝，没有 200 空正文 |
| AC08 文档可读 | 复用 Core 选定范围与依赖；未知/不支持内容有定位，浏览/搜索/锚点/复制不触发请求或执行用户 HTML |
| AC09 共享 Mock 语义 | 同一合成配置经本地与共享宿主匹配得到同一受支持响应/规则解释；被网关禁止的头条件在发布时明确拒绝，不静默改写规则 |
| AC10 Mock 生命周期 | 桌面关闭仍可调用；代理离线不影响协作运行服务；停用、调用取消、Node 重启及超额如实失败、不补发、不泄露控制认证 |
| AC11 公开入口隔离 | 公共 origin 不能读管理台身份/管理 API；密钥不进 query、请求路径、日志、下载；不可信正文不执行为管理源内容 |
| AC12 审计 | 真实权限/分享/密钥绑定操作有同事务、无秘密值的审计；Mock 调用权不能读日志，关闭/丢失明细正确说明 |
| AC13 本地化与布局 | 新增客户端、管理台、公开页集中真实中英文验收，默认摘要/表格可读，长名/时间/数字不撑坏布局，不以字段存在代替通过 |
| AC14 部署与回退 | Java＋Node 可选组合实际启动；错秘密/错版本/Node 断开明确拒绝；未启用协作不破坏原 Java/代理及本地路径 |

实施采用测试先行：每批先列需要保护的真实分支并核对有效失败原因，不能把模块缺失/接口 404 当作业务判断已先红。后补/变异验证按实记录，不自动沿用以前接受的顺序偏差。研发与独审按既有 Sol high／Sol xhigh 配置；复杂问题需升级另申请，不以准备工作自动派生多个宽审轮次。

最终候选集中安排一次必要全量门禁、真实 Java/Node/浏览器及原生联验、目录包和部署冒烟。若用户要求合并后全量，尽量将该次作为同候选最终门禁，不在产品树未变时无差别重复全量；受控故障修正只重验受影响部分，如实保留之前失败，不拼成一次全绿。生产账号、付费模型、真实项目、真实公开链接和高负载不在验收授权内。
