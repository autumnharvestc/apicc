# M9 信息架构与环境模型改造 — 设计规格（2026-09-07）

## 背景（用户六要点）

1. 环境管理创建的环境未联动接口调试的环境选择器；
2. 创建 API 报 ENOENT（名称含 `http://...` 等路径非法字符，名称直接作目录名）；
3. 环境模型重做：公用「全局变量/全局参数」，单个环境分「前置 URL（按集合设置）+ 环境变量」；
4. 层级调整：分组=组织/团队空间概念（不体现在客户端树），工作区顶层即项目；环境/测试等
   栏目归属项目；项目在顶部导航切换；插件归应用设置；最左固定主页（管理服务器/分组/项目；
   本地模式=本地服务器可建分组与项目，远程服务器分组到管理后台建）；
5. 左侧「压测」栏改为「测试」栏：单接口用例（点 API 管理用例列表，用例项可运行/压测）+
   场景用例（参考自动化测试图）；
6. 接口栏聚焦接口定义。

## 轨道拆分（顺序执行，逐轨验证合并）

### M9-A 修复轨

- **A1 环境联动**：根因 = debug 选择器读 `editor.envs`，仅在 editor.load（选中接口）时
  拉取；环境增删后不刷新。修复 = App 组合根 watch 环境清单标识（envs store 与 editor 同源
  项目）→ editor.envs 同步。附带：调试选择器空态文案。
- **A2 名称净化**：core 增 `sanitizeNodeName`：替换 Windows 非法字符 `\ / : * ? " < > |`
  与控制符为 `-`、去首尾空格与结尾点、限长 80、空结果回退「未命名」。接入点：desktop
  session 的 create*/rename*、core 导入 apply（导入名不可阻断批量流，统一净化）。
  测试：session 各 create 用例 + 导入用例。

### M9-B 环境模型轨

- core domain：`Environment.baseUrls?: Record<collectionId, string>`（缺省 {}，旧数据兼容）；
  `Workspace.globals?: { variables: Record<string,string>; headers: KV[]; query: KV[] }`
  （缺省空，workspace.yaml 兼容旧文件）。
- 生效点（core runner 内，桌面/CLI 同享）：CollectionRunner 运行集合时——
  ① 注入内置变量 `baseUrl` = env.baseUrls[当前集合 id]（{{baseUrl}} 模板继续可用）；
  ② workspace.globals.headers/query 追加到每个请求（请求同名项优先）；全局 variables 并入
  变量链（环境 > 全局）。
- UI：环境面板重做为「环境管理」：左侧锚点（全局变量/全局参数/环境清单+新建环境）；
  环境详情 = 前置 URL 表（当前项目集合清单 × URL）+ 环境变量表；全局页 = KV 表。
  显式「保存」与「保存并关闭」。

### M9-C 层级调整轨

- rail 模块收敛为：**主页（固定最左，恒可用）| 接口 | 测试（M9-D）| 环境 | 工作流 | 导入**；
  插件移出 rail → TopBar 齿轮 → 设置抽屉（插件管理 + 关于）。
- 主页视图：本地服务器卡（当前目录名 + 打开本地目录/新建本地目录〔原 TopBar 按钮迁移〕+
  分组清单〔可新建〕+ 各分组项目〔可新建/打开〕）；远程服务器卡（在线档案：登录状态、
  工作空间=团队分组清单〔客户端只读，提示至管理后台创建〕、打开 → 进入在线模式〔既有链路〕）。
- TopBar：工作区徽标 + **项目切换下拉**（本地工作区全部项目；选中 = tree.select(project)）
  + 在线模式 + 齿轮 + 语言/主题。
- SideTree 项目作用域化：新增 activeProjectId，树仅渲染该项目子树（集合在顶层）；
  分组层只在主页出现。selectedProjectId/selectedCollectionId 派生改为自 active project。
- 导入向导「目标分组」保留（本地分组=存储层团队目录，在主页/导入处管理）。

### M9-D 测试模块轨

- viewSwitch：移除 stress 模块与 api 子视图 cases；新增 `test` 模块。
- api 模块子视图收敛为：调试 / 设计（用例页签移出）。
- 测试视图：左子导航（单接口用例 = 当前项目集合→API 树；场景用例 = 项目工作流清单）；
  右侧：选中 API → 用例面板（增删用例项；每条用例行「运行」= debug.send 指定 case、
  「压测」= 切换测试模块内嵌 StressPanel 并绑定该 api+case）。场景用例项「运行」=
  切工作流模块载入；场景级性能测试（并发/时长/爬坡）**延后入账本**（需场景压测引擎，
  本轨不做假入口）。
- StressPanel/stress store 原样复用为测试模块内嵌视图（接口级门控改由测试上下文绑定）。

## 测试与验证

- 每轨：desktop 全量测试（基线 551）+ core/cli/server 不回归 + build + 打包冒烟四道底线；
  M9-B/M9-C/M9-D 完成后追加真机 CDP E2E（环境联动、导入-调试 base URL、主页建项目、
  测试模块用例运行）。
- 兼容：旧工作区（无 baseUrls/globals）打开零迁移；导入旧文件零破坏。

## 裁定记录（用户离线，沿用常设授权）

- D1 分组保留为存储/权限概念：本地分组在主页与导入向导管理，不再出现在侧树。
- D2 场景用例复用工作流引擎展示与运行；场景级压测延后（不做假按钮）。
- D3 全局参数仅 query/header 两栏（body 全局参数延后）。
- D4 baseUrl 双通道：相对 URL 自动拼接 + 内置 {{baseUrl}} 变量（兼容既有模板习惯）。
- D5 插件入口 = TopBar 齿轮设置抽屉（MVP 不做独立设置页路由）。
