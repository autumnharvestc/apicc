## 3. 方案比较与范围

### 3.1 已选择方案

| 方案 | 收益与代价 | 结论 |
| --- | --- | --- |
| A：只适配现有本地 MCP | 改动较小，但在线资产、代理任务和在线报告仍不可经 MCP 使用 | 用户未选 |
| B：本地及受控在线 MCP，共用执行契约 | 需要成员会话及宿主编排复用，能覆盖现有在线能力，不引入新的执行内核 | 用户已选 |
| 当前调用宿主：个人配置、客户端/CLI 调用 AI | 复用个人设置，无共享密钥下发或新增后端 AI 服务 | 按用户批准边界采用 |
| 团队共享与后端 AI 代调用 | 可做集中密钥、额度及无人值守处理，也引入服务端出站、授权、审计和费用治理 | 用户明确入池暂不实现 |

### 3.2 本期包含

- 三协议可替换适配与分层个人配置；声明式供应商模板、模型手工配置和可选发现。
- 本地/在线项目的用例及断言建议；指定现有报告的主动解读，不自动重跑。
- 可读、可取消、不会错项目采用的桌面交互；CLI 只输出候选/分析文件，不自动改项目。
- MCP 项目资产、设计和报告的有界读取；本地或指定代理运行已保存用例、套件、工作流的显式入口。
- 必要的迁移、最小受影响测试、集中真实页面/MCP/代理联验、独立审核和一次候选门禁安排。

### 3.3 非目标与反目标

- 不实现团队 AI 网关、共享 AI 密钥、后端自动 AI 分析、对话机器人、向量库或全项目自动巡检。
- 不做 AI 自动创建/启用定时任务、自动改权限、自动保存/覆盖资产、自动替换断言使失败变绿。
- 不新增 MCP 公网 HTTP 服务、任意文件读写、Shell/SQL、任意 URL 自由请求或压测启动工具。压测报告可读、可分析，不等于授予高负载执行权。
- 不恢复 DEF-001，不提前实施 F7f/F7g，不把 F7b 的三项遗留带进本阶段。
- 不能把“支持三种协议”说成支持各供应商全部托管工具、音视频或所有参数。首版范围是有限文本输入与结构化候选/分析输出，无供应商自动工具循环。

## 4. 分层配置、归属和未来扩展

### 4.1 四层数据

| 对象 | 关键数据与责任 | 不承担的责任 |
| --- | --- | --- |
| `AiProviderTemplate` | 稳定 ID、格式版本、名称、默认 API Base URL、允许协议、默认协议、鉴权档位、非敏感必需请求头及可选模型发现能力 | 不含 key、不执行脚本、不直接控制业务资产 |
| `AiConnection` | 本机稳定 ID、自增修订、模板 ID/版本来源、实际 Base URL、启用协议及鉴权选择、凭据引用、可选专用网络参数 | 不随模板文件变化自动重定向；不存项目 API 的认证值 |
| `AiModelProfile` | 稳定 ID、自增修订、连接 ID、真实模型 ID、选定协议、结构化输出模式、独立上下文/输入/输出能力及实际使用默认预算 | 不按模型名称猜能力，不把供应商模型目录视为已验证能力，不以应用默认值冒充模型真实上限 |
| `AiPurposeBinding` | `case-suggestion`、`assertion-suggestion`、`report-analysis` 的默认模型；可在本次调用覆盖 | 不自动降级到另一个供应商、模型或网络 |

模型支持手工填写；同一连接可有多个模型，同厂商可有多个官方/企业网关连接。模型发现为显式按钮，拉取失败不阻止手工配置。未配置模型时展示引导，不预填会产生费用的真实模型选择。

个人设置位于宿主私有配置根，凭据另存秘密存储；不进工作区文件、在线项目资产、日志或导出。用途默认保存在个人配置中；项目用途覆盖也只在本机个人偏好中记录，按本地完整项目定位或在线服务器/成员/项目定位分开，不同步成对其他成员无效的个人模型 ID。

### 4.2 模板的配置式扩展

建议交付应用自带 `providers.v1.json` 目录及个人 `~/.apicc/ai/providers.d/` 配置覆盖层，桌面允许选择导入同一格式。实际宿主私有根可按部署指定；文件位置、重载方式在使用说明列清。

- 自带最小模板为 OpenAI（Chat Completions、Responses）和 Anthropic（Messages）；“自定义”允许从三种已实现协议中选择。不承诺未验证的其他厂商原生协议。
- 配置严格校验 ID、版本、URL、协议和能力字段。模板只能引用程序已注册的适配器，不能夹带 JS、插件安装、任意请求体表达式或凭据值。
- 官方/自定义模板遵循相同加载器；新增同协议厂商不改业务代码或重新编译。首版提供导入/显式重新加载，不做远端自动下载或动态执行模板。
- 自带模板不可直接编辑；覆盖/导入前显示差异和冲突。重载失败保留最后有效目录，并列出错误文件/字段，不把坏配置静默当默认。
- 新建连接复制模板的具体值并记录来源；之后模板更新只提供“查看更新/选择应用”，不改变已有连接。删除模板不删除已建连接。

### 4.3 URL、鉴权与秘密

统一约定 Base URL 是包含版本/网关前缀的 API 根。例如 OpenAI 和 Anthropic 官方模板均以各自 `/v1` 为前缀；适配器追加 `chat/completions`、`responses`、`messages`。只去尾部斜杠，不猜删用户网关路径；设置页展示最终生成地址，防止 `/v1/v1`、前缀丢失或把完整方法 URL 当根。

- URL 禁止用户信息、query、fragment；默认 HTTPS、TLS 校验不关闭。回环 HTTP 测试端点须显式选择“不安全本地测试”并提示；不以测试需求关闭系统证书校验。生产控制后端/代理沿既有 HTTPS 边界。
- 鉴权档位为 Bearer、API-key 请求头、显式无鉴权（仅本地测试）；可在允许的具名头中绑定秘密引用。`Host`、`Content-Length` 等传输头不能任意覆盖，禁止 CR/LF。模板请求头只含非秘密默认值。
- Anthropic 版本头由模板提供可见默认值，允许合法配置覆盖，不把版本写死到业务调用流程。
- 秘密按连接及实际地址/鉴权受众绑定。只改显示名可保留；改地址或鉴权受众必须重新确认并提供/重新绑定凭据，不能把旧 key 默默发往新地址。渲染层只读到凭据存在/缺失/不可用状态。
- 保存配置不联网；连通性测试、模型发现、生成各自显式触发。测试连接使用最小固定提示，不发送项目资料，并说明仍可能产生供应商费用。
- 新连接秘密使用宿主安全存储。不可用时仅允许显式会话内使用或拒绝持久保存，不自动落明文；CLI 支持秘密环境变量/标准输入或 OS 安全存储，不新增 key 命令行参数。

### 4.4 扩展接缝而不是空功能

分开 `AiConfigRepository`、`AiCredentialResolver`、`AiInvocationHost` 和协议适配器。业务用例只提交用途、固定模型引用、投影上下文及预算，不依赖 Electron、HTTP 后端或 key 的存储位置。

本期只装配个人配置解析与本地调用宿主。连接记录显式个人归属，接口允许以后解析其他归属，但不注册未实现的 team/backend 模式、不放不可工作的切换控件。未来 AI-FUTURE-005 通过新增受鉴权宿主/解析器复用相同业务校验；后端出站授权与 SSRF 等届时另设计，不声称已实现。

### 4.5 应用默认、模型能力和实际调用额度

“应用级”指当前个人/设备的共同默认与资源保护，不是团队共享策略。本期不因此新增在线管理员 AI 配置。下列层次必须分开，不能把一张全局参数表套到所有模型上：

| 层次 | 内容 | 修改与继承 |
| --- | --- | --- |
| 应用默认值 | 各用途总期限、请求/修复次数、默认输入/输出预算；共用并发、队列和缓冲保护 | 当前设备统一管理；默认值可被模型/用途/本次配置覆盖，共用资源保护不能被下级突破 |
| 模型能力声明 | `contextWindowTokens`、可选独立 `maxInputTokens`、`maxOutputTokens`、窗口是否输入输出共用、输出是否含推理 Token，以及出处/确认状态 | 每个模型独立配置，可从具备数据的模板/发现结果预填，也允许手工填写；无数据明确标“未确认”，不能当成无限容量 |
| 模型默认使用额度 | 默认输入 Token 预算、输出 Token 预算、输入 UTF-8 字节及合并结果字节预算；允许按用途分别覆盖 | 未填写的项继承应用对应用途默认；已填写的值只作用于这个模型，不修改其他模型 |
| 用途/本次选择 | 对已选模型及用途调整本次预算 | 不修改模型能力声明；仍受应用保护、协议/模型能力和剩余总预算约束 |

预算优先级为：本次显式值 > 当前用途/个人项目覆盖 > 模型对应默认值 > 应用用途默认值。模型能力不是这个覆盖链的一环，而是最后必须满足的约束；应用资源保护也独立校验。保存或调用中的显式配置不满足约束时，列出冲突字段、来源和可用值，不能偷偷缩小或增大。

对纯继承的应用默认值，可按已确认模型能力派生较小的有效默认，并显示“继承应用默认，受模型限制”；用户显式填写的超限值不能这样静默裁剪。比如应用默认输出 16384、模型声明最大输出 8192，则该模型的继承有效默认为 8192；这不把模型能力改成 16384，也不改变另一模型的预算。

上下文窗口和本次输入预算不同：前者是模型容量，后者是本次愿意发送的资料量。对于输入输出共用窗口的协议/模型，完整输入 Token（包括系统指令、Schema、补充指令、修复历史等）加上预留生成 Token 不得超过声明窗口；有独立输入上限时还须满足它。协议口径为分别限制时按各自规则校验，不强套一条相加公式。

优先使用与模型匹配的可用本地计数；没有可靠计数器时显示估算和安全余量，不把 UTF-8 字节固定换算成精确 Token，也不承诺本地一定能证明窗口可用。模型能力未确认时使用保守的使用预算并标记未验证，较大配置需用户明确填入能力声明；一次小请求成功不等于完整上限已验证。本期不为计数自动外发额外项目资料。

应用的上下文字节/输出字节是本机载荷和缓冲保护，不是模型 Token 能力。模型可分别设置更合适的字节预算，须在应用配置的保护范围内；声明大上下文不代表默认外发整个项目。所有最终配置显示有效值及来源，在开始调用时固定。

例如应用默认输入 256 KiB、初始允许上界 4 MiB，某个模型可独立选择 1 MiB 作为使用预算，另一个仍继承 256 KiB；1 MiB 不是对应用保护的突破。模型未填独立输入 Token 使用预算时，仍受完整输入字节和已声明模型窗口/输入上限约束，不能把可选使用预算留空解释成无限输入。

## 5. 三协议与一次调用的共同契约

### 5.1 适配边界

共同调用输入包含用途、协议版本、模型配置快照、文本消息/输出 Schema、总 deadline、取消信号及额度；宿主解析 key 后交适配器，结果统一为文本/结构化结果、终态、供应商 request ID 和可用用量。协议原始响应不直接成为页面主视图。

| 协议 | 请求/解析约定 |
| --- | --- |
| OpenAI Chat Completions | `messages`；结构化参数按配置能力使用 `response_format`；解析文本 choices 及结束原因，不把工具调用当候选 |
| OpenAI Responses | `instructions/input`；结构化格式使用 `text.format`；遍历类型正确的文本 output 项，不把 reasoning/tool 项拼成正文 |
| Anthropic Messages | 独立 `system`、`messages`、输出 token 上限和版本头；读取文本 content 块及 stop reason；支持时用 `output_config.format` |

供应商兼容模式提供 `json-schema`、`json-object`（适配器确实支持时）和 `prompt-json` 三档；按配置选择，仍统一执行本地严格 Schema/业务校验。接口不支持某档时提示修正配置，不在收到 400 后无声换协议、换厂商或剥掉约束。

不发送未启用的 temperature/推理等参数。模型档案声明受支持的参数；输出上限字段由协议/兼容档位映射，不允许无限制原始请求体透传。OpenAI 流程显式请求不保存响应状态，不使用供应商持久对话或托管工具；这不等于保证第三方服务零保留。

首版支持三协议的流式传输，但业务结果在完整接收、终态及严格校验成功后一次性交付；不把半段 JSON 当可采用候选。界面可显示排队、已用时间、当前尝试及接收状态，不展示伪造进度或要求模型暴露隐藏推理。这里的模型响应流式不改变 runner-agent 的长轮询方案，也不是新增 MCP 公网长连接服务。

模型/网关明确不支持流式时可配置非流式兼容模式；长请求提示其空闲连接风险，失败不自动切换协议或模式。流式解析处理合法事件、终态、流中错误和 EOF 未完成；HTTP200 或收到部分正文不等于成功。只保留本用途需要的有限结果，不为展示缓存全部原始事件。

拒绝、截断、工具调用、异常终态和非法响应分别报告；超长/未完成输出不能截一段当成功。只对完成但结构非法的输出做预算内修复，修复时不得重新扩大上下文或添加权限。流中断不自动接龙、重发或拼装不同生成的残片。

### 5.2 额度与生命周期（用户接受重评方向，R1 具体化）

所有额度在调用开始固定，设置页显示单位、范围、有效值/来源及生效方式；CLI 对应参数使用同一校验。下表是应用初始默认及允许的产品配置范围，模型可独立设置相应预算，解析规则见 §4.5；并非所有项都是模型可覆盖的参数。并发、队列、总缓冲等为共用宿主资源保护。这里不冒称团队跨进程全局配额或精确供应商计费控制。

| 参数 | 建议默认 | 可配置范围/说明 |
| --- | --- | --- |
| 用例/断言/报告分析总期限 | 10 / 5 / 15 分钟 | 各 10 秒–2 小时，涵盖排队、退避、读流/读体及修复；从用户确认发送进入队列开始，不把审阅发送预览的人类时间算入 |
| 单次模型请求期限 | 5 分钟 | 10 秒–1 小时，每次有效值还受剩余操作总期限限制 |
| 连接测试期限 | 30 秒 | 1–180 秒；固定最小输入/输出，连通不等于模型全部能力已验证 |
| 模型发现期限 | 15 秒 | 1–120 秒；失败仍可手工配置模型 |
| 一次操作总请求次数，含首次 | 3 | 1–10；所有重试及修复共同消耗，不相乘；超过 5 次给费用和等待提示 |
| 传输自动重试 | 1 | 0–9，受总次数/期限限制；仅明确允许的可重试拒绝/故障，网络结果不确定不自动重发 |
| 结构修复次数 | 1 | 0–3，受总次数/期限限制；不对拒绝、截断或取消进行修复 |
| 同宿主并发调用 | 1 | 1–8；等待队列默认 8、范围 0–32；排队也受总期限约束 |
| 完整输入上下文 UTF-8 字节 | 256 KiB | 4 KiB–4 MiB；模型默认可覆盖，仍受应用保护及模型 Token 限制；不得静默丢关键证据 |
| 用户补充指令 | 8 KiB | 1–64 KiB，纳入完整输入预算 |
| 合并后模型结果字节 | 4 MiB | 64 KiB–32 MiB；模型默认可覆盖，接收时计数，不在无界 `.text()` 后才检查 |
| 普通模型单次输出 Token | 断言 8192，用例/报告各 16384 | 初始产品允许 16–262144，且不超过实际协议/模型声明上限；模型独立配置，不支持字段映射则拒绝 |
| 输出额度包含推理预算的模型 | 32768 | 仍在上述产品/模型范围内独立配置；不按品牌或名称自动推定口径 |
| 整次操作生成 Token 预算 | 初次配置为对应单次上限的 3 倍 | 可在 1–10 倍单次上限内独立设置；调高请求次数不自动增加该预算，改变模型/单次额度后须显示并确认冲突，不静默扩容 |
| 单次用例/断言候选数 | 5 / 10 | 各 1–50；输出也须校验上限，不先接收无限数组再截断 |
| 报告证据项 | 20 | 1–200；提示所选/总计及缺失，不随机补证据 |

262144 是初始产品防误配置上界，不是所有模型的能力，也不是协议永久硬上限；应用保护上界允许通过受校验的高级配置提高，须重新确认预算/资源，不能由模型响应或供应商目录自动提高。模型真实能力声明可大于当前应用可用额度，界面分别显示，不伪造二者相等。

在输出额度包含推理的协议中预留推理部分；业务结果字节限制独立生效。整次操作预算按每次请求发送的生成上限保守预留，用量明确时按对应口径结算；用量未知不按零返还。它是可发请求额度，不是金额上限，输入 Token 等费用仍须另算。

429/明确允许的短暂故障的退避仅在开启重试且总期限允许时进行；认证、参数或长期额度不足不盲目重试。尊重合法有界 Retry-After。若使用 SDK，关闭或纳入其内置重试；不能出现外层 3 次、内部又各重试 2 次的隐形请求。业务测试执行不使用 AI 请求重试策略。失败消息显示错误类别、状态、可查 request ID 和建议，不回显原始供应商错误体中的 key、完整提示或项目正文。

补充流式资源细则作为作者建议：默认单事件上限 256 KiB（可配 16 KiB–4 MiB）、单次累计流量 64 MiB（1–512 MiB）、同宿主在途载荷缓冲预算 64 MiB（16–512 MiB）。帧头、未完成行、错误体和中间片段同样受界；无界心跳不能绕过总期限/流量预算。这些保护约束协议载荷和缓存，不冒称 Electron/Node 总内存硬限制。缓冲不够时排队/拒绝，不突破预算；值还须经实施阶段必要边界验证，不是性能实测结论。

所有外发实现遵循 redirect 拒绝和信号传播，取消后停止队列/读体/修复；迟到结果不更新当前会话。用量仅展示供应商返回的明确计数；未返回写“未提供”，本地估算不能标作实际费用或精确输入 Token。

## 6. 上下文、候选与分析结果

### 6.1 固定来源与外发检查

引入纯数据的 `AiSourceBinding`：来源类型、本地真实根/在线规范服务器与成员作用域、项目及资产稳定定位、定义/资产版本、编辑代次或报告 ID/摘要。主进程/CLI 宿主独立检查来源，不能仅相信 renderer 给出的项目名或 API ID。

- 本地建议使用宿主项目快照，允许显式覆盖“当前接口”的已校验编辑草稿，标记未保存；其他资产未保存编辑不偷偷合并。覆盖只针对当前完整 locator，不能把 renderer 对象当任意项目读取请求。
- 在线建议通过当前成员授权读取相应版本的项目，再叠加当前接口草稿；切换登录成员、服务器或项目后旧结果不可采用。旧格式资产不可写时只给可读解释，不借 AI 绕过只读限制。
- 契约投影沿用 `contractAiView`，只遍历相关引用闭包，保留循环/缺失引用事实；不用整个工作区当默认提示。契约、模型、公共组件和现有用例来自同一来源快照。
- 不解析或外发项目秘密存储值、token、证书私钥、附件文件内容、本机绝对路径或数据集全量行。参数值、示例、文档等仍需已知字段/文本脱敏；启发式脱敏不能保证发现所有用户自定义秘密。
- 发送前可读预览目标供应商/地址/模型、用途、所选资产、预计字节、包括/未包括的正文和脱敏情况；用户显式确认后才调用。契约/示例/响应正文以不可信资料处理，不从其文字提取执行授权、URL、key 或工具动作。
- 报告正文默认不包含请求/响应 body、数据行值与脚本全文；按需勾选现有安全证据的有界内容，不能重新读取原始秘密填回已脱敏或省略的信息。上下文预算不足先缩小选择。

### 6.2 用例建议与采用

候选包含名称、范围、参数、断言、正式前后置操作及理由/来源；逻辑数据与说明分开校验，兼容当前 `AiSuggestedCase` 正式资产子集。用例、断言及新操作 ID 由本地生成，AI 返回的资产身份不作写入依据。

默认不勾选。用户可查看每条具体参数、断言目标/操作符/期望、操作内容和覆盖场景，而非只有“断言数量”。操作脚本使用业务源码查看器，附受信脚本风险提示；不是 JSON 元数据主视图。

采用只把所选新内容追加到原目标的编辑草稿，标 dirty，保存仍走已有版本/权限校验。新建议不能替换已有用例、改既有 ID、删除断言或自动触发执行；命名/语义重复可提示，由用户取舍，不靠覆盖去重。

采用前重新检查当前项目、编辑代次、相关内容摘要和配置/来源绑定；变更后显示“来源已变化，请重新生成”，不偷偷跨版本重放。在线保存冲突仍走原冲突处理，不因候选曾经生成成功而覆盖新版本。

### 6.3 独立断言建议

入口位于已有用例的断言区域，目标必须是当前明确选择的用例；可选择契约作为依据，或用户选定的一次现有响应/报告证据。不会为收集响应自动发送请求。

候选区分“契约依据”和“观测建议”，列出目标、操作符、期望、路径、理由及证据。观察到一次 503 不等于契约允许 503；缺少业务意图时要求用户判断，不生成“永远通过”的修复。

仅允许当前 Core 注册且本上下文支持的声明式断言；插件操作符需有真实描述和能力，不凭模型名称猜支持。采用追加新断言到目标用例草稿，不自动修改既有 expected 或测试结论。

### 6.4 失败与压测报告解读

入口只在已存在且可读的报告详情。分析目标绑定具体报告及摘要；比较分析仅接收已通过现有可比较性判断的一对报告，不由 AI 推翻环境/定义不一致提示。

可读结果结构为：主要结论、已观测事实、可能原因、证据定位、建议核查步骤、限制/未采集项。事实数字由程序投影，模型只引用合法 evidence ID；未知证据引用拒绝，不能把模型编出的统计当报告原值。

- 功能报告保留逻辑结论、真实请求失败、节点/数据行、重试/恢复/cleanup 等事实；引用可跳到原报告位置。
- 压测分析保留计划/实际负载、生成器饱和、指标完整性、阶段、观测窗口与阈值口径；缺失/不可计算不能补零。不能自动调大 VU、并发、速率或开始新任务。
- 已脱敏/截断/旧报告缺失上下文必须说明；不给无证据的确定根因结论。
- 结果只保存在当前分析会话；用户可显式导出分析副本，注明模型、生成时间/时区、来源摘要及“AI 辅助”。不改原报告、原 verdict、签名/摘要或将分析写回可信执行证据。首版不改离线 HTML 导出器；可从报告页查看分析后定位原证据。

CLI 保留 `ai suggest-cases`，新增同语义的断言候选及报告分析命令，按稳定定位/受控报告选择读取；输出到 stdout 或用户显式 `--out` 的独立候选文件，不写接口。已有输出文件需显式覆盖确认/参数，AI 密钥或源正文不进默认诊断日志。

## 7. 桌面配置入口与可读性

统一主入口为顶栏齿轮“设置 → AI 与模型”，主页、本地和在线状态均可达；窄窗口沿用现有“更多 → 设置”。设置不因项目只读、无接口选中而消失。

设置按“连接与供应商”“模型”“用途与额度”分节/分步表单，列出模板来源、实际地址、协议、凭据状态、自增修订及生效范围。应用默认/保护和每个模型的能力/使用预算分开编辑；展示继承、覆盖、模型限制或应用保护导致的有效值，支持将某个模型参数恢复为继承。个人/当前设备标签明确；不出现尚未实现的团队共享、后端调用开关。

业务页面只显示当前用途模型、此次发送范围以及“管理模型”。管理入口打开同一配置数据源并可返回原工作，移除接口头部重复的大配置按钮；用例和报告业务入口仍严格绑定当前项目，主页只可管理配置，不可发送业务请求。

固定文案中英文齐全、单位可读；密钥不回填。长模型名/地址可查但不挤断按钮和表头；配置及候选主视图用业务字段，不用 JSON/pre。API 原文、Schema 和脚本源码可保留专用源码查看。

没有项目、配置未完成、无读取/修改权限、任务取消、输出不合法、证据不足、来源过期分别提示，不能都归成“AI 失败”。配置修改只影响后续调用，已有调用使用固定配置；调用完成后对旧业务来源仍须校验。

## 8. MCP source、身份与可见数据

### 8.1 部署方式与会话

首版继续 stdio，SDK 处理 JSON-RPC。stdout 只有协议帧，诊断走 stderr。启动时互斥选择本地工作区 source 或在线连接 profile，不在工具参数中接受任意服务器地址/文件根；当前 source 不随模型文本切换。

在线 profile 使用单独的成员登录引导命令和既有 `/auth/login`、`/me`。密码通过交互隐藏输入或受控 stdin，不进 argv；只在 MCP 启动前进行，不能占用 MCP 的协议 stdin 做交互登录。会话 token 使用 OS 秘密存储或显式进程环境注入，不导入 Electron 私有 token 文件，不保管成员密码。

profile 固定规范服务地址、成员身份与允许的工作区/项目。每次工具调用/分页/启动重新受服务端鉴权；401/403 终止并给重新登录指引，不自动换账号。注销/换连接使旧 cursor、准备票据和来源绑定失效。不得把普通成员 token 当 agent token，或把任何身份 token 暴露为工具返回值。

成员执行请求复用安全 HTTP 边界：HTTPS、redirect 拒绝、超时/取消、有限响应、稳定错误码。回环 HTTP 只用于隔离管理台/替身验证，不扩大现有生产控制协议。CLI 子进程环境不继承 AI/成员 token；受信脚本的既有限制不因此宣称强隔离。

### 8.2 工具集与兼容

| 工具 | 数据/行为与边界 |
| --- | --- |
| `list-apis`、`get-api-design` | 保留现有本地名称、完整 UUID `apiPath` 和原必填参数；在线 source 按固定 profile 作用域映射稳定定位 |
| `list-assets`、`get-asset` | 读取接口、模型、组件、用例、套件、工作流及数据集的必要结构；数据集默认只有列结构/行数，不提供全量行或文件附件 |
| `list-runs`、`get-run`、`get-report` | 项目范围内有界历史、状态及既有安全报告投影；报告来源/格式/完整性明确，默认不含业务正文或秘密 |
| `prepare-run`、`start-run` | 仅 `--allow-run` 时注册；针对已有 case/suite/workflow，固定 source、项目、版本、环境、位置及预算，先可读准备再显式启动 |
| `cancel-run` | 仅执行权限启用时注册；按当前服务端权限取消明确的运行，不批量取消或修改计划 |
| 旧本地 `run-case` | 保留 `--workspace --allow-run` 的现有单步单用例兼容；明确一次调用就是一次真实执行。新增在线模式不提供这个可跳过准备的别名，统一使用 prepare/start |

旧本地 `run-case` 保持未选环境仅 base 的限制；新 prepare/start 可显式选择环境。旧模式不被静默切成线上或指定代理。新工具读写权限不靠 annotations 决定；其只读、外部副作用及幂等提示必须符合实际，工具描述不是授权依据。

新工具以结构化对象及相应可读文本返回来源、分页/截断状态、业务字段和限制；供机器使用的结构化 JSON 不受页面禁用 JSON 主视图的约定禁止。旧工具保留核心文本字段，新增分页不静默少返回：旧 `list-apis` 无分页参数时仅在整体结果可满足预算时沿原数组返回，超限明确要求使用分页；显式分页时返回 envelope，文档标明该形状。

`list-assets` 等默认每页 50、范围 1–200；单次 MCP 输出默认 128 KiB、范围 4 KiB–1 MiB。cursor 绑定 source、成员、项目、源修订和查询，不接受路径；修订变动要求重新开始。不依靠无界枚举/完整序列化后截断来守预算。核心统计保留，正文省略可见，不能把半段 JSON 当完整结果。

### 8.3 本地与在线报告读取

本地只读加载明确工作区；报告限于该工作区 `.apicc/runs` 的现有目录和本次 MCP 私有运行目录，使用列表返回的 opaque ID 选择，不开放任意 file/path 参数。校验真实路径/符号链接边界以及报告项目身份；旧报告不能证明属于当前项目时显示不可归属，不按名称猜测后外发。

在线所有 job/report ID 再核对 server、成员授权、工作区/分组/项目及执行身份。未归档/到期/已清理/损坏分别报告，不能把 HTTP200 空正文当成功报告。本期不顺带改 F7b 已延期的报告清理原子性；碰到该已知竞态如实报不可读，不偷偷重新执行。

资产读取和外发使用同一可复用安全投影：认证只给种类/引用存在情况，URL凭据及敏感示例/参数脱敏，脚本内容/数据集行/请求响应 body 默认不含。用户可显式请求允许的安全正文范围，但没有读取秘密原值或恢复已省略证据的工具。

## 9. MCP 执行与共用成员宿主

### 9.1 prepare/start 与副作用

新执行入口使用两步，不是让 AI 生成内容顺便执行：

1. `prepare-run` 解析已有稳定目标及显式本机/代理位置、环境、版本；调用共同准备器检查材料、脚本批准、Core/插件身份和策略额度。输出具体将执行什么、网络位置、已知限制、配置来源、尚未满足的条件。准备可以创建既有不可变执行快照，但不发送目标接口请求，不跑前后置脚本。
2. 成功返回短期 opaque 票据，绑定成员、source、目标/输入摘要、环境、位置、版本、预算和准备代次。默认有效 5 分钟，可配 30 秒–15 分钟；同进程最多保留 32 张有效票据。准备缓存不保存秘密值。
3. `start-run` 必须显式传票据及调用者复用的 intent ID；记录消耗状态后提交。票据已变更/过期或输入不同直接拒绝；启动前仍由现有服务端权威重查当前权限、代理、材料和脚本批准。准备结果不代替最终授权。
4. 返回 run/job ID、实际位置、来源修订及状态，不阻塞到整个工作流结束；后续通过状态/报告读取。不得因超时、断线或 MCP 请求取消自动改代理/换本机重跑。

单用例目标映射到已有 `TaskTarget.kind=debug`、`DebugInvocation.mode=case`，使用完整 case locator/scope；不新增另一种服务端 case Runner。prepare 产生的不可变 snapshot、材料版本选择和准备摘要必须传给 start 复用，不能在 start 再走一次“加载最新并重建快照”。启动前发现资产版本变化则让票据失效、重新准备；已提交同 intent 的对账先于这一新启动检查，不能因此把已接纳任务误判为需要重跑。

`--allow-run` 是操作人给予 MCP 的执行许可，不声称工具调用必然经过另一次人类点击；文档必须建议外部 MCP 客户端对 start/cancel 等副作用启用人工确认。准备票据是绑定和防误操作，不是认证秘密或人类确认的证明。

本地 source 只能本机执行，代理选项明确拒绝；在线 source 明确本机或 agent ID，不能依赖随时变化的项目默认代理。仅沿原有材料来源，文件/凭据不齐时拒绝，不从模型参数接收密码或任意本机路径。环境缺省语义可读显示为 base，无“自动挑一个可用环境”。

实施接缝澄清（T8/R46）：新 prepare/start 的本地 source 使用宿主启动配置选择既有 `ExecutionProfile`，默认 `no-script`；操作人可显式选择 `trusted-core-script` 运行已保存目标中的受信脚本。该档位不作为模型工具参数，准备摘要显示实际档位和脚本限制，`--allow-run` 本身不自动选择受信脚本档位。不新增本地审批数据库或任意脚本工具；旧本地 `run-case` 保持兼容，在线 source 的本机/代理执行仍沿成员与服务端现有批准权威，不被这个离线档位绕过。

### 9.2 防重、取消与生命周期

- 在线 start 使用现有固定 `SubmitJob` 和同一 intent 防重。重复相同票据/intent/输入返回原 job；同 intent 不同输入冲突，不能创建第二次业务执行。
- 在首次提交前写入宿主私有意图回执，记录服务器/成员/项目、intent、绑定摘要和可知 job ID/状态，不写 token、凭据、提示全文。原工作区只读规则不禁止这类私有运行元数据。
- 回执 IO 额度作为宿主启动配置：单条默认 16 KiB、范围 4 KiB–1 MiB；最多默认 1000 条、范围 1–10000；总量默认 8 MiB、范围 1–128 MiB，单条额度不得超过总量。额度满只拒绝新写入/提交，不驱逐活动或不确定回执，仍允许当前授权核对已有合法记录；不可安全读取的记录明确“无法核对”并保留，不假装不存在后重发。回执不保存完整提交、工作流输入、业务正文或已解析凭据。
- 提交结果不确定时标“提交结果待核对”，先用原 intent 进行受鉴权查询/对账。现有列表不足以准确定位时，在现有 JobService 权限及去重边界内补只读成员 intent 查询；不得仅凭名字或最近时间猜 job。不自动生成新 intent 或重跑。
- MCP 进程重开后可凭私有意图回执定位在线已有任务；过期票据不能再次启动。若查询确认尚无任务但原请求结果仍不确定，只给用户可读处置，不自动重发。
- 在线已接纳的代理任务不依赖 MCP/桌面继续存在；断开默认不取消。明确 `cancel-run` 走现有取消权限/通路；取消一个状态读取请求不等于取消业务任务。
- 本机任务由 MCP 宿主承担生命周期，关闭 source/退出时取消并按现有预算收束，输出已知中止/未知结果，不承诺关进程后继续执行。本地 active run 默认 1、可配 1–4，不能提高服务端策略；不借此重做 F7b 元数据生命周期专项。
- 本地异步状态/结果默认保留最多 20 个已结束运行、总 32 MiB，可配 1–100 个和 1–128 MiB；活动/未明确提交结果的项不可驱逐，容量不足拒绝新执行。新元数据清理不得删除在线业务去重事实。

### 9.3 共用实现责任

将桌面在线执行中与 Electron 无关的部分抽到 `packages/execution/client` 的成员执行编排：成员身份捕获、资产/快照、固定材料/准备、位置和策略检查、提交/状态/取消/报告身份核对。桌面和 CLI/MCP 分别提供会话、秘密存储、声明文件、本机运行生命周期及可读错误适配。

已有 `prepareProjectFiles`、`invokeExecution`、Core Runner 与 Java JobService 保持事实来源。不能让 MCP 自己拼一个弱化 SubmitJob，不能直接调用 runner-agent 的控制 token API，也不把测试执行改成由模型逐节点调度。

只抽当前两宿主确实共用的单请求/套件/工作流路径；不为本期不暴露的 MCP 压测启动重构全部压测编排。已有桌面原路径要有回归，不能以 CLI 新测试通过替代桌面真实入口仍可用。

## 10. 迁移、兼容与故障行为

- 旧桌面单连接配置及 key 迁移成一个个人连接和模型，保留原 Base URL、Chat Completions 选择和用途默认；幂等迁移，不因新增 Responses 改旧调用协议。不扫描或上传用户工作区取 key。
- renderer 的旧非敏感配置与主进程 key 合成须经来源/地址确认，特别是旧 key 未按地址绑定。可解密旧 key 只在用户确认原地址后转存新连接；不可用则提示重配，不自动迁移到不同地址。
- CLI 原环境变量与旧 `~/.apicc/ai.json` 继续作为显式兼容输入。优先级为本次 profile/显式选择，其次完整旧环境三件套，最后旧文件；字段不齐拒绝，不把不同来源的 URL 与 key 拼接。旧明文文件不静默删除或复制到项目，新安全迁移由用户确认。
- 配置格式版本、对象修订和执行定义指纹分开。界面短显示指纹但完整值可查；不得为好看改变 Core 身份模型。
- 供应商连不上、认证失败、协议不兼容、额度不足、取消、拒绝、输出非法、来源变化、在线鉴权过期及结果过期有独立错误码/可读提示。错误不能携完整上游 body 或把 key 放入 cause 日志。
- 所有本地/远端失败保留原事实；AI分析失败不改测试 verdict，MCP 读报告失败不重跑测试，模型输出不合法不创建资产。

### 11.1 建议模块划分

| 工作面 | 责任 | 主要落点 |
| --- | --- | --- |

| AI 业务 | 上下文投影、候选/断言/分析校验、来源绑定 | Core `ai` 与报告/契约只读投影 |

### 11.2 必要验证与证据

1. 三协议同一业务 fixture 获得相同合法候选语义；覆盖必要请求形状/认证头、有限流式事件/文本拼装、正常终态、HTTP200 后错误、EOF 未完成、拒绝/截断、总/单次 deadline、取消与迟到结果。验证重试/修复共享计数和 Token 预留，不隐式叠加 SDK 请求。使用内存 fetch/本机替身，不用真实付费账号做 CI。
2. 配置验证覆盖同厂商多连接/模型、两个能力不同的模型独立上下文/输出及其继承、显式超限拒绝、完整修复提示也计入预算、Token 未确认不装成精确值；同时保留配置新增厂商无需改代码、模板坏输入/更新不漂移实例、发现失败可手工配置、改地址不泄露旧 key、旧配置迁移幂等。未知能力不静默猜测/回退。
3. 用例/断言采用覆盖未选零修改、仅追加、显式保存、过期/切项目/换账号结果拒绝；报告分析引用合法证据、统计事实不变和证据缺失可读。先有效失败行为测试再实现；发现顺序偏差如实记账，不补造历史。
4. 真实 stdio MCP 验证 stdout 纯协议、默认只读、作用域/路径隔离、分页/额度，以及原本地三个工具兼容。新执行使用隔离合成项目/回环目标，不访问用户真实接口。
5. 在线 MCP 以现有真实后端及合成 agent 联验资产、prepare/start、同 intent 防重、权限/脚本批准不足、断线只查已有任务、不依赖桌面及报告读取。复用现有故障夹具，不新增全网络/全协议组合矩阵。
6. 抽共同成员接口后验证原桌面本机/代理用例、套件、工作流入口；不跑高负载或重新验收全部 F7b–F7d。
7. 最终同候选集中查看真实“设置 → AI 与模型”、中英文、长名称、候选具体内容/脚本风险、断言追加、报告事实/推测及证据定位；不能以翻译 key、字段存在或构建替代实际可读页面。
8. 各工作面完成后独审，候选确定后统一安排必要全门禁/打包冒烟；不在每个小修前后无差别重跑全仓。全量失败和补验分开如实记录，不拼成单次全绿；Git 集成及真实高负载另需授权。

## 12. 官方协议依据与状态说明

协议依据在 2026-10-30 核对；具体厂商能力和可用模型由配置及实际测试确认，不固定最新模型名单或价格。

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：消息及结构化结果入口。首版按模型能力选参数，不承诺任意兼容网关全支持。
- [OpenAI Responses 迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)：消息/输出项、结构化格式与状态保存的差异；本项目明确区分适配而非只改 URL。
- [OpenAI Token 口径](https://developers.openai.com/api/docs/guides/token-counting)、[推理预算](https://developers.openai.com/api/docs/guides/reasoning)：输出额度不等于可见正文长度，模型窗口、生成和本机字节保护分别处理。
- [Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create)、[结构化输出](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)：Messages 与其结构化格式作为独立适配，业务结果仍须本地校验。
- [Anthropic 长请求](https://platform.claude.com/docs/en/api/errors)：较长请求的流式及中间网络风险；扩大本机 deadline 不代表供应商或网关保证同等连接期限。
- [MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)：工具结构及人类控制建议；annotations 不是服务端权限校验的替代品。

本文件为阶段规格及实施依据；用户集中确认计划后已进入产品开发及必要隔离验证，实际结果以实施计划和专属证据为准。未启动供应商付费真实调用或真实项目任务。本期不会出现尚未实现的 team/backend 选择项；扩展接口不是这些候选已完成的证明。
