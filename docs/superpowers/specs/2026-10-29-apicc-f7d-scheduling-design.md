# F7d 服务端定时任务与通知设计

日期：2026-10-29。基线：main `8e2c6f259004ae3e129b4d5c1329e3b2f0012e84`，用户确认最新 CI 通过。

F7d 让已保存的在线套件和工作流在客户端退出后，仍由服务端按计划交给指定代理执行。本阶段采用现有数据库上的内嵌调度 A，保留未来独立部署调度服务 B 的可替换边界；B 不实现、不部署，也不提供不可用的选择按钮。用户已确认本设计并批准继续完成 F7d，按[整阶段实施计划](../plans/2026-10-29-apicc-f7d-scheduling.md)推进；实际完成以实施证据为准。

依据：[阶段路线](../plans/2026-10-26-apicc-roadmap.md)、[执行契约](2026-10-26-apicc-f7b-execution-contract.md)、[任务快照要求](2026-09-27-apicc-plugin-api-and-script-security-design.md#13-服务端任务快照)、[页面展示规范](../../ui-presentation-guidelines.md)。受信 Core 脚本沿 F7b 现有边界，不恢复 DEF-001，也不把早期安全专项中的未实现能力写成本阶段既有保证。

## 1 已确认的范围

- 用户已选择 A，并要求未来可通过配置和受控交接切换到独立调度服务，避免重做计划和执行内核。
- 客户端对应在线项目内维护调度、指定代理、环境、业务运行设置及结果；Web 管对应管理员权限、额度和通知渠道。部署级配置控制调度装配与通知出站许可。
- 默认固定执行快照，项目编辑不静默改变既有计划；显式更新快照时展示差异并重新准备。凭据只存引用，每次触发固定实际版本，再沿现有启动许可重核授权。
- 默认错过触发不补跑、重叠运行跳过，不自动重试整份业务任务。通知重试与执行分开，重试通知不重跑测试。
- 首版有站内通知和通用 Webhook，只发送安全摘要与需鉴权的结果定位，不发送请求/响应正文或认证材料。
- 验收覆盖客户端关闭、后端重启、代理离线、重复触发，使用隔离合成项目和可控故障，不修改真实计划。
- 不纳入本机后台调度、单请求调试定时执行、定时压测、邮件/企业 IM 专用适配器、跨代理分布式压测、Quartz/MQ/Redis、独立调度服务或延期项。F7b 三项遗留仍排 F7g 后。

## 2 分层与未来切换

```text
客户端项目配置 → 持久计划与固定快照
                       ↓
内嵌调度驱动 A → 公共触发权威 → 现有 JobService → 指定代理 → execution host/Core
                       ↓                 ↓
              触发记录与去重水位      现有运行历史/报告
                                         ↓
                                 持久通知事件与发件箱
```

新增边界为 `ScheduleDriver`、`ScheduleOccurrenceService`、`ScheduledJobSubmission` 和 `NotificationTransport`。A 的驱动只负责定期唤醒公共权威扫描到期计划，不自己拼执行参数、解析 Core 依赖或发送目标请求。Java 复用当前快照、材料、批准、任务槽、启动许可和任务去重；代理继续使用同一 Core。

部署 `scheduler.mode` 首版仅接受 `embedded / disabled`；`disabled` 停止新触发，保留计划、记录及在途任务，绝不取消业务或删除数据。未知模式（包括尚未交付的 `external`）启动/保存时明确拒绝，不偷偷降级。模式、持久 `generation` 与驱动所有权由数据库控制记录统一约束；每次取得触发权及提交任务都核对当前代次，失效驱动不能继续提交。

多个 A 实例读取同一个控制记录，普通进程重启不擅自递增代次或改写全局模式；只有带期望控制版本的受权装配变更才完成切换。生产调度/租约使用数据库 UTC 时间作为共同权威，驱动不自报判定时间；测试经同一 `ScheduleTimeSource` 接口注入受控时间。数据源须支持本阶段实际使用的事务和行锁；不能把多个独立 H2 文件误当成共享数据库的多实例部署。

H2 实现须读取数据库引擎端实时时钟，不用事务内冻结的 `CURRENT_TIMESTAMP`：通过固定、无参数、非确定性 SQL alias 调用数据库 JVM 的 `System.currentTimeMillis`，在原连接转换为 UTC；不接收客户端时间、不回退应用本机时钟、不另借连接。此为 H2 专用适配，未来支持其他数据库时须替换并验证时间源。调度专用绝对时间列保留 `Instant` 的九位小数精度，不能由默认微秒精度舍入改变 UTC 触发身份。

未来 B 只替换驱动和控制服务间的唤醒/领取适配器，复用计划 Schema、Cron/时区判定、触发身份、策略、快照和提交权威。外置服务不能上传任意目标或自报一个历史时间来绕过准入；鉴权通信和部署方案留 B 的独立需求。切换流程是停止旧驱动领取、处理/封存其未提交领取、递增代次、启用新驱动。已提交任务不撤销、不重建，旧代迟到提交被拒绝。当前只测试驱动替换边界、代次失效和同一权威的并发调用，不实现 B 的网络服务。

## 3 持久对象与状态

| 对象 | 责任及关键身份 | 清理底线 |
| --- | --- | --- |
| 调度计划与修订 | 数字实体 ID、项目作用域、执行主体、乐观版本；规则、时区、代理、快照、准备声明、材料引用及通知选择随修订固定 | 删除为停用和墓碑，不复用 ID；活动记录仍可定位原修订 |
| 触发记录 occurrence | 独立 ID；同一计划同一个 UTC 计划触发时刻有唯一约束；保存修订、原计划时间、实际观察时间、材料版本和策略 | 不因普通历史保留期删除防重身份；修订号不是制造第二次同刻触发的理由 |
| 调度控制与领取 | 模式、代次、领取者、带截止时间的短租约；只保护未提交记录 | 租约过期不是重跑已提交任务的授权 |
| 任务关联 | occurrence 与既有 job/execution 一对一，使用稳定且与人工运行区分的 intentId | 任务提交和关联在同一数据库事务提交或回滚 |
| 通知事件与投递 | 稳定 eventId、安全摘要、来源 occurrence/job；每渠道一份去重投递、次数、下次时间和最终状态 | 删除正文前确认无待发送引用；失去 HTTP 确认仍保留同一事件身份 |

触发状态使用 `pending / waiting-overlap / submitted / skipped / rejected / expired`；租约是控制字段，不伪装成业务执行状态。`submitted` 后的排队、准备、运行、取消、实际释放和报告归档直接投影原 job，不再维护第二套运行状态机。调度跳过、目标测试失败、执行不确定、报告待归档、通知失败分别展示。

公开 ID 与版本沿用 BIGINT 对应 JSON 字符串，Core 业务 ID 仍为 UUID。数据库唯一键、条件更新和事务是最终防重依据；内存锁、单实例定时器或 HTTP 成功都不能单独证明唯一执行。

每个计划持久 `evaluatedThroughUtc`：产生 occurrence、记录跳过窗口及推进已判定水位在同一事务完成。新 occurrence 的时刻必须严格大于水位；已经存在的 pending/waiting-overlap 只能按真实记录 ID 恢复，不能重新插入。修订更新、暂停恢复和时钟回拨不得重置水位。终态且无有效领取、活动任务或待通知引用的旧 occurrence 详情/键可在保留期后有界清理，但水位和计划墓碑持续保留；旧驱动既不能凭日期重建记录，也不能提交已不存在/已终态的记录。通知对 job 终态的观察游标/已发事件版本保留在来源元数据，删除通知正文不造成重新发件。现有 job 去重元数据的生命周期不在此重构，F7b 遗留排期保持不变。

## 4 快照与执行身份

创建/更新计划复用客户端现有执行准备路径，但不发送目标请求：读取已保存在线项目版本，生成不可变快照，调用 `prepareProjectFiles` 获取实际目标闭包和准备声明。只允许 suite/workflow，强制 `dedicated-task`，没有调试会话、Cookie 沿用或压测目标。用户保存的是已发布版本，不从未保存编辑器草稿或开发机路径隐式取内容。

定义、用例、数据、环境定义、运行设置、网络声明、附件 `refId/version/hash`、脚本实际清单、Core/script API 身份及所需能力固定。更新快照显示目标、环境、脚本、数据和材料绑定差异，原修订仍用于旧触发；本阶段不提供“始终最新项目版本”。项目移动、删除、代理解除关联、运行时不兼容或批准失效必须给出可读阻断原因，不自动换代理、环境或降级无认证。

凭据绑定只保存明确的项目 `refId`，支持 `current-at-trigger`（默认）或 `fixed-version`。到期记录入库时，将前者解析成当时实际版本，后者核对指定版本，均只存版本而非秘密值。请求认证与网络认证一起固定；后续排队、代理准备及开始许可沿现有严格版本校验，期间轮换导致冲突就拒绝该次运行，不悄悄改用更新值。值只经既有授权材料通道交付，个人仅本机材料不能用于服务端调度。

执行主体为创建/显式重新授权该修订的有效成员，不保存其登录令牌，也不借平台管理员身份运行。触发、提交和开始前重核账号、工作区成员身份、项目执行权、调度授权、代理关联和脚本批准。主体停用/失权时自动暂停后续触发，并记录原因；有效项目 OWNER/ADMIN 可在客户端显式重新授权、绑定自己并产生新修订，不自动接管。

已有 `JobService.submit` 的身份、材料、准备声明和许可校验不旁路。调度提交在 Spring 事务内调用相同权威，再原子写 jobId 关联及下一触发游标；任何失败整体回滚。需提前排队截止时间时，通过内部受权调用传入绝对上限，与既有项目队列上限取更早值；不开放一个可供普通 Submit 提权的自由字段。

## 5 时间规则与错过触发

首版支持一次性 UTC 时间和 Cron 循环。客户端提供每天/每周常用表单及高级 Cron，服务端为唯一计算权威，返回后五个候选计划时刻用于预览；实际到时仍受授权、重叠、额度和代理状态约束，不承诺等于实际启动时间。时区必须是显式 IANA ZoneId，默认建议为 `Asia/Shanghai`，禁止依赖服务器操作系统默认时区。日期显示到毫秒并标时区，存储与身份使用 UTC Instant。

最小间隔在保存/启用时校验，且每次准入都以持久的上一准入计划时间再次执行间隔门禁；不能只看前五个预览点就认定任意 Cron 频率安全。预算/间隔限制影响的候选时刻在预览和历史中明确说明，不静默改写表达式。显式暂停期间不创建 occurrence；恢复默认从当前时刻及已有水位之后计算下一时刻，不把人为暂停当成需要补跑的故障停机。

Cron 使用现有 Spring 的六字段 `CronExpression`，不引入另一套语法解释器；此为日期计算库，不是持久调度权威。[Spring Cron 官方格式](https://docs.spring.io/spring-framework/reference/6.2/integration/scheduling.html)、[计算接口](https://docs.spring.io/spring-framework/docs/6.2.x/javadoc-api/org/springframework/scheduling/support/CronExpression.html)。夏令时不存在的本地时刻跳过并记录；重复本地时刻支持 `first`（默认）或 `both`，预览注明 UTC 偏移，两个合法 Instant 不是同一次触发。进程重启、时钟回拨不能重放已处理 Instant。

`lateToleranceMs` 区分正常扫描延迟和错过触发。正常容差内创建一次 occurrence；超过容差使用 `misfire=skip`（默认）或显式 `catch-up-one`。后者只在配置回看窗口内补最近一个合法触发时刻，并封存此前缺口，不连续补齐历史。无符合时刻则跳过。规则求值有独立候选预算；预算耗尽暂停该计划并报 `schedule-evaluation-limit`，不无限迭代或把未算完当成已跳过。

长停机不逐条生成无限历史：记录带起止范围的“错过窗口”，将防重水位推进到该范围末端，再计算下一未来触发。未精确枚举时不虚构错过次数。已提交或持久 pending 的 occurrence 先恢复核对，不因扫描器恢复而重新套用“从未触发”的补跑规则。

## 6 重叠与排队

`overlap=skip` 默认：原触发仍待提交、排队、准备、运行或尚未确认实际释放时，下一次记录为重叠跳过。`overlap=queue-one` 可显式选择：只保留一个 waiting-overlap；期间新增时刻记为跳过，不覆盖或不断刷新那份等待记录的期限。本阶段不提供同计划无限并行或替换/强杀前次运行。

waiting-overlap 的凭据版本与定义已固定，只有前次任务实际释放后才能提交。判断沿用 job 的真实释放事实，不能用取消申请、掉线或开始上传代替；报告上传未完成但执行已释放，不额外阻止下一次运行。数据库按计划串行裁定，不在已有 job 回调事务中反向锁调度记录，终态观察经有界扫描完成，避免新增反向锁序。

每次新准入触发的绝对截止固定为原计划 UTC 时刻加 `min(计划保存的 queueTimeoutMs, 当前生效 maxQueueTimeoutMs)`；管理员调低最大值后，旧启用计划的未来触发同样受新上限约束，不保留旧额度豁免。计划保存值/修订不被静默改写，已经准入的 occurrence 截止、原 Job/permit/水位/身份不追溯改变；补跑及 waiting-overlap 也不重置或续期。最终取调度截止和既有适用队列期限的更早值，提交过晚直接过期。等待代理离线或容量不足仍使用同一 occurrence/job，不另建补跑任务；到期后代理恢复不能启动旧任务。已获启动许可的失联任务继续沿现有期限、账本与对账，不退回排队，不自动业务重试。未来手动重跑必须由用户显式提交一个新的运行意图。

## 7 配置与默认建议

本表是本设计集中审阅的新增默认建议，不是已实现或已压测容量。数量为整数，时长为毫秒，字节为 UTF-8 字节；UI 转换为秒/分钟、KiB 等并保留单位。默认值可以继承，额度取适用上限的最小值；低层不能放宽安全规则或上级最大值。保存带 expectedVersion，返回显式值、来源、生效值、策略版本及何时生效。

| 参数 | 默认建议 | 入口与范围 | 生效方式 |
| --- | --- | --- | --- |
| `scheduler.mode` | `embedded` | 部署；只支持 embedded/disabled，未来注册 external 适配器 | 重启/受控交接，新代禁止旧代提交 |
| `scheduler.scanIntervalMs / claimLeaseMs` | 1000 / 30000 | 部署；前者 100–60000，租约 3000–300000 且至少为扫描间隔三倍 | 重启；每次领取固定，不延长过期所有权 |
| `scheduler.batchSize / evaluationMaxCandidates` | 50 / 5000 | 部署；1–1000 / 10–100000 | 新扫描/规则求值；到期索引查询分页 |
| `maxSchedules` | 全局 10000、工作区 1000、项目 100 | 部署/Web 对应管理员；1–100000，下级不高于上级；含暂停但未删除计划 | 新建时；调小不删除原计划，超额不能新建 |
| `minIntervalMs` | 60000 | Web 工作区/项目；1000–86400000，Cron 技术精度为秒 | 新增/更新/启用时重检，不承诺硬实时 |

| `lateToleranceMs` | 10000 | Web 默认、客户端计划；1000–300000，不小于有效扫描间隔两倍 | occurrence 判定固定 |

| `notification.events` | failed、abnormal、expired、paused | 客户端计划可选成功/跳过通知；站内与所选渠道分开开关 | 新事件；默认不为每个重叠跳过轰炸外部渠道 |
| `historyRetentionDays / notificationRetentionDays` | 30 / 30 | Web 工作区/项目；1–3650 | 只清已结束且无活动/待投递引用的详情；防重摘要、水位、job 身份不删 |
| `allowedWebhookOrigins / allowedWebhookCidrs / allowHttpOrigins` | 空集合 | 部署上限；工作区管理员配置渠道不能突破部署许可，平台身份不自动获得工作区管理权；HTTP 必须精确授权 | 每次连接前重核；撤销后不发出新请求，不中断已发送业务任务 |

停用/删除计划停止新触发，并取消未提交的 pending/waiting-overlap；已形成 job 的取消是单独的显式操作，沿用现有取消授权与收束状态。规则/快照/主体/材料绑定更新产生新修订并取消旧修订未提交项；只改名称或通知渠道不改变运行定义，不能在同一 UTC 触发时刻新造身份。配置调小不强杀已开始任务；启用或扩大范围需显式保存和预检。

## 8 权限与管理

新增独立的项目 `manage-schedules` 权限点：有效项目 OWNER/ADMIN 默认拥有，可显式授予本项目具备现行执行权的 EDITOR；不能借此提升 VIEWER 或跨项目权限。创建、更新、启停、删除、更新快照与重新授权均检查此权限，执行主体每次触发还须保有该权限及现行执行权。查询计划/触发历史按项目可见性，读取报告仍走原报告鉴权。

Web 工作区 OWNER/ADMIN 管通知渠道和工作区调度策略，项目 OWNER/ADMIN 管本项目上限及调度授权；平台管理员的基础设施身份不自动获得项目执行权。客户端获得权威 `canManageSchedules`、渠道可选投影及有效额度，不靠前端隐藏按钮代替鉴权。审计包括操作者、计划/修订/触发身份、启停原因、快照变化及渠道变化，不含秘密、令牌或正文。

## 9 通知与出站安全

站内事件是持久通知中心和项目触发历史中的安全摘要，不依赖 WebSocket、桌面在线或第三方渠道。用户读取时重新鉴权，失去项目权限后不再看到该项目内容。事件分别表达测试结论、证据完整性和报告归档状态，不把 report pending 或通知成功当成测试通过。站内已读以当前成员和 eventId 去重，不由某个成员已读替其他成员消除事件。

任务终态观察与通知 outbox 写入按 `sourceId + eventKind + sourceVersion` 去重，轮询恢复不得生成新 eventId。Webhook 投递为有界至少一次：接收方已收到但确认丢失时可能重复，复用 eventId 与正文摘要，接收方可去重；不承诺恰好一次第三方副作用。失败通知不调用任务提交接口。

暂停来源版本只随真实暂停或删除原因形成，不以计划通用编辑版本代替；暂停后仅改名称或通知选择，不重建旧暂停事件，也不补发先前未选择的来源。成员通知历史从实际保留的来源元数据区分未观察、已观察未选及真实事件；站内开关与各 Webhook 实际状态分别投影。已清理且未选的来源不另建永久影子头，不伪造可恢复的历史。

默认只 POST 固定格式的安全摘要：事件 ID、计划/项目可读名称、原计划时间、实际运行时间、job/execution/快照定位、已投影结论、安全原因码和应用内相对链接。正文不含原始错误、请求/响应、认证信息、脚本、数据行、环境值或带令牌的下载链接。名称/文案受字段和总字节上限约束；不能任意上传自定义模板脚本。

渠道完整 URL（可能含路径/query 密钥）与 HMAC secret 均加密保存，GET 只显示脱敏来源、可用状态和版本，不回显秘密。复用既有部署主密钥与 AES-GCM 实现接缝；提取公共 cipher 时保留旧项目凭据 AAD/密文读取语义，新渠道用独立 `notification/v1/workspace/channel/version` AAD 域，禁止跨域替换。没有配置可用密钥时禁止保存/发送 Webhook，站内通知及无秘密的普通计划仍可用。

投递固定 channelId 与渠道版本；改地址或密钥产生新版本，旧版未确认投递停止并明确标 `channel-changed`，不把旧通知静默转发到新地址。停用/删除渠道同样阻止下一次发送，不删除站内事件；改址/新建本身不发送“测试通知”。发件箱满时记终态容量拒绝及站内原因，不创建无界的内存等待队列，也不循环重新生成同一事件。

通知 HTTP 适配器使用新增 `org.apache.httpcomponents.client5:httpclient5` 的 classic 传输，固定 5.6.5 及配套 HttpCore 5.4.4，不直接采用当前 Spring Boot 3.5.5 BOM 中的旧 5.5/5.3.x 组合；新增依赖的版本覆盖和实际 Maven 依赖树须随实现校验。Apache 当前发布的 [5.6.5 GA](https://hc.apache.org/download.html)及[版本说明](https://downloads.apache.org/httpcomponents/httpclient/RELEASE_NOTES-5.6.x.txt)明确对应的底层版本与连接清理修正。不升级 Boot、JDK、Node 或 Core transport，只新增有界通知出站适配。官方接口提供[自定义 DNS 解析](https://hc.apache.org/httpcomponents-client-5.5.x/5.5/httpclient5/apidocs/org/apache/hc/client5/http/DnsResolver.html)及[关闭自动重试/重定向的配置](https://hc.apache.org/components/httpcomponents-client-5.5.x/5.5.2/httpclient5/apidocs/org/apache/hc/client5/http/impl/classic/HttpClientBuilder.html)；这些接口只作为装配依据，具体安全行为须由适配器的真实网络测试证明，不能以库存在当作通过。

- 只允许部署许可内的精确 scheme/host/port 与地址 CIDR；默认没有任何外部出站许可。私网 Webhook 允许管理员显式授权，不以“内网”名字自动放行。
- 本阶段通知渠道和部署 origin 的输入范围为普通 ASCII DNS 名称及 IPv4/IPv6；暂不支持国际化域名及其 Punycode（`xn--`）标签，包括合法 IDN。这是初始支持范围限制，不代表所有 Punycode 无效或不安全，不影响 Core 普通接口请求。来源比较采用共同 canonical origin，完整地址路径/query 不改写；旧不可表示来源显示为不可用而非任意字符串。
- 每次新连接由受控 DnsResolver 返回已校验的地址集合给连接层，覆盖域名和 IP 字面量，校验 IPv4/IPv6；不先校验一遍又让底层重新解析。每渠道独立连接上下文，短生命周期连接，不跨渠道复用授权、Cookie、DNS 或 TLS 状态。
- 禁用重定向、库自动重试、自动认证协商、Cookie、系统代理和自动压缩；保留 TLS 证书/主机名校验，私有 CA 仅经部署配置。拒绝 URL userinfo、fragment、非 HTTP(S) 及未授权 origin；不提供“关闭 TLS 校验”。
- 由应用 outbox 独立裁定重试：网络错误/超时、408、429、5xx 可在次数/总期限内退避；其余非 2xx 终止。每次带相同 eventId，HMAC-SHA256 签名覆盖投递时间戳与固定正文。响应、异常和 URI 不进入普通日志，只存安全分类与 HTTP 状态码；响应按上限读取/丢弃，避免对端回显渠道秘密。
- 发件箱容量满、渠道停用/权限撤销、密钥缺失或投递耗尽均可在站内读到原因；不把外部网络失败改写成测试失败，也不静默丢失这一事实。

## 10 API 与页面

以下均为拟新增路径，前缀 `/api/v1`。网络请求调用的是成员端认证，不开放匿名触发服务；B 的驱动网络接口不在本阶段创建。

| 入口 | 责任 |
| --- | --- |
| `GET/POST /workspaces/{ws}/projects/{project}/schedules` | 分页列表/保存暂停计划，关联既有快照及准备声明；保存本身不执行 |
| `GET .../schedules/options` | 项目成员可读的 canManageSchedules、有效额度/来源、当前调度可用状态及可选渠道 id/name/kind 投影；不暴露工作区管理权限或渠道 URL/秘密 |
| `GET/PUT/DELETE .../schedules/{id}` | 读取、带 expectedVersion 更新、软删除；显式启停、更新快照及重新授权均经版本化更新 |
| `POST .../schedules/preview` | 校验规则、时区和有效额度，返回五次触发及限制；不写计划、不发请求 |
| `GET .../schedules/{id}/history` | 分页触发记录、错过窗口、等待/跳过/拒绝原因及 job 关联；报告沿用原接口 |
| `GET .../schedules/{id}/notification-history` | 同一项目读取权限的 source/event/实际投递安全摘要；站内关闭或详情过期也保留必要状态头，不回渠道秘密 |
| `GET /workspaces/{ws}/notifications`、`POST .../notifications/{id}/read` | 当前成员有权项目的分页通知和幂等已读；不缓存其他成员结果 |
| `GET/PUT /workspaces/{ws}/schedule-policy`、项目对应策略入口 | 对应管理员策略、显式值、有效值/来源和版本 |
| `GET/POST /workspaces/{ws}/notification-channels`、`PUT/DELETE .../{id}` | 工作区管理员渠道配置及脱敏状态；创建/修改不自动发送测试通知 |
| `GET/PUT .../projects/{project}/schedule-grants` | 有效项目管理员管理独立授权，客户端只读能力投影不代替该入口 |

客户端新增项目内“定时任务”页：规则与时区表单、后五次预览、目标/代理/环境、快照版本和短指纹、材料版本策略、启停/更新快照、最近结果与通知状态。显式启用前显示目标及出站风险摘要；没有可用代理、项目只读或运行不兼容时原因直接可读。新计划默认暂停，不存在打开页面就自动启用的行为。

触发历史以表格区分“计划时间、触发延迟、排队、实际运行、执行结论、归档、通知”；长内容局部滚动，导航/搜索常驻。Web 提供管理员策略、渠道脱敏状态和授权表单，不发展第二套业务计划编辑器。固定文案中英双语、单位明确、时间到毫秒并标时区、原始值次级可查，禁止用 JSON/序列化单元格做配置或历史主视图。

## 11 必要验证与验收

| 验收 | 受控操作 | 必须观察的事实 |
| --- | --- | --- |
| AC1 固定定义与材料 | 保存计划后编辑项目、轮换凭据；分别使用显式快照更新和两种凭据策略 | 不自动换定义；每次有真实材料版本，排队期间变化在请求前拒绝，不回退个人材料 |
| AC2 客户端关闭 | 创建/启用合成计划后退出隔离客户端，后端与代理继续运行，随后重开 | 服务端独立触发，重开只查同一 occurrence/job/报告；不要求电脑关机 |
| AC3 后端重启 | 在到期前、job 事务提交前/后、代理开始后分别设置检查点并重启私有后端 | 默认缺口跳过且可查；提交原子性成立，旧 job 不重建，已开始执行对账/补传，不自动重放 |
| AC4 代理离线 | 未开始时断开代理并在排队截止前/后恢复；另测试执行中控制断线 | 有界等待或明确过期，不换代理；执行中保留原执行身份，确认丢失不重跑 |
| AC5 重复与代次 | 并发两个驱动扫描、重复提交、过期租约/旧代迟到、时钟回拨 | 一时刻一 occurrence、一 job、一份业务启动；失效代次不能提交，合法套件的多请求事实仍完整 |
| AC6 时间与重叠 | 可控时间跨过容差/补跑窗、暂停恢复、DST 缺口/重复；长任务跨下一时刻 | 策略与预览一致；默认不补跑/不重叠，queue-one 不无限累积、不续期；预算不足明确暂停 |
| AC7 权限与版本 | 主体停用、成员/调度权/代理/脚本批准撤销、乐观更新冲突 | 触发/开始前拒绝，计划暂停原因可读；平台身份不能借调度越权，旧修订仍可追溯 |
| AC8 通知与安全 | 合成接收端先收到再丢 ACK，返回 429/5xx/跳转/秘密回显，模拟 DNS 地址变化、拒绝地址和坏 CA | eventId/正文身份稳定且有界重试；业务请求不增加；实际连接受约束、秘密不落日志/普通投影 |
| AC9 页面与制品 | 新包与管理台集中检查中英、长名称、时间/指纹、权限禁用、历史与通知 | 不看原始数据即可理解结果，页面无 JSON 主视图/遮挡；产物身份匹配，门禁通过不替代视觉验收 |

日期/并发/事务边界优先使用可注入时钟、真实数据库事务和屏障，不靠 sleep 猜时序；语法脚手架、缺模块、坏夹具不算业务 RED。先在已有合法夹具观察真实失败，再最小实现。不为补历史删除重写，不把后验变异验证冒充实现前 RED。

真实联验合并使用一个私有控制服务、Linux 代理、合成目标与 Webhook 接收端；权限/持锁/去重的最小单测可并行，真实服务联验串行控制负载。保留 CI80/81 的启动事件同步、短生命周期只读账本探针和停机副本完整性检查，不再增加活体账本长读。HTTP 可用于不依赖 TLS 的 UI/合成接收端验证，代理控制和私有 CA 验证仍保持 HTTPS。

执行阶段按受影响最小集合推进；最终候选先 frozen-lockfile 安装、固定工具链、构建/类型/生成契约/品牌门、一次必要全仓测试以及新制品冒烟。记录命令、源码/制品身份、退出码与实际清理；不把分段通过拼成全量通过，不只增超时或删失败测试。是否提交/合并后另跑全量由届时授权决定，不无差别在相同树上重复全量，也不靠多次推送发现已可本地复现的失败。
