## 1. 已确认目标与范围

解决开发网络无法访问集成/预发布测试网络，或开发机到目标网络延迟不适合测试的问题。执行代理部署在目标网络附近，开发机不必直接访问该网络，但代理须能主动通过 HTTPS 访问自托管控制服务。

- 复用现有 TypeScript Core；Java 服务端是控制服务，不复制请求、断言、测试计划或工作流算法。
- 首版范围 A：单接口调试、测试计划/套件、工作流；在线项目同时可选本机执行和已授权代理执行。
- 包含现有Core已支持的受信同步前置/后置脚本；代理主进程不执行任务。仅真正无脚本且内置能力的单请求调试复用一个独立常驻子进程，其余任务按完整调用独占子进程。
- 一个项目可关联多个代理，显式选择执行位置。环境与执行位置是两个独立维度，切换一者不静默改变另一者。
- 代理主动连接，首版 HTTPS 长轮询拉取工作；任务协议与传输适配解耦，为以后长连接保留切换接缝，但本次不实现长连接。
- Web 管理代理基础设施和项目关联，由平台/工作区/项目对应级别管理员操作。接口认证、环境变量和测试参数继续在客户端对应项目配置。
- 在线项目凭据由后端加密保存，授权本机/代理按需使用；个人临时凭据可选仅本机。保留无需主动解锁的体验，不自动迁移既有桌面凭据。
- 适合按部署和使用需求调整的参数必须可配置；文中的数值仅是拟议初始默认值，不得写成产品固定限制。配置分层、修改权限、实际生效值及生效时机见第7.1节。

首版不包括：单代理压测、跨代理分布式压测、定时任务与通知、URL/Git 外部规范同步、分享链接/共享 Mock、AI 增强、插件自动安装或自动升级。前述需求没有取消，分别留后续阶段。DEF-001 继续无限期延期，不以代理建设恢复脚本/WASM 专项。

## 2. 组件与唯一执行内核

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| 客户端 | 编辑在线项目；配置环境/认证/数据；选择环境和执行位置；查看进度、取消和结果 | 管理全局代理资源、给项目越级授权 |
| Web 管理端 | 代理登记、接单状态、节点配置、工作区授权、项目关联及管理审计 | 日常填写被测接口 token、实现第二套测试工作台 |
| Java 控制服务 | 项目权限、凭据存储、快照/附件保存、持久任务队列、调度归属、消息确认、结果与审计 | 在 Java 重写 Core 业务校验、断言、提取或编排执行 |
| Node 代理宿主 | 长轮询、准备任务目录与输入、调用 Core、进程监督、进度上报和结果补传 | 自行解释另一套用例语义、代替后端授予项目权限 |
| 现有 Core | 请求、断言、提取、测试计划、工作流、网络会话及已有报告语义 | 代理注册、队列、长轮询或 WebSocket 连接 |

代理是无界面的后台执行器，不是 HTTP 转发代理或完整 Electron 客户端。Java 复用现有数据库保存队列和状态；首版不引入 Redis、消息中间件或集群调度依赖。控制服务单实例，代理可部署多台。

代理采用两条装配路径，调用同一execution host/Core：真正无脚本单请求调试复用一个按需启动、空闲回收的常驻子进程，可有界并发；带脚本调试、套件、工作流按完整任务独占子进程。一个多节点工作流、其子流程/循环/onError/finally仍只有一个任务进程，不按节点或HTTP请求开进程。主进程只通信、调度与监督。

两条路径共享代理总任务额度N；共享在途/预留I加独占任务/预留K不得大于N，排队不建进程。另计进程资源与退出确认，不能在进程未退出时因Core已返回而提前释放独占资源。当前执行子进程数为K加0或1个常驻worker，回收旧代确认退出后才创建新代。

每次调用独立变量/提取状态、数据行、凭据绑定及markers、证据预算、取消信号和临时材料；Cookie按明确的服务器/工作区/项目/所有者/调试会话管理，既不做全局共享，也不清空同会话有意延续的Cookie。进程复用不复用Core运行可变状态。以上是受信内部机器的工程边界，不是恶意代码安全沙箱；同OS账号子进程并不提供强租户隔离。

调试Cookie会话由代理宿主内存中的有界scope表持有Core既有HttpSession，经限定会话IPC提供给共享/独占调试，不在主进程执行请求或脚本、不复制Cookie算法。worker回收不等于会话结束；会话有独立的可配置空闲期限/数量额度，活跃引用不回收。代理服务重启后不恢复Cookie值，旧句柄先提示失效、不悄悄改为空会话；套件/工作流用任务私有会话，不默认继承人工调试登录态。

## 3. 在线资产与两种执行位置

当前 OnlineApiEditor 只有编辑/保存及拉取到本地的引导；本阶段必须新增在线项目直接执行入口，不能把它当成既有可用能力。

本机路径：客户端读取有权使用的在线项目一致性快照，在本机准备数据与凭据，调用同一 Core，直接从本机向目标接口发请求。它不要求先将在线项目迁移成另一份本地项目，也不替换用户当前已打开的本地工作区会话。

代理路径：客户端选定项目、环境、任务与代理，提交后端任务；代理取得完整快照、附件与授权运行材料后，在代理网络内调用同一 Core。后端不逐个请求发执行许可，不将控制链路往返延迟加入接口执行循环。

| 动作 | 本机执行 | 代理执行 |
| --- | --- | --- |
| 定义来源 | 同一在线项目一致性快照 | 同一在线项目一致性快照 |
| 目标请求发出位置 | 当前客户端电脑 | 指定代理机器 |
| 关闭客户端 | 沿用本地进程任务边界，不转交服务端 | 已提交任务仍由后端与代理负责 |
| 代理不可用 | 不影响本机执行的选择 | 排队/明确不可用，不自动退回本机或换代理 |
| 仅本机凭据/文件 | 当前电脑按现有策略使用 | 准入时提示缺失，不静默上传 |

单接口调试允许显式提交当前请求草稿作为本次运行覆盖，不修改已保存接口。测试计划/工作流执行已保存的在线资产；有未保存修改时提示保存，不假装运行了当前草稿。两种执行位置复用同一项目快照、准备和执行适配边界，不各建一套请求模型。

## 4. 代理资源、项目关联与权限

一个代理可被授权给多个工作区/项目复用；关联不代表复制代理，也不代表项目能改变共用代理的全局配置。全局身份、工作区授权、项目关联分别保存。

| 层级 | 已确认的管理分工 |
| --- | --- |
| 平台 SUPERADMIN | 登记代理、管理节点级配置与接单开关、撤销身份、授予工作区使用范围 |
| 工作区 OWNER / ADMIN | 在已授予本区的代理范围内管理区内项目分配，不跨区授权 |
| 项目有效 OWNER / ADMIN | 从本区已授权集合中维护本项目关联与默认代理，不扩大上级授权 |

新增默认建议：项目有效 OWNER/ADMIN/EDITOR 可提交任务；VIEWER 仅查看有权读取的项目结果，不能通过平台发起目标请求。提交者可取消本人任务，项目有效 OWNER/ADMIN 可取消本项目任务。修改项目凭据按项目写权限；代理管理不自动授予项目资产、凭据或执行权限。平台超管管理代理也不自动获得读取各项目凭据值的特权。

后端在配置、关联、提交、领取和启动准入分别核对真实作用域。提交与开始前检查最新授权；已开始任务固定运行输入，成员/关联撤销不冒称能在断线期间即时终止。需要停止运行应单独申请取消。

远程脚本额外要求节点允许受信Core脚本且项目批准覆盖实际脚本依赖。有效项目OWNER/ADMIN优先授予单脚本/单版本批准，修改失效；也可显式信任整个项目，醒目提示未来修改及脚本可接触授权认证材料的风险。EDITOR的资产编辑/任务执行权不等于批准权，导入/分享不自带信任；撤销阻止新启动，在途仍通过显式取消收束。批准与管理策略在Web对应项目管理，日常测试脚本编辑仍在客户端项目。此为F7b远程任务准入，不接回延期运行时授权/密钥句柄桥接。

接单开关关闭仅停止接收新任务，不等于强杀所有任务。代理身份撤销阻止后续控制通信，但不能证明断线机器已停止向目标发请求。Web 应直接说明作用范围，管理审计不记录认证值。

## 5. 运行快照、文件与凭据

### 一致性快照

后端从有权使用的在线项目捕获一致的文件版本集合，固定项目/环境/用例/套件/工作流/数据集及所需附件清单。快照有独立身份、内容指纹及来源版本，不能只用现有 rootVersion 的求和数值充当快照身份。排队期间编辑项目不改变任务。

服务端工作区/分组/项目实体定位与契约内部项目/资产ID分别保留映射：授权、代理关联和后端凭据范围采用真实服务端实体；Core解析采用对应契约快照。不能将客户端传入的契约projectId直接当作后端授权依据，也不能因两个字段同名就混用。

Core 在本机或代理中从快照构建并校验 ProjectSnapshot，复用现有引用、断言、提取与工作流校验。Java 校验控制协议、权限和资产引用，不复制 Core 业务解析器。无效任务在第一条目标请求前拒绝，并说明对象和具体原因。

### 文件

附件、数据文件及运行所需网络材料通过显式授权的项目附件入口上传并固定版本/摘要；代理获得的是任务专属准备目录和引用映射，不是开发机绝对路径。只在本机存在的文件不能直接派给代理，客户端应提示上传为项目附件或改选本机执行，不能自动读取其他文件替代。未声明、缺失或不支持的材料在启动前拒绝，不默默关掉 TLS/认证或忽略文件。

公开CA/证书可按普通网络材料处理；mTLS私钥、口令等敏感材料沿凭据授权通路交付，由宿主为任务准备，不混入普通可下载附件或快照。建议初始输入额度为快照64MiB、单附件64MiB、单任务所有输入合计512MiB，均可由授权管理员配置，并在准备前检查实际可用空间；超限明确拒绝，不截断输入后继续执行。这是本次新增默认建议，不是容量测试结论；实际生效额度同时受服务端、网关和执行宿主能力约束。

### 凭据

- 配置入口始终是客户端对应项目。在线项目新增凭据默认项目范围，个人临时凭据可显式选仅本机；普通本地项目不改变原存取策略。
- 项目资产和普通快照保留引用，不存认证原值。后端加密存储采用独立存取策略，部署主密钥与数据库备份分离；缺少可用密钥时明确不可用，不回退明文。日常使用无需手动解锁，后端是可接触其托管凭据的受信组件。
- 本机执行可读取其有权使用的项目凭据；代理仅取得分配给本任务、所需引用的运行材料。仅本机凭据不会自动上传、共享或转交代理。
- 凭据版本在准备运行材料时捕获，真正启动前核对版本及授权；排队期间若被修改，重新准备或明确拒绝，不混用版本。启动后绑定固定值，报告记录实际引用版本而非原值；不永久保留所有历史密钥版本来制造“可重放”承诺。
- 认证材料通过专门授权通路交付，不混入通用任务消息、普通快照、进度或报告。代理只在本次执行内持有其所需值；本地持久任务记录不保存明文凭据。进程重启不靠恢复明文凭据自动续跑。
- 两种执行宿主均适配现有 SecretStore / credentialBindings；Core 不根据“本机/代理”另写认证算法。

## 6. 首版能力准入

复用现有 HTTP/WebSocket/SOAP 及 none/bearer/basic/apikey、认证组件引用、声明式断言与提取。OAuth 工具取得并保存的 token 按现有认证引用使用，不新增需要代理打开浏览器的交互式登录。自定义 CA、mTLS 等沿用 Core 已有网络装配能力；所需材料必须可按第5节明确准备，否则拒绝并说明。

新增默认建议：首版代理只装配内置、明确支持的执行能力，不自动安装或下发项目指定插件。依赖未支持插件的任务在准入时显示能力缺失，不能悄悄改用内置实现。在线本机执行保留现有用户主动登记的受信插件机制，但与代理不同的能力须清晰显示，不声称所有插件任务已跨端等价。

代理支持已批准的受信同步测试脚本，不支持不受信任意代码执行。Core显式提供 `no-script` 与 `trusted-core-script` 两种registry：共享调试worker不装JS引擎，独占任务按实际依赖选择。Collection/Suite/CaseExecutionDeps的强制引擎检查改为依赖准入；模块/目录前后置、用例、子流程、onError/finally及v1 JS条件都纳入固定依赖清单。未选中资产不隐式执行，缺批准/缺能力先拒绝，不删脚本后报成功，不靠客户端标记或关键词决定资格。

受信档位复用Core当前同步JS与pm API，不引入npm、任意宿主API、完整第三方平台兼容或异步脚本生命周期。既有前置变量影响当前模板及直接修改pm.request不丢失的语义在共享Core验证/修正，不写代理专属算法。node:vm超时不覆盖完整异步/内存风险；父进程期限与收束监督兜底，不称安全沙箱。脚本可能接触授权请求/响应中的认证值，输出脱敏不能防止主动外发；控制token/主密钥不作为任务材料，互不信任域拆分代理/OS账户或容器部署。

代理报告任务协议版本、Core执行包/脚本API身份、实际Node/V8及能力清单。按受控跨宿主联验形成的兼容档位严格准入；不能只因各包都叫0.1.0或Node版本相近就放行，不匹配先拒绝。保证相同受控输入/响应下语义一致，不承诺不同真实网络、DNS、目标状态、时间/随机数下结果逐字相同。复用旧Core不是恢复DEF-001或安全验收通过。

## 7. 通信及未来切换

业务层定义版本化任务、命令、确认、进度和结果消息；传输层只负责等待和交换这些消息。业务状态不从 HTTP 200、请求超时或连接关闭推导。未来长连接复用同一协议、去重与恢复语义，不改 Core，也不建立第二套任务状态机。

首版长轮询可同时带回新任务及取消/配置等控制命令；没有空闲执行槽时仍保持控制通信，不能因正在执行而收不到取消。快照/附件与最终报告走独立 HTTPS 上传下载通路。

建议首版默认值（本次集中审阅，均为可配置运行参数）：长轮询最长等待30秒，收到任务/命令即返回；心跳10秒，连续30秒无心跳标记连接异常；断线按1–30秒上限退避并加随机抖动。代理/网关等待超时须协调配置。采用上述默认值时，完全空闲每分钟约2次只是领取长轮询请求，不包含心跳和结果上传；修改等待时长后该频率随之变化。

服务器持久保存队列和控制命令，挂起请求只负责通知。请求续接间隙、断线和后端重启不能丢掉任务。未来可按代理会话协商传输方式并允许新旧代理并存；切换不改变任务或执行批次身份，不允许双通道重复领取。

### 7.1 配置分层与生效规则

“适合做成配置项的参数必须可配置”已由用户确认；下列分层和初始默认值是落实该要求的设计草案。首版实施计划须列出参数清单、单位、默认值、合法范围、修改权限、存储位置和生效方式，不能只提供界面输入框而运行时仍使用写死数值。

| 层级 | 配置内容 | 修改入口与边界 |
| --- | --- | --- |
| 部署级 | 后端地址/监听、存储位置、密钥来源、HTTP/网关额度及运行能力上限 | 部署配置、环境变量或专用密钥文件；需重启的项明确标注，不把主密钥值放入普通Web表单 |
| 代理级 | 总任务槽、共享调试在途上限/空闲回收、受信脚本模式、worker启动/监督、长轮询/心跳、重连、输入/待传预算与上传参数 | Web平台管理员维护；部署引导保留本机入口；显示配置版本与应用状态，进程启动参数变更等排空后应用 |
| 工作区/项目级 | 已授权代理及默认选择、任务期限默认值/策略最大值、排队等待期限、项目任务额度和已归档结果保留期 | 代理资源与策略由Web对应级别管理员配置；下级只能在上级授权与资源额度内调整，不改变共用节点全局配置 |
| 项目业务/单次运行级 | 接口/连接超时、测试重试、环境、认证引用、数据、执行位置、本次任务期限 | 客户端对应项目配置或运行入口；复用Core既有语义，单次运行不能扩大管理权限或突破上级额度 |

代理同时执行任务数默认1，但首版必须允许按机器容量配置为大于1；与任务内部的请求/工作流并发分别计量、展示和限额，不以“未来扩展”替代本阶段配置能力。排队等待期限可设为不因等待自动到期或有限时长，任务须直接显示当前策略及到期原因，不把它和开始后的执行期限混为一项。排队总容量和输入/证据/缓存预算同样是可配置资源额度，不默认无限增长。

共享调试的局部上限与全局剩余任务额度取交集，不能把两项相加；空闲回收仅在没有在途调用/清理时进行。脚本每操作时限按任务固定，旧Core默认3000ms保持；worker失联阈值须大于适用最大同步脚本时限并留监督心跳余量。Node堆上限不是总RSS限制，容器CPU/内存硬限制是单独部署项，未配置必须明确提示。字段/初值详见配套配置清单，不把建议值当容量保证。

配置原则：

- **继承与约束：** 页面显示显式值、继承来源、实际生效值及限制原因。普通默认值按层级继承；资源最大值取适用约束的交集，不用低层覆盖绕过上级上限。
- **单位与校验：** 时间统一有明确单位，容量明确MiB等单位；检查类型、范围及参数关联，例如心跳间隔小于失联判定时间、退避最小值不大于最大值、长轮询等待短于HTTP/网关超时并留余量、单文件额度不大于任务合计额度、磁盘预留不挤占承诺的待传预算。无效组合拒绝保存或应用，不静默改值。
- **版本与任务固定：** 提交记录策略版本，启动前核对最新授权与资源准入，实际执行参数在启动时固定并写入运行记录。降低额度可以阻止尚未开始任务，必须说明原因；不偷偷改变已开始任务的期限或执行参数。
- **动态生效：** 通信参数在原子校验、确认配置版本后于后续心跳/长轮询使用，不重建业务任务；并发数降低仅暂停新任务入槽，已有任务自然收束，不强杀。不能立即生效的参数显示待应用或需要重启。
- **清理与重试：** 保留期只作用于已归档结果；缩短保留期须提示清理影响，不删除未确认上传的结果。通信/上传重试是运行参数，不能用它悄悄重试目标业务请求或自动重跑任务。
- **不可变边界：** 正确鉴权、任务身份/幂等语义、事实完整性、凭据不进入普通日志和DEF-001延期边界不是可关闭的调参项；配置也不能启用尚未实现的传输方式或执行能力。真实宿主硬限制应明确说明，与管理员可调整的产品额度区分。

第9节的任务默认30分钟、策略最大值24小时、取消收束宽限5秒、待传区256MiB和第10节结果保留30天都属于初始可配置值。其他资源预算及排队/上传参数的具体初值随整阶段实施计划冻结，不把缺少证据的数字当作已验证容量。

## 8. 调度与生命周期

新增默认建议：每台代理总任务数默认1，可按容量配置大于1；共享调试与独占任务共同竞争总槽，其他任务在后端排队。准备预留也计额度，任务运行状态独立，工作流内部仍按Core既有并行策略。并发槽可配置不等于本阶段增加自动扩缩容、公平调度平台或跨代理拆分。

队列项固定目标代理。代理失联或繁忙时显示具体原因，不自动改选其他代理。本阶段不做任务失败自动重新执行；用户明确重跑会产生新的执行批次，并提示前次可能已有业务副作用。

| 阶段 | 含义及进入条件 |
| --- | --- |
| 已排队 | 后端已持久保存任务、目标及快照引用 |
| 准备中 | 指定代理记录接单身份，下载校验完整材料并完成 Core 准入 |
| 执行中 | 后端记录启动许可，代理记录执行意图，再开始调用 Core；未获启动许可不能因断线自行发请求 |
| 已结束 | 后端收到完成摘要与执行收束确认；共享调用已清理或独占进程已退出。报告上传与完整归档另记状态，未上传不阻止安全释放执行槽；未确认收束仍保留finalizing/待确认与资源占用 |

执行结论至少区分通过、失败、取消、超时、执行中断和准入拒绝。连接正常/失联、结果待上传/已归档分别展示，不压成一个真假状态。只有代理已结束但后端尚未收到完成摘要时，后端仍只能显示最后已知阶段及“当前状态待确认”，不能编造任务已结束；摘要已确认而报告待传时则明确显示该区别，不能把已有报告标成完整。

同一提交意图使用稳定去重身份；同一任务固定执行批次、代理及快照。接单、启动、控制和结果消息均可重发对账，但不得再进入一次业务执行。相同身份携带不同内容应拒绝，不按“看起来相同的URL/参数”合并两个合法新任务。

## 9. 断线、重启与取消

- **控制链路断开：** 未完整接单/未获启动许可则等待恢复；已开始执行且材料齐全可继续到本地截止时间。进度有界缓存、结果补传，不反复访问后端才能完成下一条接口请求。
- **目标链路波动：** 按原测试超时、重试和错误分类处理。控制消息重发不会自动重试目标请求；不能承诺目标业务接口恰好执行一次。
- **后端重启：** 代理继续已开始任务，重连后按持久任务与执行身份对账；不能把旧代理失联当作任务未开始而交给另一代理重跑。
- **代理/执行进程崩溃：** 首版不做 Core 内存快照或断点恢复。保留可取得的部分证据并显示中断/状态待确认，不自动从头发送请求；运行意图和结果确认记录用于对账，不用旧PID猜测任务身份。任务子进程须随代理服务的进程组退出策略一并交付，防止重启遗留无人管理的继续执行进程；无法确认旧执行已停止时不得自动再启动同一任务。
- **取消：** 排队未开始可由后端确认取消；运行中先显示取消已申请，代理确认并收束后才显示已取消。控制链路断开不能承诺即时取消，也不把网络超时当作取消成功。
- **共享调试故障：** 普通取消只Abort单次调用，不销毁其他调用的会话/连接；共享worker崩溃、卡死或调用无法收束时只能终止整代，所有在途调用各自保留部分事实并标中断/超时或状态待确认，不自动重发。确认旧代退出后才重建供新任务使用，IPC核对generation/executionId/scope，迟到消息不串。独占任务不随共享worker故障一并终止。
- **本地期限：** 建议任务默认30分钟、策略最大值初始24小时且可配置；不是24小时长稳验收承诺。期限独立于控制连接，先Core取消，宽限默认5秒且可配置；独占任务仍不退出则终止其进程，共享调用无法收束则按整代故障处理，不能假称仅终止一个请求。收束/退出未确认不释放对应资源，证据限制如实记录。
- **缓存容量：** 建议代理结果待传区初始256MiB，可按部署配置预算；复用现有有界证据/报告投影，快照和附件另计可配置预算。容量不足停止接新任务，给正在运行任务预留最小故障记录空间，不静默丢结果或无限撑盘。只自动回收已确认上传的缓存，未确认结果不因普通保留期到期直接删除。

消息去重和先写意图只能限制平台自动重复启动，不能证明崩溃边界上某条目标请求有没有产生副作用。首版选择保守显示中断、由用户决定是否重跑，而非伪造精确恢复。

## 10. 报告、审计与页面

Core 在执行侧应用既有证据投影与输出边界，再将可保存结果写入待传区和上传；不先缓存原始密钥再期待后端脱敏。未采集、被截断和传输不完整的证据明确标识，不伪造完整报告。

报告记录来源项目/快照、环境、执行位置、代理身份、Core构建身份、实际凭据引用版本及运行结论；不记录认证原值。本机/代理的目标接口耗时在各执行机本地测量，排队、准备、控制通信和上传耗时另列，不用跨机器共享时钟或控制链路耗时解释接口性能。

本机结果保留现有本地生命周期；代理结果由后端持久归档，客户端重开后仍可查询。建议服务端已归档结果默认保留30天，由管理员配置策略，删除与未完成上传分别处理。查看结果按项目读权限；后端/代理保存有界管理审计，不保存认证值。

客户端默认显示环境与执行位置、代理在线/繁忙/不可用原因；运行中显示最后更新时间、连接状态、阶段和取消确认状态。Web 默认显示代理版本/能力、授权范围、接单开关、最近心跳和任务概况；配置变更不静默改变在途任务。

严格遵循 `docs/ui-presentation-guidelines.md`：中文/English、单位、时区及数值精度清晰；关键失败原因直接可读；长表局部滚动。主视图使用摘要/表格/轨迹，原始数据默认折叠，不再以JSON堆叠代替交付。
