### 共用视觉和交互规格

- 保留实际应用图标、顶栏、现有界面字体和模块顺序。主页保留双面板细边框、原有卡片比例和外侧留白。环境页同样以圆角细边框区分左栏与右侧配置区。测试页的接口列表与用例列表用轻分隔线和选中底色体现层次，编辑区用统一间距、横向分隔线和表头组织内容。
- 浅色主题的起始值为功能栏 `#F2F3F5`、测试和环境导航 `#FAFAFB`、选中底色 `#EDF3FF`。通过项目现有主题变量接入，优先调整这两页的作用域，实际组件核对浅色、暗色与自动切换。主页沿用第三版已认可的面板风格。中性配色用一致的选中文字、焦点和分隔线保持层次，禁用、未保存、失败均有文字或可读名称。
- 主工具条中的创建、运行、保存入口在窄窗可换行并保持可操作。测试页随空间不足将用例选择放到编辑区上方，继续保留接口目录与搜索可达。环境页可将导航置于配置区上方，表格必要时局部横向滚动。主页保留竖版卡片，窄窗网格可减为单列。宽窗不得因局部溢出出现整窗横向滚动。
- 复用现有 `ActionMenu` 与确认组件。标题、内容文字和右侧操作各自对齐，行尾预留固定宽度。菜单支持键盘开启、Esc 关闭和回焦。悬停和焦点显隐时，行高、卡片高度、名称宽度均不跳动。名称超出时可通过悬停或键盘焦点读取全名。中英文固定文案随界面语言切换，业务名称原样展示。

## 2. 第一批　主页、分组与连接入口

**修改落点**　`HomeView.vue`、`ProjectCard.vue`、主页中英文文案。需要判断「已打开」时从 `App.vue` 接入现有项目签状态，以本地根目录和完整项目定位匹配，复用现有打开项目动作。

1. 左栏由「本地工作区」「分组」「服务器」组织。三处标题同线对齐，「全部项目」、分组行和服务器状态同列内缩，均用纯文字。「全部项目」和选中分组互斥高亮。工作区标题行 `⋯` 提供「打开本地工作区」「新建本地目录」，空工作区直接露出这两个动作。分组标题右侧 `＋` 新建分组，分组行 `⋯` 收纳重命名和删除。现有非空分组删除限制、只读约束和确认文案保留。服务器空态为「尚未添加服务器」，「管理连接」保留在底部。有服务器时保留列表、账户、登录、在线工作区浏览及回到项目签的既有入口。
2. 保留竖版卡片、圆角细边框和原有彩色首字头像。名称预留两行高度，所属分组位于下方，同排短名卡片的分组信息与长名卡片对齐。卡片菜单右上预留固定空间，保留本地重命名、克隆、移动、删除。已打开的项目可用低权重的文字提示，点击时切回匹配的已有项目签。在线及只读卡片仍按原权限提供浏览、打开和可用操作。
3. 普通浏览右侧标题为「全部项目」或当前分组名。输入非空搜索词后仍按项目名匹配本地整个工作区，显示「搜索结果」及实际命中数量，结果卡片带所属分组。同名结果按完整定位打开。搜索清空回到原分组并将焦点留在搜索框，无结果提供同一清空入口。「新建项目」「导入项目」保留右上位置。新建沿用当前分组或默认分组，项目导入继续使用现有向导默认值与显式分组选择，流程中展示实际目标，搜索命中项不改变目标。

**验证入口**　`ProjectCard.test.ts`、`ConnectionPanel.test.ts`、`ImportWizard.test.ts` 的项目导入场景、`components.test.ts` 的 `HomeView` 组，另选 `App.test.ts` 的跨分组同名搜索、主页往返保留草稿、管理连接与在线成签场景。复用已覆盖的创建、打开和认证行为，补齐迁移菜单的目标、清空回原组和键盘回焦。实窗看全部项目、跨组重名搜索、无工作区和有远程连接四种状态。通过条件为操作与目标明确，长名和行尾操作可读，项目签、权限和连接行为正确。

## 3. 第二批　环境导航、表格与保存反馈

**修改落点**　`EnvPanel.vue`、环境中英文文案与页面样式。复用 `envs.ts` 及现有环境管理入口，按需在现有保存链路增加返回结果和准确的状态反馈。

1. 左栏保留全局变量、全局参数和环境三种编辑目标，标题与行分别对齐。环境标题 `＋` 展开新建和派生，空环境清单时仍可新建，派生显示需要已有父环境。具体环境行尾放删除，确认框显示该行完整环境名。打开菜单或取消删除不会切换当前编辑对象。以触发行的完整环境定位与当时根目录执行，在确认后再次核对。删除当前对象回到适用的默认页，删除其他环境保留当前页和其草稿。
2. 右侧固定标题、当前配置归属和保存状态。全局变量空态提供「添加变量」，点击后聚焦新增行的名称输入。全局参数继续区分查询参数和请求头，保留每行启用状态、顺序与存储语义。具体环境显示两张表，第一张按模块编辑基础 URL，第二张编辑环境变量。两张表使用一致表头、行高和细分隔线，变量名和值仍可编辑，行尾操作定宽。
3. 各编辑目标分别比较草稿与已确认的保存基线。比较使用现有写入规范化规则，忽略纯展示行 ID，保留有效值、启用状态和有意义的行序。未保存状态由真实差异驱动，改回非空基线值或原本缺省的状态可以清除相应差异。切换同项目的编辑目标再返回时保留各自草稿。保存成功后基线取本次确认的内容，后续编辑和其他面板草稿仍可见，失败保留草稿。保存中阻止同一目标重复提交，切换项目或环境后，回执只更新原作用域。
4. 当前环境的「保存环境」通过先写变量、再写基础 URL 完成。只有两步都成功才显示整体保存成功。若只成功一步，按已确认结果更新对应基线，指出仍待保存的部分并保留该草稿，重试需要能收敛。沿用根目录、项目和环境身份保护，验证组件联动后，测试页和接口调试仍能读取新建或派生的环境。

**验证入口**　`EnvPanel.test.ts`、`stores/envs.test.ts`、`App.test.ts` 的环境联动和项目切签。定向覆盖空态新增回焦、菜单目标、派生、只读、恢复基线、部分成功后的失败和重试、保存中继续编辑、切项目后的迟到回执及切换环境。实窗核对空全局变量、全局参数、预发布环境有配置和窄窗。通过条件为编辑归属、待保存状态和所见结果始终一致，失败不会展示为保存成功。

## 4. 第三批　测试导航、用例编辑与运行结果

**修改落点**　`TestSidebar.vue`、`TestView.vue`、`CasePanel.vue`、测试中英文文案，必要时在 `App.vue` 或现有调试 store 复用环境选择、保存判断和运行归属。`CasePanel` 也由 `OnlineProjectAssets.vue` 消费，桌面测试工作台的运行环境、布局或回调按实际调用方接入。

1. 侧栏保留单接口用例、场景用例、测试套件、数据集四个模式，搜索条常驻，清空回焦，结果列表独立滚动。接口按当前项目和原有模块归属展示。对同名模块、接口和嵌套目录继续使用完整定位。保留场景进入设计器、场景压测、套件及数据集的创建与现有操作。
2. 大标题显示当前接口，上方保留模块和必要路径。用例列表分离选择和操作，名称、用例范围和断言数可读。`base` 展示为「基础用例」，底层值继续使用 `base`；其他真实环境名原样。用例新增、重命名、范围编辑和删除仍可达，继续按用例 ID 与范围辨识。清晰区分「本用例请求」的继承与覆盖，保留应用当前调试草稿、恢复继承、数据集和外部 CSV／JSON、断言、AI 依据及建议、提取和脚本操作。前置和后置操作用带数量的折叠行展示，折叠时仍保留草稿、顺序及已有校验能力。
3. 顶部固定所选用例的运行、压测、保存入口。已有卡片快捷操作如需迁移仍须可达，按触发的用例身份执行。运行按钮的禁用状态复用当前用例相对于持久化快照的校验，旁边显示「保存后可运行」等具体原因。运行继续使用已保存用例，原有有效只读运行能力保持。草稿改变或校验失败时保留错误反馈，保存失败不发起请求。其他用例或默认请求的编辑不得误判为当前用例未保存。
4. 用例范围与实际运行环境分别显示。运行环境复用当前正式请求签的选中值，旧入口沿用项目调试环境回退，和 `debug.runCase` 实际提交的环境一致。主工具条选择器显示「运行环境」。压测仍从现有工作台入口选择目标和环境，由工作台显示其自身的生效环境。验证时刻意让请求签与项目压测默认环境不同，分别核对运行入参和压测预选来源。
5. 有当前用例结果时提供「查看结果」，定位到现有响应查看器并为键盘用户定位焦点。结果和运行中状态使用已有运行事实，按根目录、完整接口定位、用例 ID 与范围以及当前运行身份识别归属。切换用例、项目或收到迟到结果时保留可查结果，同时保持当前编辑视图归属正确。失败消息直接可读，保留响应、断言、证据及已有回退入口。

**验证入口**　`TestSidebar.test.ts`、`CasePanel.test.ts`、`AiAssertionSuggestions.test.ts`、`stores/cases.test.ts` 与 `stores/debug.test.ts` 的对应行为，`App.test.ts` 的单接口运行结果、证据定位、压测预选、场景工作台和切换回归。核查 `onlineWorkspace.test.ts` 及实际挂载 `OnlineProjectAssets` 的相关场景，覆盖在线用例保存、继承或恢复、读写权限及原执行入口。实窗集中确认同接口多用例、不同环境、运行中、成功或失败结果和窄窗。通过条件为运行和保存始终绑定实际用例，显示与真实出站目标一致，切换后不会串用例或丢失功能。

## 5. 审核、验证与交付

- 沿用已确认的开发方式，开发由一个 Sol xhigh 子代理负责，另一个 Sol xhigh 子代理独立审核。每批围绕一个页面完成可交付路径，使用现有测试先确认基线。仅对新入口及已有覆盖缺口补必要用例。每批冻结差异后集中自验、独审与归档，并在合批后按三页验收条件做整体验收。
- 视觉验收使用真实渲染页面或隔离应用。按中文常规窗、英文窄窗、浅色与暗色安排代表性场景。记录实际窗口尺寸、用例名称与验证所用的源码或构建版本。主页观察左栏对齐、竖卡和同名结果，环境页观察空态及可扫读的两张表，测试页观察三列优先级、保存限制、结果定位及布局回退。真实操作验证键盘、焦点和完整名称是否可达。
- 构建候选执行 `pnpm -C apps/desktop typecheck`、`pnpm -C apps/desktop typecheck:vue` 与受影响测试，最终候选执行桌面构建和目录包启动冒烟。共享组件沿消费者逐项核对，主要路径包括 `ProjectCard` 的本地／在线主页、`CasePanel` 的本地工作台／在线项目，以及 `ModuleRail` 的接口／工作流／测试／环境。若改到共享主题或其他共享代码，追加其实际消费者的定向回归。核查 CI 各任务的受影响入口，区分本地实际结果、基线 CI 和下一次远端 CI。
- 最终交付一份 Windows 验证包与使用同一合成工作区的简短验收说明。样板沿用 `docs/design/f8-frontend/evidence/desktop-pages-ci107/`。验证原始日志、候选和哈希计划归入 `local/f8-desktop-pages/`，可共享的逐项证据和回执回填工作记录。全量或完整本地门禁仅在本次明确确认后执行。合并与推送按当次授权执行。
