## 1. 现状和目标

正式在线项目的接口、工作流和用例保存共用项目资产版本。客户端可提交文件增量，服务端仍按整个项目的预期版本做原子校验。现有并发回归覆盖了不同文件因基于同一旧版本而一笔成功、一笔冲突的行为。[客户端保存](../apps/desktop/src/main/online/execution.ts) · [服务端校验](../server/src/main/java/com/autumnharvestc/server/execution/assets/ProjectAssetsService.java) · [并发用例](../server/src/test/java/com/autumnharvestc/server/execution/ProjectAssetsApiTest.java)

项目版本变化自动触发必要比对。可安全合并的保存一次点击即可完成。需要用户处理时，保留草稿并明确受影响资产。来源变更对当前页面可见时先提示，由用户决定什么时候应用。原子提交和执行快照继续按项目资产版本校验，服务端检查当前权限。正式在线项目协作、工作区迁移以及 URL/Git 外部规范同步保留各自入口。

## 2. 保存的合并规则

首版覆盖正式在线接口编辑、新建工作流、用例新增与编辑。保存携带实际改动、编辑时的相关基线和完整目标身份。接口、工作流按稳定 ID 定位，用例按所属接口、用例 ID 和环境范围定位。新建资产在首次提交前固定 ID，在此次操作的有限重试和回执核对中复用。

| 编辑基线、我的提交和服务器现值的关系 | 处理方式 |
| --- | --- |
| 服务器只改了无关资产，目标与依赖仍符合编辑前提 | 在服务器最新资产上应用本次操作，再提交增量。 |
| 双方已把同一项改成同一值 | 确认服务器已有结果，返回保存成功。 |
| 同一接口下不同用例或仅改接口描述并新增用例 | 允许已明确支持且前提仍成立的组合。共用的用例索引从合并后的业务对象生成。 |
| 双方修改同一项为不同值，或目标、引用和继承前提已改变 | 保留原草稿。说明具体冲突，展示受影响项的编辑时版本、我的修改和服务器版本。 |
| 服务器已删除目标 | 保留原标签和草稿，标明「服务器已删除」。普通保存拒绝写回原目标。若需要另存为新资产，由用户显式选择适用的创建入口。 |

首版采用已验证的业务单元和操作规则。例如变更接口请求参数时，要核对用例是否依赖原默认请求。仅凭两笔提交落在不同文件不足以判断兼容。权限、依赖或目标身份无法确认时保留草稿。展示使用业务字段与归属，保留原有业务正文查看方式。

在桌面主进程基于服务器最新快照重放明确的操作，使用已有项目资产 API 提交最小增量。服务端继续检查当前授权、资产约束和项目版本。实际以入锁后的版本判断为准。明确的版本竞争可重新读取、重新校验并有限重试。连续竞争耗尽预算时提示「项目正在更新，草稿已保留」。网络中断且结果未知时按原操作核对状态，确认已生效后收束；无法确认时保留原操作身份和草稿。保存只捕获点击时的内容，回执更新对应项目和资产，保存期间较新的输入仍标为未保存。

## 3. 同步时机与界面行为

| 时机 | 行为 |
| --- | --- |
| 首次打开项目或尚无草稿的资产 | 读取最新版本，再展示本次打开内容。 |
| 切回项目、窗口回前台或重连 | 合并短时间内的重复请求，检查当前项目。先只检查更新，已显示的目录、标签和编辑区继续保持。 |
| 点击保存 | 读取或核对最新项目版本，按第 2 节提交用户改动。正常显示「已保存」，其他成员的可见改动继续通过更新提示呈现。 |
| 点「查看」 | 显示与当前页面相比的新增、修改、删除及可读归属。只知道版本变化时展示「服务器有更新」，核实可见差异后才显示数量。 |
| 点「应用更新」 | 应用用户查看的版本。保留可用标签、选中项、展开和滚动位置。新到的更新继续提示；相同内容和已撤回的可见差异消除提示。受影响草稿仍可查看并处理。 |

后台已读版本、界面已应用版本和每个草稿的编辑基线分别跟踪。已有页签上的其他成员可见改动先提示，再由用户应用；自己的保存结果按对应目标更新。页面明确当前存在待应用变更，选择新资产时按最新可用内容读取。不同服务器、账号、项目和请求代次分开接收结果。权限失效继续按现行在线授权关闭相关访问。本期首要覆盖打开、保存和显式应用，对回前台等时机只做合并后的当前项目检查；评估轻量版本查询后再决定其接线，避免重复拉取大项目正文。

在线运行继续以用户确认的已保存版本申请固定快照。若该版本已无法建立快照，提示先查看更新。已开始运行与已保存的定时计划按原有快照规则运行。实时协同、强制自动覆盖和新存储模型留作后续评估。

## 4. 首版验收

- 四个独立客户端从 O 开始，按甲改 A、乙新建工作流、丙新增用例、最后保存 B 的顺序各点一次保存。服务器保留四份改动。最后一位用户先看到自己的保存结果与待应用提示，目录直到主动应用才更新。
- 确定性覆盖同接口下不同用例、双方修改同一参数、服务端删除正在编辑的接口，以及接口请求与用例继承前提相互影响。分别核对安全合并、同值收束和保留草稿。
- 覆盖两次保存争用、结果未知后的核对、保存中继续输入、切换项目后的迟到回执，以及查看更新期间又到新版本。真实执行固定已经确认的版本。
- 以真实在线服务和不同客户端会话验证原子保存与草稿归属。用实际客户端核对中英文提示、窄窗及目录应用前后位置。沿用定向验证与独审，本地全量仍按次确认。
