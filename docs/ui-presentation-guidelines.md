# 页面展示规范：面向用户可读，原始数据次级可查

生效日期：2026-10-23。来源：用户在 F5、F6 连续两次遇到页面以 JSON 堆叠代替可读展示，明确要求记录并在后续页面设计中规避。

适用于客户端、管理页面、运行/测试/压测报告、离线 HTML，以及新增或修改的其他面向用户页面。内部 JSON 存储、契约格式和机器可消费的 JSON 导出不受此约定禁止。

## 1. 默认展示

- 配置、状态、统计、比较、节点、生命周期和运行轨迹，应按业务含义使用摘要、字段表、列表、可展开详情或时间线。不能把 `JSON.stringify`、对象调试输出、整段 `<pre>` 或 JSON 单元格作为主要页面的交付形式。
- 用户不应必须理解内部字段名、遍历嵌套对象，才能知道运行是否成功、哪里失败、为何不可比较或哪项数据未采集。关键结论、原因和限制必须直接可读。
- “原始数据/高级详情”作为次级入口，默认折叠；保留既有输出策略允许的原数据，不靠删证据或隐藏失败换取整洁。把 JSON 从一个大块拆进多个表格单元格，不算可读性改进。

## 2. 明确允许的 JSON 场景

API 请求/响应业务正文、契约与 Schema 编辑器、专用原始报文查看器，以及显式 JSON 导出，可以采用源码或树形展示。这些内容本身就是用户要检查或编辑的对象，不要求强行转成业务表格。

业务原文、ID 和用户自定义键值不自动翻译或改写；长正文沿用现有有界预览、截断提示和输出规则。例外不能反过来覆盖报告元数据、配置、统计等主视图。

## 3. 可读性要求

- 固定标签、状态和提示按界面语言显示；独立离线报告默认中文并保留已约定的英文切换，不以内部枚举或翻译 key 代替文案。未知码如实保留，不编造解释。
- 时长、速率、百分比标明单位，数值精度适合阅读，不改变计算原值；真实零、未采集、不适用、不可计算分别说明。
- 开始/结束时间可读到毫秒并明确时区，原时间戳可查；长定义指纹短显、完整值可展开，内部比较仍用完整值。不能因展示难读擅自改身份或版本模型。
- 不同统计总体分开命名，不能把逻辑成功当作原请求没有失败。结论、原始事实和完整性限制同时保留。
- 长表/正文在自身区域滚动；不逐字挤断表头、撑坏顶栏或让导航和搜索失去可用性。
- 图表只画真实观测，缺失区间不伪造连续趋势；0/1 个数据点须说明限制，不为美观补点。

## 4. 设计、审核与验收检查

在阶段开始确定的需求/验收中说明各类数据的默认展示和原始数据入口，而不是到手验时再临时决定。实现者自审与独立审核均检查：

1. 不展开原始数据，能否读出主要结论、关键配置、失败原因和数据限制？
2. 元数据是否有业务标签、状态解释、单位及本地化，而非仍在大块或单元格里堆 JSON？
3. 长名称/数字/正文是否可查且不破坏布局？原始业务内容、统计原值和不同总体是否保持？
4. 已运行的验证是否覆盖真实可见文字/结构和必要交互，而非只证明字段、区块或翻译属性存在？

只复用受影响的最小测试，阶段交付集中手验新增展示；DOM 行为和构建通过不能代替浏览器视觉证据。不为本规范新增全页面快照矩阵、压力运行或每次全量测试。任一主视图仍用 JSON 代替已要求的可读展示，不得仅凭“有数据/可导出/测试绿”判为完成。

## 5. 重复缺陷记录

- 2026-10-22，F5 工作流报告：汇总、节点和调用轨迹仍大量直出 JSON；后续修为可读摘要与表格，用户确认通过。关联：[F5 设计](superpowers/specs/2026-10-21-apicc-f5-workflow-design.md)。
- 2026-10-23，F6 压测报告：配置、统计、节点时延、生命周期等再次直出 JSON，并有英文硬编码、数字/表头挤断问题；经 G-06/G-07 修正和用户手验。关联：[F6 设计](superpowers/specs/2026-10-22-apicc-f6-stress-design.md)。

复发原因：将“序列化数据已呈现”当作“页面可用”，验证未把业务可读性作为交付条件；第一次修正没有提升为跨页面约束。后续统一按本规范设计与审核，而非仅修某一份报告。此归档不表示已对全部旧页面完成扫描或整改。
